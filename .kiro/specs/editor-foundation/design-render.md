# 描画：格子・投影・表示の切り替え・変形中の更新

第1段階の方式（オフスクリーンの画像へ描いて egui に貼る、変化のあったフレームだけ描く、未完了の描画は2回分まで）は変えない。足すものはすべて、**既存の1回の `queue.submit` の中**に入れる。別の送信を足さないので、未完了の描画を数える仕組み（`MAX_FRAMES_IN_FLIGHT = 2`）はそのまま効く。

## 3Dに描くものと、eguiに描くもの
| もの | 描く場所 | 理由 |
|---|---|---|
| 床の格子と軸の線 | 3D（`render::grid`） | 部品との前後関係が要る |
| 線の表示、透かし | 3D（`render::display`） | 形状そのもの |
| 変形中の部品 | 3D（シェーダーで行列を1つ掛ける） | 下の「変形中」 |
| ハンドル、向きの立方体、軸の文字、計測の線と数値、変化量 | egui（3Dの画像の上） | 常に手前に出したい。当たり判定がCPUの計算になり、画面なしで試験できる。触れたときの強調で3Dを描き直さない |

## 毎回の入力（`FrameParams` に足す項目）
```rust
pub enum DisplayMode { Faces, FacesAndLines, Lines, XRay }
pub struct GridParams { pub spacing: f32, pub visible: bool }                    // 間隔は core::camera::grid_spacing が決める
pub struct DragPreview { pub nodes: Range<u32>, pub world_delta: Mat4 }          // 変形中だけ Some
// FrameParams に display: DisplayMode、grid: GridParams、drag: Option<DragPreview> を足す。view_proj は平行投影の行列も受ける
impl SceneRenderer { pub fn supports_lines(&self) -> bool; }                     // 線の表示が使えるか
```

## 床の格子と軸
- 格子は、高さ0の水平面を**画面全体の三角形1枚**で描く。フラグメントシェーダーが、画素ごとの視線と平面の交点を求め、交点の座標から線の濃さを決め、交点の深度を書く。線の太さを画素で決められ、遠くは薄れ、ズームしても頂点を作り直さない。
- 線の束を頂点で作る案（`LineList`）は捨てた。線の太さが物理1画素に固定され、高精細の画面では細すぎる。間隔が変わるたびに頂点を作り直す必要もある。
- 間隔は `10^floor(log10(距離 / 5))` を基本に、1段細かい線を薄く重ねる。同じ値を状態欄に出すので、計算は `core::camera::grid_spacing(distance)` の1か所に置く。
- X軸とZ軸の線は太くして色を付ける（X #E0655F、Z #5B8DEF）。向きの文字は立方体の側に出す。
- 格子は形状の後に同じパスで描く。深度は比べるが書かない。半透明で重ねる。部品の向こうにある格子は隠れる。
- WGSL の `@builtin(frag_depth)` は naga にある（`naga/src/front/wgsl/parse/conv.rs`）。多重サンプルの描画先と組み合わせた実機での動きは**未確認**。作業の最初に小さな試験で確かめ、だめなら `LineList` に切り替える（切り替えの判断は進行役に伝える）。

## 平行投影と仰角90°
- `OrbitCamera` に `projection: Projection { Perspective, Orthographic }` を足す。平行のときの見える高さは `2 × distance × tan(fov_y / 2)`。切り替えても注視点での見かけの大きさが変わらず、保存の項目も増えない。
- 平行の行列は `glam::camera::rh::proj::directx::orthographic`（実物で確認）。反転Zにするために近い面と遠い面の引数を入れ替える。入れ替えで深度の大小が透視と同じ向きになることは**未確認**なので、単体テスト（手前の点の深度が大きい）で確かめる。近い面と遠い面は、目の位置と全体の境界球から決め、目の後ろ側にある形状も切らない。
- 視線（`screen_ray`）は、平行のとき「画面上の位置から、視線の向きへ平行に出る線」になる。選択・注釈・計測・ハンドルは同じ関数を使うので、ここを直せば全部が従う。
- 仰角の制限を±89°から±90°にする。真上と真下が出せないと、上面図が1°傾く。`look_at`（上向きの基準がY）は90°で壊れるので、視点の行列は方位と仰角から直接作る（右・上・奥の3軸が常に決まる）。
- 立方体と数字キーの視点は `OrbitCamera::snap(ViewDir)` で方位と仰角だけを置き換える。補間はしない（第1段階の方針）。

## 表示の切り替え
| 表示 | 描き方 |
|---|---|
| 面 | 第1段階のまま |
| 面と線 | 面を描いた後、同じ形状を `PolygonMode::Line` のパイプラインでもう一度描く。暗い線。深度は「同じか手前」で比べ、深度の偏りを付けて面とのちらつきを防ぐ |
| 線 | 面を描かず、線だけを描く。奥の線も見える |
| 透かし | 面を半透明で描く。深度は書かず、比べない。重なりの順は保証しない（見通すための表示と割り切る） |
- `PolygonMode::Line` は `Features::POLYGON_MODE_LINE` が要る（`wgpu-types/src/features.rs`。ネイティブだけの機能）。Metal・Vulkan・DX12・GL の各バックエンドが対応を申告している（`wgpu-hal` の各 `adapter.rs`）。`main.rs` の `device_descriptor` を包む既存の処理で、アダプタが持っていれば要求する。持っていなければ `supports_lines()` が偽になり、画面は「面と線」「線」を無効にして理由を出す（要件4.2）。
- 線は三角形の辺をすべて描く（四角形の対角線も出る）。太さは物理1画素。「形の稜線だけを太く描く」表示は、辺の抽出が要るので後続とする。
- 深度の偏りの値は定数にまとめ、実機の画像で決める。反転Zと32ビット浮動小数の深度での効き方は**未確認**。
- 選択の輪郭線は、どの表示でも最後に重ねる。

## 変形中：行列を1つ渡すだけ
ドラッグ中に動かす部品のインスタンスを毎フレーム書き直すと、子孫が5万個なら1フレームに約7MBを送ることになる。そうしない。
- フレームの定数に「変形中の範囲（`NodeId` の連続範囲）」「差分の行列 D」「D の法線用の行列」を足す。頂点シェーダーは、インスタンスの `NodeId` が範囲に入っていれば、ワールド行列の前に D を掛ける。選択の強調が同じ範囲の比較をすでに行っているので、仕組みは同じである。
- 輪郭線のマスク（`mask.wgsl`）も同じ定数を見る。輪郭が部品と一緒に動く。
- ドラッグ中に送るのは定数バッファ1つ（数百バイト）で、動かす部品の数に依らない。CPU側の文書も、確定するまで書き換えない。Esc での取り消しは、D を消して描き直すだけで済む。
- 数値の欄をドラッグしている間も、同じ経路で見せる。

## 確定したとき：範囲だけ書き直す
- インスタンスは形状ごとにまとめて並んでいるので、1つの部品のインスタンスはバッファの中に散らばる。作るときに「描画（`Draw`）の番号 → インスタンスの位置」の表を残し、動かした範囲の描画だけを `queue.write_buffer` で上書きする。隣り合う位置はまとめて1回で送る。
- 追加・複製・削除・表示の切り替えでは、これまでどおりインスタンス全体を作り直す。
- `SceneDirty` に `display`（表示・格子・投影の切り替え）と `drag`（D の変化）を足す。部分更新は `Session` が「動かした範囲」を溜め、`gpu_view` が次のフレームで取り出す。

## 足した図形の形状
- `SceneRenderer::add_primitives(device, queue, &[Arc<Primitive>])` が、足した分だけの小さなバッファを作って1回で送る。形状の位置の表（`PrimSlot`）は末尾に足す。既存のページには触らない。モデルを閉じるときに一緒に捨てる。
- 図形1個は数十KBなので、分割転送は要らない。1回の呼び出しが32MiB（第1段階の1フレームの予算）を超えるときは断る。
- 読み込みの転送中は編集を受け付けないので、転送と追加が重なることは無い。

## 何もしない間は描かない
- ハンドルと立方体は egui の描画なので、触れたときの強調では3Dを描き直さない。`SceneDirty` が立つのは、視点・表示・選択・変形・構造・大きさが変わったときだけである。
- 無条件の `request_repaint` は足さない。ドラッグ中の描き直しは、ポインタの入力が来たフレームにだけ起きる。
- 確かめ方は第1段階と同じ（何もしないフレームで `RenderStats::draw_count` が増えない）。格子・表示の切り替え・ハンドルを出した状態で、もう一度確かめる。
