# UX設計（ユーザーストーリーとUX5階層）

実装の前に書いた。第3段階の [ux.md](../cad-inspect/ux.md) は有効で、ここには足す分だけを書く。

## 誰のためか
- **CAD や3Dプリント用の STL を受け取って確かめる人**: 多くは Z を上にして作られている。開いたら立って見えてほしい。回転の数値を調べて打ち込みたくない。
- **Y が上のソフトで作った STL を開く人**: 少数だが居る。寝て見えたら、すぐ直したい。
- **書き出した GLB をほかのソフトで使う人**: この画面で見た向きのまま渡したい。

## ユーザーストーリー
| # | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| S1 | Z が上の STL を、何もせずに立った向きで見たい | 開くと、ファイルの Z が画面の上を向く |
| S2 | 寝て見えたら、1回の操作で直したい | 状態欄の「上 = Z（仮定）」を押すと、Y が上で開き直す |
| S3 | いま何を仮定しているかを、いつでも見たい | STL を開いている間、状態欄に向きの仮定が出ている |
| S4 | 向きを替えるときに、作業を黙って失いたくない | 未保存があれば、開き直す前に確認が出る |
| S5 | 高さを測ったら、立っている向きの高さが出てほしい | 寸法・計測・断面は、画面の軸（Y が上）で出る |
| S6 | 書き出した GLB が、ほかのソフトでも同じ向きであってほしい | 現在の回転が GLB に反映される。Z を上と仮定したときは、結果の一覧に回転の初期値が出る |
| S7 | レビューを開き直したら、保存したときの向きと視点に戻ってほしい | レビューに向きが書かれ、その向きで復元する |

## 1. 戦略
- 目的は「STL を開いたら、たいていは直さずに済む。違ったら1回押せば直る」こと。向きを細かく決める道具にはしない。
- 大事にする順番は、①作業と元のファイルを失わない・壊さない、②仮定を仮定として見せる（ファイルに書かれていないことを、書かれているように見せない）、③画面で見た向きのまま書き出される、④覚えることを増やさない（単位の仮定と同じ流れに乗せる）。
- 状態欄は形式を問わず、長いファイル名と選択名を残りの幅に合わせて省略し、「詳細」を画面内に保つ。幅に収まる名前はそのまま見せる。

## 2. 要件（戦略から導いたもの）
- ①から: 切り替えは、別のモデルを開くときと同じ未保存の確認を通す。STL は読むだけで、座標の値を書き換えた物を作らない。向きを替えても単位の仮定は残し、単位を替えても向きは残す。
- ②から: ボタンに「（仮定）」と書く。回転は「変形」の欄に X = -90 として見せ、隠さない。画面の軸の名前はこのアプリのもの（Y が上）であることを、ボタンの説明と文書に書く。
- ③から: 向きは部品の回転で表し、書き出す GLB にそのまま入れる。結果の一覧に1行足す。
- ④から: キーを足さない。小窓や設定の画面を足さない。向きは2つだけにする。

## 3. 構造
- 状態は「Z が上」「Y が上」の2つ。押すたびに入れ替わる。3つ以上を順に回す形（単位の仮定）と違い、押した先が1つに決まるので、説明に行き先を書ける。
- 置き場所は状態欄の、単位の仮定のボタンの隣。どちらも「ファイルに書かれていない前提」で、どちらも押すと開き直すので、並べて1つのまとまりに見せる。
- 上の向きは STL の文書だけが持つ。書き出して GLB へ移ると、ボタンは消える（回転は部品に残る）。

## 4. 骨格
状態欄の並びの目安（実際の順は今の実装に合わせ、単位の仮定の隣に置く）:
```
… 格子 10 mm  [表示 mm]  [上 = Z（仮定）]  [STL = mm（仮定）]  簡略表示 …  [詳細]
```
- 幅が足りないときに隠す順は今のまま（格子 → 表示 → 部品の数）。2つの仮定のボタンは隠さない（今の状態を常に見せる）。幅960で、未保存の印2つと知らせが同時に出ても重ならないことを試験で確かめる。
- 「変形」: 回転 X に -90、大きさに 0.001（mm のとき）。どちらも誤りではないことを、手順書の「うまくいかないとき」に書く。

## 5. 表層（画面の言葉）
| 場所 | 文 |
|---|---|
| ボタン | 「上 = Z（仮定）」／「上 = Y（仮定）」 |
| 説明（Z のとき） | 「STL には上の向きの決まりが無いため、Z を上と仮定しています。押すと Y を上にして開き直します。画面の X・Y・Z はこのアプリの軸（Y が上）です」 |
| 説明（Y のとき） | 上の文の Z と Y を入れ替え、「ファイルの座標のまま表示しています」を添える |
| 書き出しの結果（Z のとき、今の1行の後ろへ） | 「開いたときは Z を上と仮定し、回転 X の初期値を -90° にしました」 |
| ヘルプの表 | 「STL の上の向きを替える ／ 状態欄の「上 = …」を押す（開き直す）」 |
| ヘルプの制限 | 「STL の単位と上の向きは仮定（既定は mm・Z が上）で、…」 |

## UX を通して変わった実装（4件）
1. **軸の名前の説明を足した。** 戦略②から。Z が上の STL では、ファイルの Z が画面の Y になる。計測の ΔY や断面の Y がファイルの軸と違うことを黙っていると、数値の出どころを偽ることになる。ボタンの説明と `docs/stl.md` に書く（当初の案は、ボタンと回転だけだった）。
2. **向きと単位が互いを消さないことを要件にした。** 戦略①から。今の単位の切り替えは、開き直しの指定に単位だけを渡している。向きを足すだけだと、単位を替えたとたんに向きが既定へ戻る。要件2.3 と試験にした。
3. **書き出しの結果に1行足した。** 開いたときの仮定として回転を説明すれば、その後に利用者が回転を編集しても意味が通る。
4. **手順書の撮影を既定（Z が上）に合わせる。** 戦略②から。検証用の手順は `stl_up: "y"` で今の座標のまま通すが、手順書の絵まで Y にすると、利用者の画面と絵が食い違う。手順書 03 は、測る2点の位置を取り直す。
