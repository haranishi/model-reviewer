# 保存先の照合と読み直し

## 保存先を置き換える条件

- 読み込みが表示に反映された時点で、選んだパス、リンクを解決したパス、バイト数と BLAKE3 を記録する。ドライブ間で複写して元を削除すると、ファイルの識別子は変わる。開いたときの内容との照合なら、この移動も検出できる。
- GLB 書き出しでは、開いたパス、リンク、同じ内容のファイルを保護する。内容の照合は書き出しスレッドで行い、サイズが該当する保存先だけを順に読む。長い書き出しの途中に保存先が変わり得るため、一時ファイルを置き換える直前にも確認する。
- 書き出しに成功した場所と内容に、一時ファイルの識別子と更新時刻を対応づける。識別子は Unix では装置番号と inode、Windows ではボリューム番号とファイル ID。元のモデルが同じ名前の出力と入れ替わっても、両者を区別できる。開いたパスとリンクの禁止を先に適用する。
- レビュー保存では、既存の保存先がレビュー読込と同じ形式・版・値の検査に通ることを条件にする。読み取れないファイル、壊れたレビュー、将来の版は置き換えない。

## 読み込みと復元

- 保存ボタン、保存先の選択、保存コマンドで、表示中のモデルを置き換える読み込みの状態を見る。
- 復元で出力そのものを開き直す場合に限り再出力を許す。別の候補は通常の読み込みと同じく保護する。
- STL の単位や上の向きを替えるときは、未保存の確認を経ても表示中のモデルの識別値を引き継ぐ。読み込みスレッドで照合したバイト列を、新しい単位と向きで解析する。
- 次の読み込みを中止して元の表示に戻るときは、選択用の索引を回復する。索引は表示中の文書に後から足した図形も含む。
- 部品名を照合する例外は、実際に STL として読んだモデルの唯一の部品（番号 0）だけに適用する。

## 限界

保護の記録はアプリを閉じるまで有効。同じ内容の独立したコピーも保護する。移動と同時に内容も書き換えたファイルは、内容だけでは追跡できない。最後の照合と置き換えの間に他のプロセスが保存先を差し替える競合は残る。

ファイルシステムから識別子や更新時刻を取得できない場合は、開いた内容と一致する保存先への再出力を断る。レビュー JSON の検査と、失敗後に必要な索引の再作成は同期処理で、大きなレビューやモデルでは待ち時間が生じる。

## 変更箇所と検証結果

- アプリの実装は `crates/app/src/` の `app.rs`、`exporter.rs`、`exporter/protection.rs`、`session/export.rs`、`session/mod.rs`、`session/open.rs`、`session/persist.rs`、`ui/status.rs`、`ui/toolbar.rs`。
- モデルの識別とレビューの復元は `crates/core/src/identity.rs`、`crates/core/src/review_file.rs`。試験は `crates/app/tests/` の `export.rs`、`open.rs`、`persist.rs`、`stl.rs`。
- 利用者向けの説明は `README.md`、`README.ja.md`、`docs/review-json.md`、`docs/stl.md`。仕様はこの文書と [requirements.md](requirements.md)。

元ファイル保護を最初に追加したときの11件は、修正前にすべて失敗した。その修正後、macOS（arm64）で書式検査、警告をエラーにする静的検査、ワークスペース全体の試験、リリースビルドが成功。試験は673件成功、失敗0件、実行対象外54件。依存のロックファイルは当時の修正では変わらなかった。上の向きにも保護を適用した版の結果は [統合時の検証](../stl-up-axis/tasks.md#元ファイル保護との統合時の検証) に記録した。

実ドライブ間の移動は、同一ドライブ内での複写と削除で再現した。Linux・Windows での実行、アプリの起動、GPU 描画は未確認。実機では大きな試験用モデルを別ドライブへ移し、移動先への保存を断る案内、通常の出力への再書き出し、復元中の画面応答を確認する。
