# 座標系・カメラ・描画

## 座標系とカメラの約束
- ワールド座標は glTF のまま使う。右手系、+Y が上、単位は変換しない。モデルの正面は +Z を向く。
- カメラは注視点まわりの回転台方式（`OrbitCamera`）。`yaw` はワールドY軸まわり、`pitch` は ±89° に制限する。上下が反転しないので、初めての人が迷子にならない。自由回転（トラックボール）は捨てた。
- 目の位置は `eye = target + distance × (cos pitch · sin yaw, sin pitch, cos pitch · cos yaw)`。`yaw = pitch = 0` は正面図になる。
- 初期視点は `yaw 35°・pitch 20°・fov_y 40°` で、境界球が収まる距離にする。距離は `r / sin(min(fov_y, fov_x) / 2) × 1.05`。
- 行列は glam 0.34 の `glam::camera::rh::view::look_at_mat4` と `glam::camera::rh::proj::directx::perspective_infinite_reverse` で作る（wgpu のNDCはZが0〜1・Yが上なので `directx`）。`Mat4::perspective_*` は 0.34 で削除済み。
- 深度は**反転Z・無限遠・Depth32Float**（クリア値 0、比較 `Greater`）。大きさが桁違いのモデルでも、遠近の設定を詰めずに前後が乱れない。近接面は `max((eyeから境界球の中心までの距離 − 半径) × 0.5, 半径 × 1e-4)`。
- 操作量の初期値: 回転 0.4°/ポイント、平行移動は注視点の深さで画面1ポイントがワールド何単位かに合わせる、ズームは `exp(−スクロール量 × 0.002)`、距離は境界球半径の 1e-3〜1e3 倍に制限。実機で触って調整する値であり、定数は `core::camera` の先頭にまとめる。
- カーソルへ向かうズーム: 注視点を通りカメラに正対する平面上で、カーソルの下の点がズーム前後で動かないように `target` をずらす。大きなモデルの細部へ、回転と移動を挟まずに寄れる。
- 投影は透視だけ。レビューJSONのカメラには `projection` の項目を持たせ、平行投影を後から足せるようにする。

## 描画方式：オフスクリーンの画像へ描き、eguiには画像として渡す
3Dは `SceneRenderer` が自前の画像へ描く。アプリは `egui_wgpu::Renderer::register_native_texture` で登録した `TextureId` を、中央の領域に画像として貼る。描画の命令は `App::ui` の中で作って `queue.submit` する。eguiの描画はその後に送られるので、同じフレームで反映される。未完了の描画は2回分までにし、超える前に古いものの完了を待つ。画面に出ていない間などはGPUより速く送れてしまい、未完了の分が形状の分だけメモリを持ち続けるためである（実測で1回転ごとに数MB増え続けた）。

この方式を選んだ理由:
1. **深度バッファを自分で持てる。** eguiの描画パスに深度を付けるには `NativeOptions::depth_buffer` が要り、`egui_kittest` の描画パスには深度が無い（`egui_kittest/src/wgpu.rs` で確認）。コールバック方式では画面なしのテストで3Dを描けない。
2. **3Dを描き直さないフレームを作れる。** パネルの上でマウスを動かすだけでもeguiは描き直すが、画像は使い回せる（要件9.6）。
3. アンチエイリアスの設定をeguiと切り離せる。3Dビューだけの画像も取り出せる。

代償は、ビューと同じ大きさの画像が1枚増えることと、eguiが貼るときの1回分の描画である。捨てた案（コールバックでeguiのパスへ直接描く）は [design-decisions.md](design-decisions.md)。

### 描画先
| 画像 | 形式 | 備考 |
|---|---|---|
| 色（多重サンプル4） | Rgba8UnormSrgb | 解決先へ書く |
| 深度（多重サンプル4） | Depth32Float | |
| 解決先（eguiへ渡す） | Rgba8Unorm、`view_formats = [Rgba8UnormSrgb]` | 描くときは sRGB のビュー、eguiへ登録するのは Unorm のビュー |
| 選択マスク | R8Unorm | 選択があるフレームだけ使う |

- `register_native_texture` は Rgba8Unorm を要求し、eguiのシェーダーは画像の値をガンマ値として扱う（`egui-wgpu/src/egui.wgsl`）。sRGBのビューへ描けば変換はGPUが行い、シェーダーで手計算しなくて済む。ビュー形式の指定が通らない環境では、Unorm へ直接描いてシェーダーの最後で変換する。
- 大きさは「領域の大きさ × `pixels_per_point`」を四捨五入した物理ピクセル。1未満なら描かない。`min(8192, limits.max_texture_dimension_2d)` を超えるときは上限に収めて拡大表示する。
- 大きさが変わったら描画先を作り直し、`update_egui_texture_from_wgpu_texture` で同じ `TextureId` に付け替える。終了時に `free_texture` する。
- 多重サンプル4の色と深度は、3024×1964 の全面で合わせて約190MBになる。確保に失敗したらサンプル数1へ落とす。数は定数にして、実測で見直す。

### 形状とインスタンス
- 頂点とインデックスは、モデル全体を**ページ**（GPUバッファ）へ詰める。1ページの目標は64MiB。それより大きいプリミティブは専用の1ページにする。プリミティブは `(ページ, インデックス範囲, base_vertex)` で指す。
- 描画は**インスタンス描画**。同じプリミティブを参照する部品は、インスタンスバッファの連続した範囲にまとめ、1回の描画命令で描く（要件9.3）。インスタンス1件は `ワールド行列・法線行列・色・NodeId・フラグ` で144バイト。
- 法線行列はワールド行列の左上3×3の逆転置で、CPUで作る。逆行列が有限でない（拡大率0など）ときは単位行列にする。
- インスタンスバッファは**表示状態が変わったときだけ**作り直す（非表示の部品は入れない）。頂点とインデックスは読み込み時に1回送るだけで、以後は送らない（要件9.2）。
- 面の向きによる間引きはしない。鏡像の変換や裏表の不揃いなモデルで面が消えるのを避ける。法線が視線と逆向きなら裏返して両面を照らす。塗りつぶしの負荷が増える分は、問題になってから計測して決める。
- ライティングは、カメラ側からの平行光1つと、上下で色を変える環境光。色はリニアで計算する。`has_normals` が偽のプリミティブは、フラグメントシェーダーでワールド座標の微分（`dpdx`・`dpdy`）から面法線を作る。頂点を三角形ごとに複製しなくて済む。
- baseColorFactor のアルファは無視して不透明で描く（簡略化の一覧に出す）。

### 選択の強調
- 選択範囲（`NodeId` の連続範囲）をフレームの定数として渡し、シェーダーが `NodeId` と比べて色を少し明るくする。選択を変えてもバッファは書き換えない。
- 輪郭線: 選択中のインスタンスだけを深度なしでマスクへ描き、解決先の画像にマスクの縁を重ねる。色の違いだけに頼らず（要件5.7）、**他の部品に隠れていても場所が分かる**。裏面を膨らませる方式は、法線の無いモデルや鋭い角で破綻するので採らない。線はマスクの内側に引く二重線で、外縁は暗く（#14161C）、その内側は明るい（#F4F7FB）。琥珀一色では橙の部品の上で見分けられなかったため。どの色の部品の上でも、暗い線か明るい線のどちらかが見える（GPU試験で橙・白・灰の箱を確かめる）。
- マスクへ描く対象は、各バッチの中で `NodeId` 順に並んだインスタンスから、選択範囲に入る部分を二分探索で求める。選択が変わったときに1回だけ計算する。

## GPU資源の寿命と上限
- `SceneRenderer` がGPU資源をすべて持つ。表示中と転送中の2組を持ち、転送が終わってから入れ替えて古い組を `destroy` する。転送の失敗や中止、新しい `begin_upload` では転送中の組だけを捨て、表示中のモデルは残す（要件2.7）。切り替えの間はGPUメモリも2組分になる。モデル本体（`Arc<Model>`）は、当たり判定に使うのでアプリが持ち続ける。
- 上限の検査は `plan_buffers` が `wgpu::Limits` だけを見て行う純粋関数にする。ページが `max_buffer_size` を超える、頂点数やインスタンス数が `u32` に収まらない、といった場合は確保の前に `LimitExceeded` を返す。GPUなしで試験できる。
- eframe の既定は `wgpu::Limits::default()`（`max_buffer_size` は256MiB）。`NativeOptions::wgpu_options` の `WgpuSetup::CreateNew` にある `device_descriptor` を包み、`max_buffer_size` をアダプタが許す値まで引き上げる。それでも1プリミティブが上限を超えれば、理由を表示して開かない。
- 確保は `device.push_error_scope`（検証エラーとメモリ不足）で囲む。あわせて起動時に `device.on_uncaptured_error` を登録する。wgpu の既定は捕まえなかったエラーでパニックするので、記録してモデルを閉じ、理由を表示する動きに置き換える。
- **転送の分割**: `continue_upload` は、渡された予算（初期値32MiB）まで `queue.write_buffer` をオフセットつきで呼び、残りは次のフレームへ回す。`write_buffer` は呼んだ時点でデータを複製するので、予算がそのまま1フレームのCPU負荷の上限になる。全体量が分かるので、進捗は実測のバイト数で出せる（要件2.8）。
- GPUが無いとき（`wgpu_render_state` が `None`）は、3Dビューに理由を出すだけで、他の機能は動かす。
