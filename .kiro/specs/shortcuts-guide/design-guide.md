# 手順書

## 読む人と書き方
読むのは、アプリを使う人である（作る人ではない）。Rust やリポジトリの中身を知らない前提で書く。画面の言葉とキーは、アプリの表示と同じ文字で書く（「開く」「計測」「吸着 入」「表示 mm」）。各ページは「したいこと → 手順（番号つき）→ 画面 → うまくいかないとき」の順にし、1ページ100行以内に収める。開発者向けの内容（形式の細部、性能値、試験）は既存の `docs/*.md` に任せ、手順書からはリンクだけを張る。

## ページの構成（`docs/guide/`）
| ファイル | 内容 | 画像（`images/`） |
|---|---|---|
| `README.md` | 入口。先頭に英語の短い案内（3行以内）。このアプリでできること・できないことを数行。場面からページを選ぶ表。確かめた環境 | `overview.png`（画面の5つの場所に名前を付けたもの。名前は本文の表で付け、画像に文字を描き足さない） |
| `01-start.md` | 用意するもの、ビルドと起動、見本を開く、終わり方（未保存の確認が出る場面） | `start-empty.png` |
| `02-open-view.md` | 開く（ボタン・ドロップ・起動の引数）、回す・ずらす・寄る、向きの立方体、表示の切り替え、部品の一覧と非表示 | `view-sample.png`、`view-xray.png` |
| `03-measure.md` | 計測の道具、吸着の印（頂点・辺・面）、距離と X・Y・Z の差、表示の単位、消し方 | `measure-snap.png`、`measure-panel.png` |
| `04-section.md` | 断面の入・切、軸・位置・反転、切った所を測る、切り口の見え方の制限 | `section-on.png` |
| `05-stl.md` | STL を開く、単位の仮定（mm）と替え方、STL から GLB として書き出す | `stl-open.png` |
| `06-shapes.md` | 図形を置く、寸法を打つ、外形を読む、複製と削除、取り消し | `shapes-dims.png` |
| `07-review.md` | 注釈を置く・直す・消す、視点を保存する、レビューの保存と読み込み、共有する前の注意（パスに利用者名が入ること） | `review-notes.png` |
| `08-export.md` | 書き出し、書き出すと作業の対象が移ること、結果の一覧の読み方、元のファイルは変わらないこと | `export-result.png` |
| `09-shortcuts.md` | 既定のキーの表、変えられないキー、設定の画面の使い方、重なったとき、戻し方、設定ファイルの場所、キーが働かない場面 | `keys-window.png`、`keys-conflict.png` |
| `10-troubleshooting.md` | 症状から引く表: 起動しない、文字が四角になる、開けない、キーが効かない、数値が1000倍違う、設定が保存されない、未保存の確認が出ない終わり方 | なし |
- 既存の文書との分担: README は概要と入口、`docs/glb.md`・`docs/stl.md`・`docs/review-json.md` は形式の説明、`docs/verify.md` は検証。同じ説明を2か所に書かず、手順書は「どう使うか」だけを書く。README の操作表は残すが、表の下に「キーは変えられます（手順書の 09）」の1文とリンクを足す。
- 確かめていないことは、書いてある所で分かるようにする。入口に「画面を動かして確かめたのは macOS（Apple Silicon）だけ」、09 に「Windows と Linux の設定の場所は、試験でだけ確かめた」と書く。確かめた後は、検証の記録に合わせて直す。

## 既定のキーの表を、アプリと照合する
`09-shortcuts.md` の既定の表は、`<!-- keys:begin -->` と `<!-- keys:end -->` の間に置く。行は「まとまり｜画面の言葉｜macOS｜Windows・Linux」。試験（`crates/app/tests/guide.rs`）が、`Action::ALL` と `Keymap::default()` から同じ表を作り、この間の文字と一致することを確かめる。食い違ったら、試験の失敗の文に、正しい表をそのまま出す（写せば直る）。変えられないキーの表も、同じ仕組みで `<!-- fixed:begin -->` の間に置く。

## 画像を撮り直せる形にする
- 手順は `crates/app/e2e/guide-<ページ>.json`（例: `guide-03-measure.json`）。既存の手順と同じ書き方で、見本（`assets/samples/review-sample.glb` と `review-sample.stl`）だけを使う。画像の名前は、上の表の名前にする。
- 実行は進行役が行う。`target/release/model-reviewer --script crates/app/e2e/guide-03-measure.json --out target/guide`。出た画像を開いて見て、よければ `docs/guide/images/` へ写す。**見ていない画像を置かない。**
- 自動操作は利用者の設定を読まない（要件7.1）ので、画像のキーの文字は必ず既定になる。
- 画像の大きさは、撮った機械の画面の倍率で変わる。撮った条件（ウィンドウの大きさ、倍率、OS）を `docs/verify.md` の「手順書の画像」に書く。手順を変えずに撮り直して、置き換えられることを確かめる。
- ポインタを載せた説明（ツールチップ）は、今の自動操作では撮れない（3Dビューの上を動かす手順しか無い）。説明の画像は手順書に載せず、文で書く。必要になったら、部品の上へポインタを動かす手順を足す（保留）。
- 個人の情報が写らないようにする。開くのは見本だけ。状態欄に出るのはファイル名だけで、フォルダは出ない（**要確認**: 詳細パネルを開いた画像にフォルダが出ないこと。出るなら、詳細パネルを開いた画像は撮らない）。
- 画像には、内容が分かる代わりの文を必ず付ける（既存の README と同じ書き方）。

## 入口
- **README（日本語）**: 「起動」の節の前に「使い方は手順書へ」の1行とリンク。**README（英語）**: 「The step-by-step guide is in Japanese」の1行とリンク。
- **アプリのヘルプ**: 表の下に、[ショートカットの設定] と「手順書: docs/guide/README.md」、[場所を写す]。[場所を写す] は、リポジトリの場所（`Cargo.toml` の `repository` を `env!` で読む）に `/blob/HEAD/docs/guide/README.md` を足した文字を、クリップボードへ入れる（`egui::Context::copy_text`）。ブラウザは開かない（理由は design-decisions.md）。**要確認**: 公開した後の実際の場所で開けること。`repository` が空なら、相対の場所だけを出してボタンを出さない。
- **設定の画面**: 下端に「くわしくは手順書の 09」の1行（文字だけ）。

## リンクと画像の検査
`crates/app/tests/guide.rs` が `docs/guide/*.md` を読み、相対のリンクと画像の参照（`](` の後ろ。`http` で始まるものと `#` だけのものを除く）が、実在するファイルを指すことを確かめる。10ページと入口がそろっていること、各ページが100行以内であることも見る。場所は `env!("CARGO_MANIFEST_DIR")` から相対でたどり、区切りを文字列で組み立てない。
