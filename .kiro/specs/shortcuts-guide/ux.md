# UX設計（ユーザーストーリーとUX5階層）

実装の前に書いた。戦略から順に決め、下の階層の判断は上から導いている。第1〜第3段階の ux.md はそのまま有効で、ここには足す分だけを書く。

## 誰のためか
- **初めて使う人**: 受け取ったデータを確かめたいだけの人。キーを覚える気は無い。ボタンを押しながら、気づいたら覚えている形がよい。
- **毎日使う人**: 同じ操作を何十回もする人。手がほかのCADの配列を覚えていて、違うキーを押してしまう。自分の配列に直したい。
- **手順を調べる人**: 「STL を開いたら数値が変だ」「キーが効かない」で止まった人。画面の言葉で探して、自分の場面のページに着きたい。

## ユーザーストーリー
| # | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| S1 | ボタンを押すついでにキーを知りたい。表を開いて探すのは面倒 | ポインタを載せた説明と、道具の列の小さい表示に、今のキーが出る |
| S2 | 一覧でまとめて見たい。操作の名前で探したい | 設定の画面に全部の操作が並び、名前やキーで絞れる |
| S3 | 自分の手になじむキーに変えたい | 行を押してキーを押すだけで変わり、すぐ効く |
| S4 | 変えたせいで別の操作が黙って効かなくなるのは困る | 重なったら相手の名前が出て、置き換えるかやめるかを選べる |
| S5 | おかしくしてしまったら戻したい | 1つだけ、または全部を初期値に戻せる |
| S6 | なぜそのキーを選べないのかを知りたい | 選べないキーを押すと理由が出る。変えられないキーの一覧もある |
| S7 | 次に起動しても同じ設定であってほしい。設定のせいで起動できなくなるのは困る | 保存される。ファイルが壊れていても既定で起動し、知らせが出る |
| S8 | 使い方を、順番に読める形で知りたい | 手順書に、場面ごとのページと画面の画像がある |

## 1. 戦略
- 目的は「覚えなくても使え、覚えたら速く、手になじまなければ直せる」こと。キーの数を増やすことではない。
- 大事にする順番は、①利用者の作業と設定を失わない・壊さない、②画面に出ているキーが本当に効く（嘘の表示をしない）、③変えた結果がその場で見える、④迷ったら元に戻せる、⑤手順書が画面と食い違わない。
- 設定を触らない人の画面を変えない。足す表示は、説明の文と、道具の列の小さい1文字だけにする。

## 2. 要件（戦略から導いたもの）
- ①から: 保存は一時ファイルからの付け替え。壊れたファイルは消さずに別の名前で残す。新しい版のファイルは上書きしない。自動操作と試験は利用者の設定に触れない。削除（Delete）は固定にして、うっかり別のキーへ移らないようにする。
- ②から: 画面のキーの文字は、すべて割り当ての表から作る。配列によって印字が違うキー（記号、Shift+数字）は、表示と実際がずれるので割り当てさせない。
- ③から: 確定のボタンを置かず、変えたらすぐ効かせて保存する。説明・道具の列・ヘルプの表が同時に変わる。
- ④から: 行ごとの「初期値に戻す」と、2回押しの「すべて初期値に戻す」。取り込みは Esc でやめられる。重なりは黙って奪わない。
- ⑤から: 手順書の既定のキーの表を、アプリの表と試験で照合する。画像は自動操作で撮り直せる形にする。

## 3. 構造
- 画面は1枚のまま。足すのは「ショートカットの設定」の小窓1つ（ヘルプと同じ出し方）。入口はヘルプの中のボタンと、割り当てられる操作「ショートカットの設定」。上部のボタンは増やさない（幅960で既にいっぱい）。
- 操作を名前で探して実行する小窓は作らない。探す役目は、設定の画面の検索の欄に持たせる（理由は末尾の1）。
- 操作は3種類に分かれる。**割り当てられる操作**（41個）、**変えられないキー**（Esc・Enter・Delete など）、**割り当てに使えないキー**（OSや入力欄が使うもの）。設定の画面は、上に1つ目、下に残り2つを理由つきで並べる。
- キーの働く場所は2つ。第3段階までの操作は「ポインタが3Dビューの上」（今の決まり）。開く・保存・書き出し・ヘルプなどは「どこでも」。どちらも、入力中とダイアログ中は働かない。
- 手順書は、入口 → 場面のページ（起動 → 開く・見る → 測る → 切る → STL → 寸法の図形 → 指摘と保存 → 書き出し）→ 設定 → 困ったとき。各ページは「したいこと → 手順 → 画面 → うまくいかないとき」の順。

## 4. 骨格
```
┌ ショートカットの設定 ────────────────────────────────────────────┐
│ [ 探す: 名前かキー            ]         この設定は保存されます    │
│ ── 道具 ──────────────────────────────────────────────────────── │
│ 選択            [ V ]                                            │
│ 移動            [ キーを押してください（Esc でやめる） ]  ← 取り込み中 │
│ 回転            [ T ] ●変更  [外す] [初期値に戻す（R）]          │
│   └ 「T」は「…」で使っています  [置き換える] [やめる]  ← 重なったとき │
│ 図形            [ 未割り当て ]                                   │
│ ── 見る ──（以下、まとまりごと）                                 │
│ ── 変えられないキー ──                                           │
│ Esc やめる・解除／Enter 確定／Delete・Backspace 削除             │
│ 使えないキー: Tab・Space・矢印、Cmd+C/X/V/A、Cmd+Q/W/H/M ほか（理由）│
│ [すべて初期値に戻す]                                   [閉じる]  │
└──────────────────────────────────────────────────────────────────┘
```
- 行のキーの部品を押すと取り込みが始まる。取り込みは1行だけ。別の行を押すと、前の行の取り込みはやめる。
- 「変更」の印と [初期値に戻す] は、既定と違う行だけに出す。[外す] は、キーがある行だけに出す。
- 選べないキーを押したときの理由は、その行のすぐ下に出す（「Shift と数字の組は、配列によって別の記号になるため使えません」など）。
- 道具の列は、ボタンの右下に1文字（V・G・R・S・M・N）。修飾つきや2文字以上のキーは出さず、説明の文に出す。
- 説明の文は「移動（G）: 矢印をドラッグして動かします」の形のまま、括弧の中だけが今のキーになる。
- ヘルプの下に「[ショートカットの設定]　手順書: docs/guide/README.md [場所を写す]」。

## 5. 表層
配色と文字は第3段階のまま。足す色は無い。道具の列の1文字は補助の文字色（本文より薄い）で、ボタンの絵に重ならない隅に置く。「変更」の印は琥珀（選ばれた道具と同じ色）の小さい丸と文字。取り込み中の行は、選ばれた道具と同じ枠で囲む。理由と確認の文は、行の下に字下げして出す。記号（⌘ など）は使わず、「Cmd」「Ctrl」「Shift」と書く（字形が無い環境で欠けないようにする）。

## この検討で要件・設計が変わった点: 11件
依頼の4項目をそのまま実装した場合からの変更。
1. **操作を探す小窓を別に作らず、設定の画面に検索を入れた**（S2、戦略「数を増やさない」）。日本語の名前で探すには変換が要り、変換の確定の Enter と実行の Enter が同じキーになる。確かめられない挙動を足すより、探す役目だけを満たした。
2. **確定のボタンを無くし、変えたらすぐ効かせて保存する**（戦略③）。「OK を押し忘れて消えた」が起きない。代わりに、行ごとと全部の初期化を置いた（④）。
3. **重なりを黙って奪わない**（S4、戦略④）。相手の名前を出して選ばせる。初期値に戻すときも同じ確認を通す。
4. **Delete・Esc・Enter を固定にし、「変えられないキー」として画面に並べた**（戦略①、S6）。削除が別のキーへ移る事故を無くし、Delete と Backspace の2つを持つ特例も要らなくなった。
5. **記号キーと Shift+数字を割り当てに使わせない**（戦略②）。配列によって印字と実際がずれ、画面のキーが嘘になる。
6. **キーの働く場所を操作ごとに持たせた**（構造）。足した Cmd+O などは、ポインタが上部のボタンの上にあっても働く。第3段階までの操作は今の決まりのまま。
7. **保存するのは既定との差だけ**（戦略①）。後の版で操作や既定が増えても、変えていない所は新しい既定に付いていく。
8. **自動操作では利用者の設定を読まない**（戦略①）。設定を変えた人の機械でも、既存の手順が同じ結果になる。
9. **ヘルプからブラウザを開かず、手順書の場所を出して写せるようにした**。開くには外部の依存を足す必要がある（[design-decisions.md](design-decisions.md)）。
10. **画面のキーの文字を、すべて割り当ての表から作る**（戦略②）。説明・ヘルプ・何も開いていない画面に手書きで入っていたキーを無くし、手順書の表も試験で照合する（⑤）。
11. **キーの小さい表示は道具の列だけ**（戦略「触らない人の画面を変えない」）。上部と上端のボタンは幅960で余りが無く、説明の文に出す。
