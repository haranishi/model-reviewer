# 書き出し（画像の埋め込みと、見た目の写し）

要件6。第2段階の決まり「元のバイト列を土台にし、変えた所だけを直し、足す物は配列と BIN の末尾に足す。既存の要素の番号は1つも変えない」と、第5段階の [色の写し](../creation-basics/design-export.md) を保ち、広げる。

## 入力に足すもの（`gltf::export`）
```rust
pub struct ExportScene { /* … */ pub textures: ExportTextures }
pub struct ExportTextures {
    pub images: Vec<ExportImage>,      // Draw.tex → uses[i].image → images[j]。文書の番号のまま
    pub uses: Vec<TexUse>,
}
pub struct ExportImage { pub hash: ImageHash, pub mime: Mime, pub bytes: Option<Arc<[u8]>> }  // 貼った画像だけ Some
ExportNote::Retextured { nodes: u32, images: u32, image_bytes: u64, baked: u32 }
```
`app::session::export::export_scene` が、文書の表をそのまま写す。画像のバイト列は `Arc` の共有で、複写しない。

## 変わったかどうかの判定
- 色の写しと同じく、**ファイルにある部品は自分のノード、複製は写す元のノードの描画と、土台を読み直した値を比べる**。比べるのは、基本色のビットと、`same_look(文書の TexUse, 土台の TexUse)`（どちらも無ければ同じ）。
- `same_look` は値で比べる。画像はハッシュ、`sampling`・`cutoff` は値、`map` は次の3つを同じとみなす: ①どちらも `Vertex` で、行列のビットと UV の番号が同じ（`info_from` は比べない）、②どちらも `Box` で `size` と `aspect` のビットが同じ、③片方が `Box { size, .. }` で、もう片方が `Vertex`（単位行列。UV の番号は問わない）かつ `baked_box == Some(size)`（ビットが同じ）。
- ③があるので、箱形で貼って書き出した後、文書（箱形のまま）と新しい土台（UV に焼いた形状）が「同じ」になり、次の書き出しで何も足さない（要件6.7）。

## 足すもの（`export/recolor.rs` を「見た目の写し」に広げる。名前は `restyle.rs` に改めてよい）
1. **画像**。描画が指す画像のうち、土台の `images` に同じハッシュのものがあれば、その番号を使う。**土台の側は、材質から使われていない画像も含めて、`bufferView` を持つすべての画像のハッシュを索引にする**（土台を読む所 `export/base.rs` だけが作る。読み込みの `ImageInfo` は出す画像しか持たないので、それに頼ると、外して書き出した後に取り消したとき、元の画像をもう1枚足してしまう）。無ければ、バイト列を BIN の末尾に足し（4バイト境界にそろえる。`target` の無い `bufferView`）、`{"bufferView": n, "mimeType": "image/png"}` を `images` に足す。**`name` と `uri` は書かない。** 同じハッシュは、1回の書き出しで1回だけ足す。足す順は、部品の順・描画の順で最初に出た順（同じ文書から同じバイト列にするため）。
2. **サンプラ**。`Sampling` を glTF の数（`wrapS`・`wrapT`・`magFilter`・`minFilter`）に直し、土台に同じ値の要素があればそれを、無ければ足して使う。
3. **テクスチャ**。`{"sampler": s, "source": i}`。土台に同じ値の要素があればそれを使う。
4. **材質の写し**。鍵を（元の材質の番号、色のビット、画像の変更）に広げる。元の材質の JSON を写し、変わった項目だけを直す。
   - 画像を替えた（UV で貼る）: `baseColorTexture` の項目を、**`UvMap::Vertex.info_from` が指す材質の `baseColorTexture`（`texCoord`・`extensions`・`extras` を含む）の写し**にし、`index` だけを新しいテクスチャの番号にする。写す元の材質が今の土台に無い、または `baseColorTexture` を持たなければ `InvalidScene`。材質の番号は書き出しをまたいで変わらない（足すだけの決まり）ので、外して書き出した後に取り消しても、最初の材質から `TEXCOORD_1` や UV の変換を取り戻せる。メッシュの写しは `material` だけを替えるので、UV のアクセサは残っている。
   - 画像を外した: `baseColorTexture` の項目を除く。
   - 箱形で貼った: `baseColorTexture` を `{"index": t}` と、箱形の組が0番でなければ `texCoord` だけにし（変換なし）、`alphaMode` と `alphaCutoff` は元のまま保ち、`extras.model_reviewer.box_size` に `size` を書く（`extras` がオブジェクトでなければ、印を書かずに進める。次の書き出しで同じ形状をもう一度足すことになるので、結果の一覧に出す）。
   - 元のプリミティブに材質が無いときは、基本色（と上の項目）だけの材質を作る。
5. **メッシュの写し**。UV で貼った・外した・色だけ変えた描画は、今までどおり `material` だけを替える（形状のデータは増えない）。**箱形で貼った描画**は、土台を読み直した形状（複製は写す元、足した図形は `scene.added`）に `bake_box` を掛け、位置・法線（あれば）・元の `TEXCOORD_n` をすべて同じ番号で（分けた頂点へ元の頂点の値を、小数で）・箱形の UV を元の組の次の番号で・番号のアクセサを足して、そのプリミティブを `{"attributes": {…}, "indices": n, "material": m, "mode": 4}` に差し替える。元のプリミティブにあった頂点の色と接線は写さない（規格の上では無くてよい項目）。**スキンを持つノードと、モーフを持つプリミティブは焼かない**: 関節と重み（`JOINTS_0`・`WEIGHTS_0`）を落としてノードの `skin` を残すと規格に反し、モーフを落とすとアニメーションの重みの数が合わなくなる。貼る前に断る（[design-paste.md](design-paste.md)）のに加え、書き出しでも `no_box_nodes` と土台の JSON の両方で確かめ、当たれば `InvalidScene` にする。同じ（形状、幅と高さ、元の UV の組）の焼いた形状は1回だけ足す。**取り消しで戻ったとき**: 土台の形状が焼いた形状に替わっていて、文書が箱形でない描画は、開いた時点の描画（`ExportScene::originals`）と比べ、同じなら開いた時点のプリミティブの JSON をそのまま、違えばその形状と材質を元に写す。全部が戻れば元のメッシュを指す。
6. **足した図形**（`Appender`）。画像の無い描画は今のまま（基本色と `metallicFactor: 0` の材質）。画像のある描画は、焼いた形状と、`baseColorTexture` と印を持つ材質を足す。材質の鍵は（色、テクスチャの番号、`size`）。
7. `extensionsUsed` と `extensionsRequired` は変えない（拡張を新しく使わないため）。

## 照合に足すもの・ゆるめるもの（`export/verify.rs`）
| いまの確かめ | 直し方 |
|---|---|
| 最上位は8つの配列以外が元と等しい | `images`・`textures`・`samplers` を足し、11個にする。元からあった要素は値として等しく、足した要素は末尾にある |
| 足した `bufferView` は形状のアクセサが指す | 足した画像が指すもの（`target` なし）も認める。その範囲は足した BIN の中にあり、バイト列のハッシュが `ExportImage.hash` と同じ |
| 足した材質は、元の写し（基本色だけ違う）・材質なしの写し・足した図形の材質のどれか | 「基本色・`baseColorTexture`・印を除いて元と等しい」写しと、足した図形の画像つきの材質を加える。UV で貼った写しの `baseColorTexture` は、`index` を除いて元のどれかの材質のものと等しいこと |
| （新規） | 焼いたプリミティブを使うノードが `skin` を持たず、元のプリミティブが `targets` を持たないこと |
| ノードの `mesh` が変わるのは、`material` だけを替えた写しのとき | 箱形で焼いたプリミティブを認める。条件は、三角形の数が同じで、各三角形の頂点の位置が元の形状とビット単位で同じ順に並ぶこと |
| 開き直した描画ごとの形状と色が文書と一致 | **描画ごとの見た目（`same_look`）が文書と一致**を足す。箱形の描画は、形状を「三角形ごとの位置の並び」で比べ、UV が `box_uv` の値と（相対 1e-6 以内で）合うことを確かめる |

## 画面と結果の一覧（`app`）
- `note_ja(ExportNote::Retextured)`: 「画像を変えた部品 3 個: 画像 1 枚（245 KB）を足しました。元の画像と材質は、ファイルに残しています」。`baked > 0` なら「箱形の投影の部品 2 個は、UV 付きの形状を作って足しました（頂点の色と接線は写していません）」。
- 今の注意（色を変えた部品があり、モデルにテクスチャがある）は、部品単位の判定に替える。
- 書き出しの後、文書の箱形の描画は箱形のまま残す（画面は式で貼り続ける）。開き直すと、同じ部品は「モデルの UV」として開く。そのときは「1枚の大きさ」の欄が出ない（焼いた UV を持つ形状になるため）。`docs/glb.md` に書く。

## 利用者の持ち物（要件5.3・6.1）
書くのは、付帯情報を落とした画像のバイト列と `mimeType` だけである。ファイル名・フォルダ・貼った日時は、文書にも GLB にも入らない。レビューJSON は変えない（レビューは、書き出した GLB の識別に結び付く。今の決まりのまま）。

## 大きさ
- 画像は復号せずに写すので、書き出しのメモリは「元のファイル ＋ 足す BIN」。全体が 4 GiB を超えるときは、今の決まりで書く前に断る。
- 箱形で焼くと、形状のデータが増える（頂点は、軸の境目で分かれる分だけ元より多い。番号は同じ数）。500万三角形の STL に貼って書き出すと、形状がほぼ2倍になる。結果の一覧のバイト数で分かるようにする。

## 壊れやすい所
1. **`same_look` の③**。印を書き忘れる、または読み込みが印を拾わないと、書き出すたびに焼いた形状が増える。`exporting_twice_adds_nothing` で固定する。
2. **ハッシュを取る対象**。文書は付帯情報を落とした後のバイト列、土台は BIN の中の画像のバイト列（詰め物を含まない `byteLength` の範囲）。範囲を1バイトでも取り違えると、同じ画像が毎回足される。
3. **照合のゆるめすぎ**。「足した材質なら何でも通す」にすると、元の材質の金属らしさや拡張を落とす誤りを見逃す。除く項目を名指しで比べる。
4. **写す元の取り違え**。複製は写す元のノード、書き出した後の足した図形は自分のノードと比べる（色の写しと同じ決まり）。焼く形状も同じ出どころから取る。
5. **足す順**。ハッシュの表を走査した順で足すと、実行ごとにバイト列が変わる。最初に出た順にする。
6. **外す → 書き出す → 取り消す → 書き出す**。元の画像の重複、`texCoord` と UV の変換の消失、MASK の閾値の食い違いが、どれもこの順で出る。`remove_export_undo_export_restores_original` で止める。

## 要確認
- 材質の差し替えの拡張（プリミティブの `extensions` の対応表）を持つファイルで、箱形の写しが対応表をどう扱うか。写さない方針（上の5）で、試していない。`docs/glb.md` に「未確認」と書く。
- ほかのソフトが、`name` の無い画像と、同じ名前の材質の写しをどう扱うか。進行役が1つのソフトで確かめ、使ったソフトと版を `verification.md` に書く。
