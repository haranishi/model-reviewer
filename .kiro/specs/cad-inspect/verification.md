# 検証の記録（第3段階。2026-11-27、macOS・Apple M4 Pro）

区切りA（吸着する計測・断面・表示の単位）の記録は [verification-a.md](verification-a.md)。区切りB（STL と寸法）は、レビュー修正後と取り込み時の結果を以下に記す。

## 区切りBのレビュー修正

| 対象 | 修正前に再現した失敗 | 修正後に試験で確認したこと |
|---|---|---|
| STL の再指定 | 改名後は部品0が見つからず復元が止まった | 注釈と非表示状態が新しい名前の部品0に戻った。GLB 用の名前違いと未知の番号は拒んだ |
| 頂点の結合 | 結合表が標準の `RandomState` を使う試験が失敗した | 標準の表を使い、頂点番号は初出順で、正負のゼロは同じ頂点になった |
| 寸法 | 幅2 mの板で厚みを0.002 mmから0.003 mmに変えても履歴が増えなかった | 履歴が1件増え、取り消すと元の厚みに戻った。丸め誤差だけでは履歴は増えなかった |
| 実パス | STL の名前の1バイトが、読み直し用のパスでは置換文字に変わった | STL・GLB ともパスの元のバイトを保持した。書き出し、単位変更、レビュー保存先の照合で表示名を誤用しなかった |
| 断面 | 断面を無効にしたビューポートで境界箱を1回の描画につき2回求めた | 無効・有効・再び無効の順に0回・1回・0回だった |
| 移動の状態欄 | mm 表示でも「移動 +0.4535」とシーンの値が出た | 同じ移動が「移動 +453.5 mm」になった。cm・m・「ファイルと同じ」も3Dビューの書式と一致した |

回帰試験は8件追加した。macOSで通常の試験489件が成功し、失敗0件、既定の除外52件。整形検査、全ターゲットの静的検査（警告0件）、リリースビルドも成功した。

この保存先では非UTF-8名の作成が拒まれた。Unix用の試験は、作成できる保存先ではSTL・GLBの実ファイルを開いて書き出し、再度書き出したGLBを読み直す。今回は同じ表示名を持つ別ファイルを用意し、取り違えを防ぐ動作を確認した。非UTF-8名の実ファイルでの往復、Linux・Windows上の実行、アプリ起動とGPU描画は今回の未確認項目である。

## 外部のソフトで作った STL（Blender 5.2.2 LTS で書き出した。リポジトリには置かない）
- 箱（20×30×40 mm、バイナリと ASCII）・円柱（直径50・高さ25）・25万三角形の形の4つを読み、落ちず、寸法と三角形の数が合った。
- 箱は実機で、角から角が頂点どうしで 20 mm、外形が 20×30×40 mm（相対の差 1e-6 未満）。元のファイルは変わらない。
- 書き出した GLB を同じソフトで開くと、大きさはメートルで正しい。ただし向きは 20×40×30（Z が上のソフトの STL を、Y が上のまま扱うため）。書き出す前に回転の X に -90 を入れると 20×30×40 になった。[docs/stl.md](../../../docs/stl.md) に書いた。上の向きの切り替えは、その後に [STL の上の向き](../stl-up-axis/verification.md) で入れた。
