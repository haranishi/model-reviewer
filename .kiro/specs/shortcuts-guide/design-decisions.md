# 判断・捨てた案・落とし穴・保留

## 決めたこと（理由つき）
| # | 決めたこと | 理由 |
|---|---|---|
| 1 | 操作とキーの対応を1つの表にし、振り分けも画面の文字もそこから作る | いまは `app.rs` の分岐と、説明・ヘルプ・README の文字が別々で、変えられるようにすると必ず食い違う |
| 2 | 既定は第3段階と同じ。足すのは、キーの無かった4つ（Cmd+O・Cmd+S・Cmd+E・F1）だけ | 依頼は「ショートカットを足す」。覚えたキーを変えない |
| 3 | 修飾は完全一致で照合する。**Shift+Home が働かなくなる** | 「Z と Shift+Z」のように、修飾の違いで別の操作を持てるようにするには、表の側を完全一致にするしかない。Home だけ Shift を見ていなかったのは、意図ではなく書き方の差である |
| 4 | Esc・Enter・Delete・Backspace は固定 | Esc は場面ごとに意味が変わる（6段の順）。Delete は消す操作で、誤って別のキーへ移ると害が大きい。固定にすれば「1つの操作に1つのキー」で済む |
| 5 | 使えるキーを、英字・数字・F1〜F12・Home など に限り、修飾は Shift と Cmd（Ctrl）だけ | 記号と Shift+数字は、配列で印字と届くキーが違う。Alt は macOS で別の文字を打つキーで、届き方を確かめていない。表示と実際がずれる組を入れない |
| 6 | 入力欄の編集とOSが使う組（Cmd+C・X・V・A、Cmd+Q・W・H・M）は、どのOSでも断る | Cmd+C などはキーとして届かない（下の落とし穴3）。OSで分けると、設定ファイルを別の機械へ持っていったときに意味が変わる |
| 7 | 1つの操作に1つのキー。重なりは確認して置き換える | 表が単純になり、「どちらが効くか」を考えなくて済む |
| 8 | 変えたらすぐ効かせ、すぐ保存する。確定のボタンは無い | 保存し忘れが起きない。戻す手段（行ごと、全部）を別に持つ |
| 9 | 保存するのは既定との差だけ。知らない項目は書き戻す | 後の版で既定や操作が増えても、利用者が変えていない所は新しい既定になる。新旧の版を行き来しても割り当てが消えない |
| 10 | 形式は JSON、場所は環境変数から決める。外部の依存を足さない | `serde_json` は使っている。設定の場所のクレート（`dirs` の類）は `Cargo.lock` に無く、要るのは3つの場所だけである |
| 11 | 壊れたファイルは、次に保存するまで触らない。保存の直前に `.broken` として残す。新しい版と読めないファイルは上書きしない | 起動しただけで利用者のファイルを書き換えない。手で直す余地を残す |
| 12 | 設定の場所を決めるのは実行ファイルの入口だけ。自動操作は既定を使う | 試験と自動操作が、利用者の設定に左右されず、触れもしない |
| 13 | キーの働く場所（3Dビューの上／どこでも）を操作ごとに持つ | 第1段階の要件（パネルの上では1文字のキーを働かせない）を保ったまま、開く・保存をどこでも押せるようにする |
| 14 | 操作を探して実行する小窓は作らない。設定の画面の検索で探せるようにする | 下の「捨てた案」 |
| 15 | 手順書は `docs/guide/` に日本語で10ページ。英語は入口の案内だけ | 画面が日本語だけである。英語の手順は、画面の言葉を訳せないと役に立たない |
| 16 | 既定のキーの表とリンクを、試験でアプリと照合する | 手順書は、直し忘れると黙って古くなる |

## 既存の振る舞いを変える所（要件にも書いた）
1. Shift+Home が初期視点にならない（要件2.7）。
2. Cmd+O・Cmd+S・Cmd+E・F1 が働く（要件2.2）。今までは何も起きなかった。
3. 同じフレームに届いた複数のキーの順が、コードの順から届いた順になる（design-keymap.md）。
4. `LaunchArgs` に項目が増える（公開の型。手で組み立てている試験を、契約の作業で直す）。
5. 説明の文とヘルプの表の、キーのつなぎ方をそろえる（「Shift＋H」→「Shift+H」。全角の「＋」をやめる）。README の表も合わせる。

## 捨てた案と理由
| 案 | 捨てた理由 |
|---|---|
| 操作を名前で探して実行する小窓 | 名前が日本語なので、探すのに変換が要る。変換の確定の Enter と、実行の Enter が同じキーで、変換中の Enter は第1段階から未確認のままである。開いた直後の入力欄に入力の位置が入らない罠もある。41個の操作はボタンと一覧で届く。要るなら別の作業にする |
| 設定を TOML などで書く | 読み書きのクレートを直接の依存に足すことになる。手で書く人より、画面で変える人のための機能である |
| 設定の場所のクレートを足す | 依存とライセンスの確認が増える。場所の決まりは3行で書ける |
| モデルの隣やレビューJSONに設定を書く | 利用者のフォルダに自分のファイルを増やさない。割り当ては人のもので、モデルのものではない |
| 全部の割り当てをファイルに書く | 既定を後から変えられなくなる（古い既定が利用者の設定として残る） |
| OK とキャンセルのある設定の画面 | 取り込み → 確認 → OK と段が増える。途中の状態（まだ効いていない割り当て）を画面に持つことになる |
| 重なったら黙って相手から奪う／重なりを許す | 効かなくなった操作に気づけない／どちらが働くか分からない |
| OSごとに断る組を変える | 設定ファイルの意味が機械で変わる |
| 自動操作でも利用者の設定を読む | 設定を変えた機械で、既存の手順が違う結果になる |
| 環境変数で設定の場所を差し替える | 差し替えの入口が2つになる。引数 `--keymap` で足りる |
| ヘルプから手順書をブラウザで開く | egui の「場所を開く」は、有効にしていない機能（`egui-winit` の `links`。`webbrowser` クレート）が要る。`Cargo.lock` に `webbrowser` は無い。場所を出して写せれば足りる（分かれ道3） |
| 手順書の本文をアプリの中に出す | 画像と表を出す部品が要る。文書を2か所で持つことになる |
| 上部と上端のボタンにもキーの小さい表示 | 幅960で余りが無い。重なりの試験（`layout.rs`）を崩す |
| 記号で修飾を書く（⌘ など） | 字形が無い環境で欠け、画面なしの試験が落ちる（第1段階の落とし穴5） |

## 落とし穴
1. **`has_focus` は前面でないウィンドウで常に偽。** 取り込みを「部品が入力の位置を持っているか」で判定しない。`Session.keys.capture` で判定する。
2. **検索の欄に入力の位置が残ったまま取り込みを始めると、キーが届かない。** 振り分けが「入力中」で先に返る。取り込みを始めるときに入力の位置を手放す。
3. **Cmd+C・X・V はキーの出来事として届かない。** `egui-winit` が「コピー」などの出来事に変えて返す（`egui-winit/src/lib.rs` の `on_keyboard_input`）。取り込み中に何も起きないように見えるので、その出来事を見て理由を出す。
4. **Shift+数字は、数字のキーとして届かない。** 論理キーが記号（`!` など）になる。記号が egui の知らないキーなら物理キーに落ちるので、配列によって届いたり届かなかったりする。だから断る。
5. **`egui_kittest` は描けない文字で落ちる。** キーの文字に記号を使わない。F1・PageUp などの文字で試験を1本通す。
6. **入力用の構造体に項目を足すと、手で組み立てている試験が通らなくなる。** `KeyLabels::default()` を既定の文字にして、足すのは1行で済むようにする。契約の作業でまとめて直す。
7. **ヘルプが開いているかは egui の一時の記憶にある**（`ids::HELP_OPEN`）。設定の画面を開くときにヘルプを閉じないと、小窓が2枚重なる。
8. **説明の文は、いまは静的な文字列の表にある**（`ui/toolrail.rs` の `hint`）。キーを埋めると、毎フレーム文字列を作ることになる。`KeyLabels` は割り当てが変わったときだけ作り直し、説明の文は出すとき（ポインタが載ったとき）だけ組み立てる。
9. **`fs::rename` は、置き換え先がフォルダだと失敗する。** 失敗の経路で一時ファイルを消す。試験にする。
10. **起動しただけでフォルダやファイルを作らない。** 設定を変えない人の機械に何も残さない。
11. **第3段階の区切りBが、同じファイル（ヘルプ、状態欄、自動操作、README）を変える。** 取り込む前に始めると衝突する。

## 確かめた事実と、要確認
- 確かめた（リポジトリと依存の実物）: キーの振り分けは `app.rs` の `shortcut_commands` の1か所。既存の試験の7つのファイルが、この関数を `(ctx, session)` で呼ぶ。`Cargo.lock` に `dirs`・`directories`・`webbrowser` は無く、`serde_json` は `app` の依存にある。`eframe` は既定の機能を切っている。egui のキーの出来事は「論理キー、無ければ物理キー」で届く（配列に英字が無い場合の逃げ道）。`egui::Key` に `name()`・`from_name()`・F1・PageUp・Home がある。自動操作の `key` は、キーと修飾を入力へ注入する（`command` は macOS で Cmd）。レビューの保存は一時ファイルからの付け替えである。第1段階の要件に「パネルの上では1文字のキーを働かせない」がある。
- 要確認: 日本語入力が入のまま、入力欄の外でキーがどう届くか（`egui-winit` には日本語入力を許すかどうかの切り替えがあるが、入力欄の外でどう働くかを実機で見ていない）。日本語配列の実物。macOS の既定のメニューが持つキー（Cmd+H・Cmd+M のほかにあるか。あれば断る組に足す）。Cmd+O・S・E が、OSやメニューに取られずに届くか。F1 が macOS で届くか（Fn の設定による）。テンキーの数字が、文字キーの段と同じキーとして届くか（今の文書は「テンキーは使わない」）。修飾キーだけを押したときに、キーの出来事が届かないこと。`egui::Key::name()` の数字とページ送りの文字。`fs::rename` の置き換えが Windows で通ること（レビューの保存と同じ方法だが、CI の試験で確かめる）。状態欄の知らせを出す入口の名前。`Tool::Shape` をキーで選んだときに、ボタンと同じ動きになるか。

## 保留（範囲外。足したくなったもの）
操作を探して実行する小窓／Alt（Option）・記号・テンキーの割り当て／1つの操作に複数のキー、2打鍵／設定の書き出しと読み込み、配列の見本（プリセット）／単位・ウィンドウ・配色など、ほかの設定の記憶／押せないキーを押したときに理由を状態欄へ出す／ツールチップを撮る自動操作の手順／手順書の英語版と、画面の英語化／メニューバーにキーを出す／開いている間のファイルの見張り。

## 依頼者に確かめたい分かれ道（どれも既定で進められる）
1. **足す既定のキー**: 既定は「Cmd+O 開く・Cmd+S レビュー保存・Cmd+E 書き出し・F1 ヘルプ」の4つを足す。足さないなら、割り当てられる操作として置くだけにする。
2. **操作を探して実行する小窓**: 既定は「作らない（設定の画面の検索で探す）」。CAD らしさとして欲しいなら、日本語入力の確認を含む別の作業にする。
3. **ヘルプから手順書を開く**: 既定は「場所を出して写す」。ブラウザで開くなら、外部の依存を1つ足す（ライセンスの確認が要る）。
4. **Shift+Home**: 既定は「働かなくする」。残すなら、初期視点に2つ目のキーを持たせる特例が要る。
