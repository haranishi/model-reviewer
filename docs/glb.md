# 対応するGLBと、対応しないもの

自己完結した GLB だけを読みます（STL は [stl.md](stl.md)）。判定は拡張子ではなく、先頭4バイトが `glTF` であることです。形状は BIN チャンクから読みます。`uri` があるバッファ（data: を含む）は読みません。

三角形リストを読みます。ストリップとファンはリストへ直します。既定のシーンが無ければ先頭のシーン、シーンが無ければ親の無いノードを根にします。カメラとライトのデータは読まず、警告も出しません。

新しいモデルの形状の転送が済むと表示が切り替わります。新しいモデルを開けなかった場合は、元のモデルで作業を続けられます。

## 理由を出して開かないもの

| 条件 | 表示 |
|---|---|
| 先頭が glTF でない | GLBではありません |
| 必須拡張 `KHR_draco_mesh_compression` または `EXT_meshopt_compression` | 形状の圧縮は未対応。任意拡張で代替のアクセサがあればそれを読み、無ければ破損として扱う |
| 必須拡張 `KHR_mesh_quantization` | 必須拡張 {名前} は未対応です（量子化された頂点形式は未対応） |
| 必須拡張 `EXT_mesh_gpu_instancing` | 必須拡張 {名前} は未対応です（拡張によるインスタンス配置は未対応） |
| 上以外の未知の必須拡張 | 必須拡張 {名前} は未対応です（未知の必須拡張） |
| バッファに uri がある | 外部バッファは未対応です |
| BIN が無いのにバッファを参照する | BINチャンクがありません |
| 範囲、型、個数、ノード参照、範囲外のインデックス、非数の位置など | データが破損しています（{箇所}） |
| sparse アクセサ | 未対応の形式です（sparse アクセサ） |
| 親が2つ、循環、シーンの根が不正 | ノード階層が不正です: {詳細} |
| 描けるメッシュが無い | 表示できる形状がありません |
| 頂点やインスタンスが u32 を超える | 大きすぎます（{何が}） |

必須でも受け入れて簡略表示にする拡張は `KHR_materials_unlit`、`KHR_materials_emissive_strength`、`KHR_materials_ior`、`KHR_materials_transmission`、`KHR_lights_punctual` です。`KHR_texture_transform` は基本色の画像に反映します。KTX2（`KHR_texture_basisu`）と WebP（`EXT_texture_webp`）が必須でも形状は開き、通常の `source` に対応する代替画像があればそれを使います。

## 基本色の画像が見える条件

BIN に埋め込まれた PNG と JPEG を表示します。条件は3つです。材質の `baseColorTexture` が指す画像が `bufferView` を持ち `uri` を持たないこと、`mimeType` が `image/png` か `image/jpeg` で、先頭のバイトも PNG か JPEG であること、形状に指定の UV（画像のどこを各頂点に合わせるかを示す座標）があることです。`texCoord` が選ぶ `TEXCOORD_n`、サンプラの繰り返し・補間、`KHR_texture_transform` の拡大・回転・ずらしと UV 番号に対応します。

形状を先に描き、画像が届くと「面」「面と線」の面に画像の色と基本色（`baseColorFactor`）を掛けて描きます。MASK 材質は、透明度の積がしきい値（既定 0.5）より小さい画素を抜きます。画像が無いとき（外した、読めない、表示を切った）も、基本色の透明度がしきい値より小さければその面を描きません。「線」「透かし」や、上端の「画像」を切ったときは画像を省きます。表示の切り替え（Shift+T）は編集や書き出しに影響しません。

読み込み中は状態欄に「テクスチャ 完了数/総数」が出ます。表示用の長辺は最大 4096 画素（装置の上限が小さければその値）、縮小版を含む合計の既定は 512 MiB です。大きい画像から縮め、収まらなければ省きます。`--texture-budget-mib N` で容量を指定でき、`--no-textures` で起動すると画像を復号せず、貼り付けもできません。

## 開いて簡略表示にするもの

状態欄に「簡略表示 N 件」と出ます。押すと一覧が開きます。

| 内容 | 表示 |
|---|---|
| 法線、金属らしさ・粗さ、遮蔽、発光の画像 | 基本色以外の画像として件数を表示 |
| 外部ファイル・データ URI、未対応の画像形式、指定の UV が無い・使えない | 該当する面は基本色で描き、件数と理由を表示 |
| 画像の破損、長辺が 8192 画素超、または画素数が 8192 × 4096 超 | 該当する画像を省いて理由を表示。GLB 自体の参照や BIN の範囲が壊れている場合はファイルを開けない |
| 頂点色／アルファ合成 | 頂点色を省き、BLEND は不透明な面として表示 |
| アニメーション・スキン・モーフ | 種類ごとの件数を示し、静止した姿で表示 |
| 法線が無い、または法線が壊れている | 法線の無い形状 N 件は、面ごとの法線で表示します |
| 線と点 | 線 N 個、点 N 個を省略しました |
| 簡略表示の対象の拡張 | 拡張 {名前} は見た目だけを簡略化して表示します |
| 知らない任意拡張 | 未対応の任意拡張 {名前} は無視します |

## 書き出し

「書き出し」は、開いたGLBを土台にして、変えた所だけを直した新しいGLBを書きます。元のファイルは書き換えません。

- **保つもの**: テクスチャ、材質、アニメーション、スキン、モーフ、カメラ、知らない拡張、`extras`、元のBINのバイト列。既存の要素の番号は1つも変えず、足す物は配列とBINの末尾に付けます。JSONは値として保ちます。項目の並びと数の書き方（`1.0` と `1.0e0` など）は変わることがあります。
- **変えるもの**: 動かした部品の変形（位置・回転・大きさの3項目。傾いた拡大は `matrix`）、子の並びが変わった親の `children`、根が変わったときのシーンの `nodes`、`buffers[0].byteLength`。
- 複製は元のノードの名前・子・変形を差し替え、元と同じ色と画像の貼り方ならメッシュも共有します。足した図形にはメッシュ・アクセサ・バッファビューと、基本色や貼った画像を持つ材質を足します。

**削除した部品は、シーンから外すだけです。ノードと形状のデータはファイルに残ります。** 番号を詰めると、本アプリが中身を知らない拡張が指す番号を直せないためです。受け取った人がデータを取り出せるので、見せたくない形を消したいときは別のソフトで取り除いてください。書き出しの結果に、外した部品の数を必ず出します。

結果の一覧には、ほかに次を出します。アニメーションの対象になっている部品を動かした数（再生するソフトではアニメーションの値が優先されます）、スキンの付いた部品を動かした数（glTF の決まりで表示に使われません）、`matrix` で書いた部品の数、シーンが無いファイルにシーンを足したこと。

書き出さないとき（理由を出し、保存先には何も残しません）:

- 画像の貼り付けが終わっていない（レビュー保存も同じく断ります）。
- 保存先が開いたモデルや貼った画像と同じ。改名・移動・複製の後も元の内容で見分け、レビュー保存でも保護します。その起動で書き出した GLB には再び書き出せます。
- 元のファイルが開いたときから変わっている、または見つからない。
- 全体が4GiBを超える。
- 書いた結果を読み直した照合（元の BIN と未編集の項目、部品の数・名前・位置・基本色・三角形の数、画像のハッシュと貼り方）に通らない。

書き出した後は、作業の対象が新しいファイルに移ります。レビューは新しいファイルに結び付いて保存されます。取り消しで書き出した時点まで戻ると「形の編集 未書き出し」の印が消えます。

## 部品の色を変えて書き出す

右の「色」で見本を選ぶか、16進・RGB の値を入力すると、選んだ部品と子孫に色が付きます。Enter か欄を離れて確定し、「戻す」で取り消せます。複数の色がある選択では色の数が出ます。空の RGB 欄は3つの値がそろうと確定します。

見本と数値欄には書き出す基本色を sRGB で表示します。3Dビューでは照明が掛かり、選択中の部品は少し明るく見えます。GLB には RGB をリニア値で書き、各面の透明度を保ちます。

ファイルにある部品やその複製の色を変えると、元の材質とメッシュの写しを追加し、色を変えた部品から参照します。同じ色の写しは共有します。元の材質やメッシュは使われなくなっても残ります。色の変更で頂点やインデックスのデータは増えません。

写した材質は元の画像の参照、金属らしさ、粗さ、拡張を引き継ぎます。選んだ範囲に画像が表示されているときは「色」に案内が出ます。たとえば木目の板に赤を指定すると、赤みを帯びた木目になります。

## 画像を貼って書き出す

「画像を貼る…」か PNG・JPEG のドロップで選んだ部品と子孫に貼ります。画像かどうかは先頭のバイトで決め、フォルダなど通常のファイルでないものは読まずに断ります。基本色の RGB は白になり、透明度と MASK のしきい値を保ちます。「画像を外す」は今の色を保ち、書き出す材質から元の外部画像への参照も外します。貼り付け・取り外し・大きさの変更はそれぞれ「戻す」で取り消せます。レビューを読み直して編集を破棄すると、画像の貼り方もそのレビューに対応する GLB の状態に戻ります。[画面での手順](guide/12-texture.md)

- **モデルの UV** を使う面は、取り込んだ UV・サンプラ・座標の変換を保って基本色の画像を差し替えます。**箱形の投影**は読み込んだ貼り方がない面（図形や STL など）に使います。面の向きに近い軸から平らに貼り、画像の縦横比を保って繰り返します。「1枚の大きさ」は画像の長い辺の長さで、初期値は選んだ範囲の外形の最長辺です。どの面でも部品の外形の中心が画像の中心になります。貼り替えても大きさは保ち、縦横比を新しい画像に合わせます。スキン・モーフ付きの部品で箱形が必要なら貼り付けを断ります。
- 貼るファイルは1枚 64 MiB、文書に保持する貼り付け画像は圧縮状態で合計 256 MiB までです。撮影情報（EXIF・XMP）や文字の注釈を除き、元の画素の並びを保って GLB に埋め込みます。画像のファイル名・場所は記録しません。同じ内容の画像は元の GLB の埋め込み分も含めて共有します。画像を外しても元の画像と材質はファイルに残ります。**貼って書き出した画像は、外してから書き出し直してもファイルの中に残り、受け取った人が取り出せます**。同じ GLB のレビューを復元した後も、どの部品にも使っていない貼り付け画像の枚数を結果に出します。渡したくない画像があるときは、貼る前のモデルから作り直してください。
- 箱形で貼った面は、位置・法線（あれば）・UV・頂点の番号を持つ形状として追加します。三角形の数と位置は同じです。元の UV の組は同じ番号で写します。複製・追加図形・STL も、箱形の大きさを変えて書き出すたびに同じ番号を箱形の UV に使います。頂点色・接線・面ごとの拡張は写しません。書き出した後に取り消して書き出すと、開いた時点の形状と材質の参照に戻ります。材質切り替え拡張（`KHR_materials_variants`）付きのモデルや他のソフトでの見え方は未確認です。開き直すと「モデルの UV」になり、「1枚の大きさ」の欄は出ません。
- 書き出し結果に、画像を変えた部品数、足した画像の枚数とバイト数、箱形から UV に変換した形状数が出ます。既存の材質の追加情報と競合して箱形の大きさを記録できない場合は、次回も形状を作り直す旨を表示します。

## 新規の文書から書き出した GLB

［新規作成］（Cmd+N）で始めた文書には、元のファイルがありません。書き出しは、ノードもメッシュも無い最小の GLB（「空の土台」。`asset.generator` が `model-reviewer`、`asset.version` が `2.0`、根の無いシーン1つ）を元のファイルの代わりにして、上と同じ組み立て・書き込み・照合を通します。

- 置いた図形と貼った画像は通常の GLB と同じ方法で書きます。同じ文書からは同じバイト列になり、利用者のパスや名前は入りません。
- 部品が1つも無い文書は書き出しません（「書き出す部品がありません。図形を置いてから書き出してください」）。メッシュの無い GLB は、このアプリでも開けないためです。
- 保存先の既定の名前は「無題.glb」です。書き出すと作業の対象がそのファイルへ移り、以後はファイルを開いたときと同じに扱います。
- 書き出すまで、レビューは保存できません（レビューはモデルのファイルの大きさとハッシュで相手を確かめるため）。注釈と視点は置けて、書き出した後に保存できます。
