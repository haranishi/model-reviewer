# UX設計（ユーザーストーリーとUX5階層）

実装の前に書いた。戦略から順に決め、下の階層の判断は上から導いている。第1段階の [ux.md](../model-reviewer/ux.md) はそのまま有効で、ここには足す分だけを書く。

## 誰のためか
- **使う人**: 受け取ったモデルを確かめるだけでなく、「ここをこう動かしたい」を形で示したい人。指摘を言葉で書く代わりに、部品を動かし、仮の形を置いて返す。制作ソフトの操作は少し知っているが、常用はしていない。
- **救う相手**: 編集されたGLBを受け取る制作者。テクスチャやアニメーションが抜けたファイルが届くと、作り直しになる。元の中身が残ったまま、変えた所だけが変わっていてほしい。

## ユーザーストーリー
| # | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| E1 | 上下・前後と大きさの見当を付けたい。床も軸も無いと、傾きに気づけない | 格子と軸が出る。格子の間隔が状態欄に出る。立方体で前・上・右へ1回で切り替わる |
| E2 | 真横・真上から、遠近のゆがみ無しで位置を合わせたい | 平行投影に切り替えても、見かけの大きさが変わらない |
| E3 | 部品を掴んで動かしたい。トラックパッドしか無い | 1本指のドラッグで、ハンドルを掴めば変形、外せば視点の回転になる。道具を替えなくても視点を回せる |
| E4 | 「右へ12.5」のように、決まった量だけ動かしたい | 右のパネルに数値を打って Enter で確定する |
| E5 | 試して、違ったら戻したい | Cmd+Z で1回分ずつ戻る。注釈や表示の切り替えも同じように戻る |
| E6 | 仮の形を置いて「ここにこういう物が要る」と示したい | 図形を1回押すと見えている場所に出て、すぐ動かせる |
| E7 | 編集した結果を渡したい。相手のファイルを壊したくない | 書き出しは必ず別のファイルになる。元の中身は残る。何が変わったかが一覧で分かる |
| E8 | 途中でやめても、何を失うかを知っておきたい | 形の編集とレビューの未保存が別々に出る。閉じる前に、失うものが名前で出る |
| E9 | 2点の間の長さを知りたい | 2回クリックで距離が出る。単位の前提が画面に出ている |

## 1. 戦略
- 目的は「指摘を、動かした形で渡せるようにする」。第1段階の「見て、指して、残す」に「動かして、渡す」を足す。作り込む道具にはまだしない。
- 大事にする順番は、①利用者のファイルと作業を失わない・壊さない、②いま何をしているか、何が変わったかが分かる、③トラックパッドだけで迷わず動かせる、④待たせない。
- 第1段階のレビューの流れを悪くしない。編集を使わない人には、画面が複雑になっただけに見えてはいけない。

## 2. 要件（戦略から導いたもの）
- ①から: 開いたファイルへは書き出せない。取り消しは未保存の印が付く操作すべてに効く。未保存は2種類を分けて見せる。書き出しは元の中身を保ち、結果の注意を一覧で出す。
- ②から: 道具・投影・表示は、いまの状態が常に見える形で置く。変形中は変化量を数値で出す。数値を換算しない（単位は前提として示すだけ）。
- ③から: どの道具でもドラッグは視点の回転。ハンドルは部品の見える場所に出す。押せる範囲を広く取る。
- ④から: 変形中はGPUへデータを送り直さない。何もしない間は描かない。

## 3. 構造
- 画面は1枚のまま。道具は1つだけ選ばれる（選択・移動・回転・拡大・図形・計測・注釈追加）。注釈追加は第1段階のボタンと N キーを残し、道具の1つとして扱う。
- **どの道具でも、ハンドル以外から始めたドラッグは視点の回転**にする。クリックだけが道具ごとの意味を持つ。視点を変えるために道具を抜ける必要が無い。
- 選択は1つ（部品1つと子孫）のまま。変形・複製・削除・数値入力は、すべてこの選択に対して働く。
- 「保存」はレビュー、「書き出し」はGLB。書き出すと作業の対象が新しいファイルへ移り、レビューもそれに付いていく。
- 判断が要る知らせ（未保存の確認、書き出しの結果、失敗）は中央のダイアログ、要らない知らせ（確定した操作、道具の使い方）は状態欄。

## 4. 骨格
```
┌ [開く] │ [レビュー保存][レビュー読込] │ [書き出し] │ [戻す][やり直す] │ [全体表示][選択を表示][初期視点] │ [注釈を追加] │ [?] ┐
├───────────────────┬──────────────────────────────────────────────────┬───────────────┤
│ 注釈（3）       ◀ │┌──┐              [面|面と線|線|透かし] [透視|平行] [格子] ┌────┐│ ▶ 部品        │
│ 1 arm 端が欠け…   ││選│                                                  │ 上 ││ ◉ ▾ assembly  │
│ 2 base 厚みが…    ││移│                                                  │前 右││ ◉   ▸ axle    │
│                   ││回│        3Dビュー（床の格子と軸）                   └────┘│ ⊘   base      │
│ ───────────────── ││拡│              ハンドル ─┼─  ＋12.50                     │ ───────────── │
│ 視点              ││図│[立方体][球][円柱][平面] ← 図形の道具のときだけ          │ 変形          │
│ 名前 [      ][保存]││計│                                                       │ 位置   X Y Z  │
│                   │└──┘                                                       │ 回転・大きさ  │
├───────────────────┴──────────────────────────────────────────────────┴───────────────┤
│ a.glb ●形の編集 未書き出し ●レビュー未保存 │ 移動: 矢印をドラッグ │ arm │ 1単位=m │ 格子 0.1 │ 部品 14 │ [詳細▴] │
└────────────────────────────────────────────────────────────────────────────────────┘
```
- 道具の列は3Dビューの中の左端に置く。部品の一覧は 依頼で選んだ画面の案のとおり右へ移し、その下に「変形」を置く（一覧と数値が並ぶ、制作ソフトに近い形）。注釈と視点は左のパネルへ移す。パネルの開閉と部品の名前（自動操作の指し方）は変えない。
- 「変形」は右の部品一覧の下に置き、部品を選んでいるときだけ中身を出す。選んでいなければ「部品を選ぶと数値が出ます」の1行にする。
- 表示・投影・格子は、3Dビューの上端に**並べたボタン**で置く（開くメニューにしない）。いまの状態が見え、1回で切り替わる。図形の4つも、道具の横に並べる。
- 立方体は72ポイント。面のどこを押しても反応する。ハンドルは画面上で約90ポイント、当たりの幅は線から12ポイント。
- 変形中の変化量は、ハンドルの脇と状態欄の両方に出す。
- 書き出しの結果は「書き出しました」と注意の一覧を1つのダイアログで出す。注意が無ければ状態欄だけにする。

## 操作表（第1段階の表に足す分。ヘルプにも同じ表を出す）
| したいこと | マウス・トラックパッド | キー |
|---|---|---|
| 道具を選ぶ | 左端の列を押す | V 選択／G 移動／R 回転／S 拡大／M 計測／N 注釈 |
| 動かす・回す・拡大する | ハンドルを押してドラッグ。離すと確定 | ドラッグ中の Esc で取り消し |
| 数値で指定する | 右の「変形」の欄を押して入力、または欄を左右にドラッグ | Enter で確定、Esc で戻す |
| 取り消し／やり直し | 上部のボタン | Cmd+Z ／ Shift+Cmd+Z |
| 図形を足す | 「図形」→ 形を押す | |
| 複製／削除 | | Cmd+D ／ Delete（Backspace） |
| 前・右・上から見る | 立方体の面を押す（後・左・下も） | 1 ／ 3 ／ 7 |
| 透視と平行を切り替える | 上端のボタン | 5 |
| 面と線を切り替える／透かし | 上端のボタン | Z ／ Shift+Z |
| 距離を測る | 「計測」→ 表面を2回クリック | M、Esc で終了 |
テンキーは使わない（数字は文字キーの段）。1文字のキーは、入力欄に文字を打っている間とダイアログの表示中は働かない。Windows と Linux では Cmd の代わりに Ctrl。

## 5. 表層
配色と文字は第1段階のまま。足す色は軸だけで、X #E0655F・Y #7CC36A・Z #5B8DEF。軸は必ず X・Y・Z の文字を添え、色だけで見分けさせない。選ばれている道具とボタンは、琥珀の帯と太字で示す。押せないボタンは薄くし、触れると理由が出る。記号（道具の絵、立方体、矢印）は図形として描き、フォントの絵文字に頼らない。

## この5階層を通したことで変わった実装: 10個
依頼をそのまま実装した場合からの変更点。
1. **どの道具でもドラッグは視点の回転**（構造）。道具ごとにドラッグの意味を変える案をやめ、ハンドルから始めたドラッグだけを変形にした。
2. **ハンドルは部品の原点ではなく、見えている範囲の中心に出す**（E3）。原点が遠くにあるモデルで、ハンドルが画面の外に出るのを防ぐ。
3. **取り消しの対象を「未保存の印が付く操作すべて」にした**（戦略①）。変形だけでなく、注釈・表示・視点も履歴に入る。
4. **未保存の印を2つに分け、確認のダイアログで失うものを名前で挙げる**（E8）。
5. **書き出すと作業の対象が新しいファイルへ移る**（戦略①）。レビューが編集後のファイルに付いていく。開いたファイルは書き出し先にできない。
6. **書き出しの結果に注意の一覧を出す**（戦略②）。削除した部品のデータが残ること、アニメーションが関わる部品を変えたことを隠さない。
7. **表示・投影・図形を、開くメニューではなく並べたボタンにした**（骨格）。状態が見え、出たばかりの小窓の位置が定まらない問題も避けられる。
8. **単位は換算せず、前提として表示するだけにした**（戦略②）。数値がファイルの値と食い違わない。
9. **道具の列を3Dビューの中に置き、注釈と視点を左のパネルへ移した**（戦略の3点目、②）。部品の一覧と変形は右で、左が「指摘」、右が「モデル」と分かれる。
10. **追加した図形は注視点に出し、選択して移動の道具へ切り替える**（E6）。大きさはモデルに合わせる。置いた物を探させない。
