# 読み込みの流れ・未対応の検出・エラー

## 流れ
```
[UIスレッド] OpenModel(path) ─ 世代番号を+1 ─▶ [読み込みスレッド（1回の読み込みに1本）]
                                                 ① 読み取り  std::fs::read
                                                 ② 識別      ModelIdentity::from_bytes（blake3）
                                                 ③ 解析      load_glb：容器 → JSON → 未対応の検出 → 検証 → 形状とノードの組み立て
   ◀── LoadEvent { generation, Stage / Loaded / Failed } ── 送るたびに ctx.request_repaint()
[UIスレッド] 世代が今と違えば捨てる。Loaded なら begin_upload → 毎フレーム continue_upload（予算つき）
            → 転送完了 → インスタンス設定・初期視点・最初の描画   ここで前のモデルを置き換える
[読み込みスレッド] ④ PickIndex::build（表示とは並行）──▶ LoadEvent { generation, PickReady }
```
- **UIを止めない**（要件2.4・2.5）。読み取り・ハッシュ・解析・当たり判定の索引づくりは別スレッドで行う。UIスレッドがするのは、予算つきのGPU転送と、イベントの受け取りだけである。
- **古い結果を捨てる**（要件2.6）。`LoadEvent` は必ず世代番号を持ち、`Session` は自分の世代と一致するものだけを受け取る。古いスレッドには共有フラグ（`AtomicBool`）で中止を伝え、工程の合間に確かめて早く終わらせる。途中で止められないのは `fs::read` と `load_glb` の内部で、その結果は世代の比較で捨てる。
- **置き換えは成功してから**（要件2.7）。新しいモデルの転送が終わるまで、前のモデルとレビュー状態は表示したままにする。失敗したら何も失わない。代償として、切り替えの間は2つ分のメモリを持つ。
- **表示を先に、索引は後で。** 当たり判定の索引は表示に要らないので、モデルを渡した後に作って別のイベントで届ける。届くまでの3Dクリックは選択せず、「選択の準備中です」と状態欄に出す。
- **パニックを外へ出さない。** スレッドの本体を `catch_unwind` で包み、パニックは `LoadError::Internal` に変える。そのため release でも `panic = "unwind"` のままにする（`abort` にしない）。
- 進捗の表示は工程名だけ（読み取り中／解析中）。割合を出すのはGPU転送のバイト数だけにする（要件2.8）。
- 古い読み込みが後から届く場合を試せるように、各工程の前に呼ぶ試験用の関数を差し込めるようにする。当たり判定の索引は `PickIndex::build_cancellable` で作り、新しい読み込みが始まったら止める。
- ドロップされたのが `.json` ならレビューの読み込みとして扱う。複数ドロップは最初の1つだけ使い、その旨を伝える。拡張子は目安で、判定は先頭の `glTF` の4バイトで行う。

## load_glb の手順と、未対応の検出
`gltf::Gltf::from_slice` は使わない。理由は2つある。①検証つきの読み込みは、gltfクレートが知らない必須拡張を「Unsupported extension」という一律のエラーにするので、利用者に拡張名と理由を伝えられない。②BINチャンクを丸ごと複製する。代わりに次の順で読む。
1. `gltf::binary::Glb::from_slice(bytes)` で容器を借用のまま分ける。
2. `gltf::json::deserialize::from_slice(&glb.json)` でJSONを読む。
3. **自前の検査**（下の表）。ここで必須拡張と外部参照をはじく。
4. `gltf::Document::from_json(root)` で gltf クレートの検証を通す。
5. アクセサの範囲の検査 → ノードの検査 → 形状の読み取り（`primitive.reader(|_| Some(bin))`）。

| 検出するもの | 扱い | 利用者への表示 |
|---|---|---|
| 必須拡張 `KHR_draco_mesh_compression`・`EXT_meshopt_compression` | エラー | 形状が圧縮されているため未対応 |
| 必須拡張 `KHR_mesh_quantization` | エラー | 量子化された頂点形式は未対応 |
| 必須拡張 `EXT_mesh_gpu_instancing` | エラー | 拡張によるインスタンス配置は未対応 |
| 必須拡張で、下の許可リストに無いもの | エラー | 拡張名と「未知の必須拡張」 |
| バッファに `uri` がある（data: も含む） | エラー | 自己完結したGLBだけに対応 |
| BINチャンクが無いのにバッファを参照 | エラー | 形状データがありません |
| アクセサやバッファビューがBINの範囲を超える、型や個数が合わない | エラー | データが破損しています（どこか） |
| sparse アクセサ | エラー | 未対応の形式です（sparse アクセサ） |
| インデックスが頂点数以上、位置が非数・無限大 | エラー | 同上 |
| ノードが2つの親を持つ、循環している | エラー | ノード階層が不正です |
| 描けるメッシュが1つも無い | エラー | 表示できる形状がありません |
| 頂点数・インスタンス数が `u32` を超える | エラー | 大きすぎます（何が） |
| テクスチャ、頂点色、アルファ合成の指定 | 警告 | 色は baseColorFactor だけで表示 |
| アニメーション、スキン、モーフ | 警告 | 再生せず、静止した姿で表示 |
| 線・点のプリミティブ | 警告（その分は描かない） | 線・点 N 個を省略 |
| 法線の無いプリミティブ | 警告 | 面ごとの法線で表示 |
| 任意拡張（必須でない）で知らないもの | 警告 | 拡張名を列挙 |

- **必須でも受け入れる拡張（見た目だけに関わるもの）**: `KHR_materials_unlit`・`KHR_materials_emissive_strength`・`KHR_materials_ior`・`KHR_materials_transmission`・`KHR_texture_transform`・`KHR_lights_punctual`。gltf クレートの同名の機能を有効にして検証を通し、警告を出す。形は正しく、見た目が簡略化されるだけだからである。
- Draco などが**任意**で使われている場合、仕様上は非圧縮の代替データが入っている。代替のアクセサが実在すれば読み、無ければ破損として扱う。
- 三角形ストリップと三角形ファンは、三角形リストへ直して読む。
- **形状の共有は、アクセサの組（位置・法線・インデックス・種類）で判定する。** メッシュ番号で判定すると、材質だけが違うメッシュの形状を二重に持つことになる。同じ組は `Primitive` 1個にまとめ、色は `Draw` 側に持たせる。
- シーンは既定のシーン、無ければ先頭を使う。シーンが1つも無ければ、親を持たないノードを根にする。カメラとライトは黙って無視する。
- ノードの走査は**再帰を使わない**。深い階層で関数の呼び出しが積み上がり、スタックを使い切るとプロセスごと落ちる。訪問済みの印で循環と多重の親を見つける。
- 行列指定のノードはそのまま、TRS指定は `Affine3A::from_scale_rotation_translation` で合成する。ワールド変換は親から順に掛ける（行きがけ順なので、親は必ず先に確定している）。
- 入力の大きさは信用しない。個数は掛け算の前に範囲を確かめ、確保するサイズはBINの長さから導ける上限で抑える。

## 法線が無い入力
glTFの仕様は、法線が無ければ面ごとの法線で描くよう求めている。頂点を三角形ごとに複製すれば実現できるが、頂点が最大で数倍になる。本アプリは頂点を共有したまま、描画時に微分で面法線を作る（[design-render.md](design-render.md)）。`Primitive::has_normals = false` と警告で、利用者にも分かるようにする。法線の長さが0や非数のものは、その頂点だけでなくプリミティブ全体を「法線なし」として扱う。部分的に壊れた陰影を見せないためである。

## エラーの扱い
- エラーは3つの型に分ける。`LoadError`（読めない）、`RenderError`（GPUの都合）、`ReviewError`（レビューJSON）。どれも日本語の文へ変換する関数を持ち、UIはそれを表示するだけにする。
- 表示の場所は2つ。一時的な知らせ（外れたクリック、保存した、など）は下部の状態欄に出す。利用者の判断が要るもの（読み込み失敗、モデル不一致、未保存の確認）は中央のダイアログに出す。
- 読み込みの警告（簡略化の一覧）は、状態欄に「簡略表示 N 件」と出し、押すと一覧が開く。開いた直後に黙って消えないようにする。
- どのエラーでもアプリは動き続け、直前の状態を保つ。ログ（標準エラー出力）には英語の技術的な詳細も残す。
- ファイルの中身や利用者のパスを、ネットワークへ送る処理は存在しない（依存にネットワークのクレートを入れない）。
