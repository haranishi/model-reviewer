# テストと性能

第1・第2段階の方針（論理はGPUなしで試す、GPUの試験は `#[ignore]`、実機の確認はOSの入力を使わない自動操作）を保つ。検証コマンドも同じ4つである（`cargo fmt --all --check`、`cargo test --workspace`、`cargo clippy --all-targets --workspace -- -D warnings`、`cargo build --release`）。GPUのある環境では `cargo test --workspace -- --include-ignored` も通す。

## 3つのOSで同じ結果にするための決まり（要件13.2）
- 換算・角度・投影を通った値は、**許容差つき**で比べる（相対 1e-5、0付近は絶対 1e-6）。`assert_eq!` で比べてよいのは、計算を通らない値（読んだ座標のビット、番号、個数、種類、文字列の定型）だけである。第2段階で、回転の角度の丸めが原因で Linux と Windows の試験だけが落ちた。
- しきい値（辺の角度10°、吸着の半径、寸法の上下限、球と円柱のそろい方 1e-4）の試験は、しきい値から十分に離れた入力で行う（角度なら 0°・45°・90°、半径なら半分と2倍）。境目ちょうどの値を試験にしない。
- 表示の文字（`format_length`）の試験は、2進で正確に表せる値（0.5、2.5、1024 など）か、丸めの境目から離れた値を使う。
- パスは相対だけを使い、区切りを文字列で組み立てない（`Path::join`）。一時ファイルは `std::env::temp_dir()` の下に、試験ごとに違う名前で作る。STL の ASCII の試験データは、`\n` と `\r\n` の両方を生成器で作る（リポジトリの改行の変換に頼らない）。

## どこで何を確かめるか
| 対象 | 置き場所 | 確かめること |
|---|---|---|
| 近くの三角形 | `core/src/bvh.rs` の中 | 球に触れる三角形がすべて返る（総当たりと同じ集合）。上限を超えると `false`。空の形状と有限でない入力で落ちない |
| 切った当たり判定 | `core/tests/pick.rs` | 消す側の面に当たらず、その奥の残った面に当たる。平面をまたぐ三角形の、残す側の点に当たる。全部が消す側なら当たりなし。`clip = None` は既存の `pick` と同じ結果。透視と平行 |
| 断面の計算 | `core/src/section.rs` の中 | `cuts` と `ray_range` がつじつまが合う（範囲の中の点は `cuts` が偽）。`clamped`、`frame_corners`（4点が平面の上）、`drag_offset`（軸に沿って動かした量が返る、視線が軸と平行なら `None`）、`code` |
| 吸着 | `core/tests/snap.rs`（新規） | 立方体の角の近くで頂点、辺の近くで辺、面の中央で面。**平らな面の対角線には付かない**。縁（平面の図形の外周）は辺。輪郭のすぐ外から頂点に付く。吸着を切ると面。断面で消えた頂点に付かない。部品に拡大・回転があっても、返る `local` が頂点の座標と一致する。頂点を共有しない形状（STL 相当）でも同じ |
| 計測 | `core/src/measure.rs` の中 | `push_with` で種類が残る。`delta` の符号。部品を動かすと差が変わる |
| 単位 | `core/src/units.rs` の中 | `source == shown` で値が1ビットも変わらない。mm 表示で 0.0254 → 25.4（許容差）。往復（`from_display(to_display(x))`）。`next_display` の順。`format_length(.., 4)` が既存の `format_distance` と同じ文字 |
| 寸法 | `core/src/shapes.rs` の中、`core/tests/doc.rs` | `dims_of(scale_for(d)) ≈ d`。球と円柱の不ぞろいで `None`。範囲外と有限でない値で `None`。`add_shape_primitive` の記録が複製でも読め、読み込んだ形状では `None` |
| STL の読み込み | `stl/tests/parse.rs` | バイナリと ASCII が同じ `Model`（頂点の数、三角形の数、境界箱）。立方体は頂点8・三角形12。`solid` で始まるバイナリ。複数の `solid`。`\r\n`。部品の `local` が単位の倍率。同じ入力から同じ結果 |
| 壊れた STL | `stl/tests/malformed.rs` | 要件6.1 の各場合が、決まった `StlError` になり、落ちない。三角形の数に `u32::MAX` を書いた84バイトの入力で、確保が起きずに `CountMismatch`。空・1バイト・83バイト。ランダムなバイト列（決まった種）1万通りで落ちない |
| 土台の合成 | `gltf/tests/export.rs` | `load_glb(synthesize_base(m))` の約束（design-stl-units.md）。同じ入力から同じバイト列。合成した土台に、動かす・図形を足す、を重ねた書き出しが照合に通る |
| レビュー | `core/tests/review_roundtrip.rs` | `stl_unit` の往復。無ければ `None`。知らない値は読まない。GLB のレビューが今までと同じバイト列 |
| 描画 | `render/tests/gpu.rs`（`#[ignore]`） | 断面で、消す側の中心の画素が背景になり、残す側は変わらない。反転で入れ替わる。裏の面が切り口の色。鏡写しの部品でも表が切り口の色にならない。線・透かし・選択の輪郭でも切れる。位置を変えたフレームで送るのが定数だけ。何もしないフレームで描かない。断面なしの絵が今までと同じ |
| 画面の部品 | `app/tests/{section_bar,section_view,dims,measure_panel}.rs`、既存の `measure_view`・`toolrail`・`viewbar`（`egui_kittest`） | 入力用の構造体だけで動く。押すと期待した `Command` が積まれる。押せない状態で理由が出る。日本語の文言で落ちない。幅960で状態欄が重ならない（`layout.rs` に足す） |
| つながり | `app/tests/{snap,section,stl,dims,units}.rs`（新規）、既存の `measure`・`export`・`persist`・`open`・`malformed` | `Command` の列で、吸着した計測、X と C、断面の中の選択、STL を開く→注釈→レビュー保存→開き直して復元、STL→図形→寸法→書き出し→作業の対象が GLB、単位を替えても文書が変わらない、寸法の確定が取り消せる |

## 実機の自動操作（進行役が実行する）
足す手順は `hover_view`（3Dビューの中の位置へポインタを動かす。押さない）1つ。`open_model` に、省略できる `stl_unit` を足す。入力の注入は、既存の仕組み（前の分を画面が受け取ってから次を入れる、隠れている間は描画を要求する）を通す。`dump_state` に足す項目: `measure.kinds`・`measure.delta`、`snap`（入・切、候補の種類）、`section`（軸・位置・反転、または `null`）、`units`（前提・表示・STL の仮定）、`source_kind`、`selection.dims`。既存の項目の意味と数値は変えない。
| 手順 | 内容 |
|---|---|
| `inspect-1.json` | 見本の GLB を開く → 計測 → 角の近くを2回クリック → 2点とも頂点で、距離が期待値 → X で吸着を切って同じ所を押すと面 → C で断面 → 軸 Y → 位置を入力 → 反転 → 消えた側をクリックして選択が奥の部品になる → 表示を mm → 画像 |
| `stl-1.json` | 見本の STL（20×30×40 mm の箱）を開く → 状態欄が「STL = mm（仮定）」 → 角から角を計測して 20 mm → 注釈 → 円柱を足して寸法を入力 → 書き出し → レビュー保存 → 状態を書き出す |
| `stl-2.json` | 起動し直して、書き出した GLB とレビューを開く → `stl-1` の最後の状態と一致。STL のハッシュが変わっていない |
| `heavy-inspect.json` | 下の性能の測定 |
既存の9本（`smoke`〜`heavy-edit`）は、**手順を変えずに**通ること。特に `measure-1` は、既定で吸着が入った後も通るかを最初に確かめる。クリックの位置が角や辺の近くで結果が変わるなら、手順の先頭に吸着を切る1行を足し、変えたことを検証の記録に書く。

## 性能：測るものと目標
**下の目標は設計上の狙いであり、測った値ではない。** 測った結果は検証の記録（`verification.md`）に、モデル・機械・条件とともに書く。届かなければ、値を書いたうえで直すか、目標を見直す理由を残す。他のソフトとの比較は書かない。
| 測るもの | 測り方 | 目標 |
|---|---|---|
| 吸着の探索 | `stress-nested 100000 200` で、計測の道具のまま `hover_view` を300回（表面の上を横切る）。新しい性能値「吸着の探索」の平均と最大 | 平均4ミリ秒以内。超えたら間引きが働くこと |
| 吸着中のフレーム | 同じ操作の「フレームのCPU時間」 | 視点を回したときの平均の1.5倍以内 |
| 吸着のメモリ | 探索300回の前後の常駐メモリ | 増え続けない |
| 断面の位置のドラッグ | 同じモデルで矢印を300コマ動かす。送ったバイト数とフレームのCPU時間 | 形状とインスタンスは0バイト。定数だけ |
| 断面つきのクリック | 断面を入れて `click_view`。当たり判定の時間（「吸着の探索」に含めて測る） | 断面なしと同じ桁 |
| STL の読み込み | 生成した 500万三角形のバイナリ（約250MB）と、100万三角形の ASCII。読み取り・識別・解析の時間、読み込み中の常駐メモリの最大、読み込み後の常駐メモリ | 目標は置かない。測って記録する。メモリの最大は design-stl-units.md の見込み（ファイルの2倍弱＋もとの常駐）と比べる |
| 寸法の確定 | 既存の「編集の確定」 | 既存の変形の確定と同じ桁 |
生成は `cargo run --release -p model-reviewer-testdata -- stl-stress <三角形の数> <binary|ascii> target/stress.stl`。リポジトリには置かない。見本は `stl-sample`（箱。バイナリ）で作り、`assets/samples/review-sample.stl` に置く（生成器の出力と同じであることを試験で確かめる）。

## 外部のツールで作った STL での確認（進行役）
- `MR_EXTERNAL_STL_DIR=<フォルダ> cargo test -p model-reviewer-stl --test external -- --ignored --nocapture`。フォルダの `.stl` をすべて読み、落ちないこと、三角形の数が1以上で境界箱が有限であること、バイナリなら三角形の数がファイルの申告と同じことを確かめる。変数が無ければ何もしない。
- 用意するファイル: 別のソフト（例: Blender の STL 書き出し）で、寸法の分かっている箱を、バイナリと ASCII の両方で書き出したもの。外形の表示が元の寸法と合うこと（相対 1e-4 以内）、角から角の計測が合うことを、実機で確かめる。使ったソフトと版を検証の記録に書く。ファイルはリポジトリに置かない。
- 書き出した GLB を別のソフトで開き、大きさがメートルで正しいこと（20 mm の箱が 0.02 m）を確かめる。
