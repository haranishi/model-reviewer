# テスト方針・サンプルGLB・検証の手順

## 考え方
- **GPUも画面も要らないテストを厚くする。** コア・読み込み・レビューJSON・`Session` は純粋なRustで、`cargo test` だけで確かめられる。当たり判定がCPUなので、「開く→選択→非表示→注釈→視点→保存→復元」の流れも、GPUなしで通せる。ネットワークもGPUも無い作業環境の実装者が、自分で合否を確かめられる。
- **GPUが要るテストは `#[ignore = "GPUが必要"]` を付けて分ける。** GPUの無い環境の `cargo test` では「ignored」と数えられ、成功には数えられない（要件12.5）。実機では `cargo test --workspace -- --include-ignored` で全部を流す。
- **人のマウスを動かさない。** 画面の確認は、`egui_kittest`（画面なし）と、アプリ自身の自動操作（[design-app.md](design-app.md)）の2つで行う。OSへ入力を注入する道具は使わない。
- テスト用のGLBは、リポジトリに置いた生成器（`crates/testdata`）がメモリ上に作る。壊れたGLBも同じ生成器から作るので、外部のファイルに頼らない。

## 必須テスト（依頼の8章）と置き場所
| 確かめること | 場所 | 方法 |
|---|---|---|
| ノード階層の変換が正しく合成される | `crates/gltf/tests/hierarchy.rs` | サンプルを読み、各ノードのワールド位置を手計算の期待値と比べる（誤差 1e-5）。行列指定・TRS指定・軸ごとに違う拡大率を含む |
| 変換された部品への当たり判定 | `crates/core/tests/pick.rs` | 回転と拡大のかかった部品へ既知の光線を撃ち、ノード・ローカル座標・距離を確かめる。手前の部品を非表示にすると奥が選ばれること、拡大率の違う2部品で手前が選ばれること、外れると `None` |
| レビューJSONの保存・復元で情報が保たれる | `crates/core/tests/review_roundtrip.rs` | 非表示・注釈・視点を作って `to_json` → `parse` → `restore` し、元と等しいこと。日本語と改行を含む本文 |
| 異なるモデルへの誤った復元を防ぐ | 同上 | 1バイト違うモデルで `ModelMismatch`。存在しないノード番号で `UnknownNode`。新しい版・違う形式・非数を拒む |
| 不正なGLBでアプリ全体が落ちない | `crates/gltf/tests/malformed.rs`、`crates/app/tests/flow.rs` | 下の「壊れた入力」をすべて `load_glb` に通し、パニックせず `Err` になること。アプリに開かせても動き続け、前のモデルが残ること |

## そのほかの主なテスト
- **core**: カメラ（`fit` の後に境界の8隅がすべて画面内、`project` と `screen_ray` が互いに逆、背面は `None`）。表示状態（親を隠すと子孫が実質非表示、親を戻すと子の設定が残っている）。BVH（総当たりの結果と一致。乱数は自前の線形合同法で種を固定）。
- **gltf**: 未対応の検出の表（[design-loading.md](design-loading.md)）を1行ずつ。共有メッシュが `Primitive` 1個になること。統計の数。法線なしの印。
- **壊れた入力**: 先頭4バイト違い、途中で切れた容器、壊れたJSON、BINより長いバッファビュー、頂点数以上のインデックス、非数の座標、循環するノード、2つの親、必須のDraco・meshopt・量子化・未知の拡張、外部URIのバッファ、メッシュなし。加えて、サンプルGLBの**決まった500か所**（種を固定）を1バイトずつ書き換えたものと、長さを切り詰めたもの。結果が `Ok` でも `Err` でもよいが、パニックしてはならない。
- **render（GPU不要）**: `plan_buffers` が小さな上限で `LimitExceeded` を返す、共有メッシュが1回だけ詰められる、インスタンスの並びが `NodeId` 順。
- **render（GPU必要・ignore）**: サンプルを画像へ描き、中心の画素が背景色でないこと。選択ありと無しで画像が変わること。大きさを変えても落ちないこと。何もしないフレームで描画回数が増えないこと。
- **app（画面なし・GPU不要）**: `egui_kittest` の `Harness::builder().build_eframe(..)` で `App` を組み立て、次を通す。ドロップで開く → ビューをドラッグ → クリックで選択 → 「非表示」→ 注釈追加 → 視点保存 → レビュー保存 → **別の `App` を作り直して**レビューを読み込み → 状態が等しい。ほかに、読み込み中に別のファイルを開くと後の方だけが残る、入力欄にフォーカスがある間はショートカットもカメラも働かない、未保存のまま開こうとすると確認が出る。一時ファイルは `env!("CARGO_TARGET_TMPDIR")` の下に置く。
- **app（GPU必要・ignore）**: `.wgpu()` を付けた同じ流れで `harness.render()` の画像を保存し、3Dビューの領域が背景一色でないことを確かめる。
- `egui_kittest` は、描けない文字があると既定でパニックする。テストでは `fonts::install` を呼び、さらに `allow_missing_glyphs()` を付けて、日本語フォントの有無でテストの合否が変わらないようにする。日本語の字形そのものは、実機の画像で確かめる。
- 画像を基準画像と1画素ずつ比べるテストは作らない。GPUやフォントの違いで割れ、直す手間のほうが大きい。

## サンプルGLBの仕様（`assets/samples/review-sample.glb`）
生成器 `crates/testdata` が作る、小さな台車の形。**同じ環境では必ず同じバイト列**ができる（日時や乱数を入れない）。リポジトリに置いたファイルが生成器の出力と同じ内容であること（構造が一致し、数値の差が1e-6以内。OSで `sin`/`cos` の末尾が違いうるため）を、テストで確かめる。これが出どころの証明になる。ライセンスはリポジトリと同じ（MIT OR Apache-2.0）で、`assets/samples/README.md` に生成方法とともに書く。
| ノード | 変換 | 形状と色 | 確かめたいこと |
|---|---|---|---|
| `assembly`（根） | Y軸まわり15°回転 | なし | 親の変換が全体にかかる |
| `base` | 拡大 (2.0, 0.2, 1.2) | 箱、灰青 | 軸ごとに違う拡大率と法線 |
| `axle_front`・`axle_rear` | 平行移動 ±0.7 | なし（まとめ役） | メッシュの無いノード |
| `wheel_FL`・`FR`・`RL`・`RR` | 車軸から平行移動 (0, -0.25, ±0.68)＋X軸まわり90°回転 | **同じ円柱**（半径 0.32、半分の厚み 0.06）を4つが共有、濃い灰 | 形状の共有 |
| `arm` | 平行移動 (0.05, 0.501, 0)＋Z軸まわり30°＋拡大 (1, 2, 1) | 半分の長さ (0.09, 0.2, 0.09) の箱、橙。台とは別アクセサ | 親子で重なる回転と拡大 |
| `arm_tip`（`arm` の子） | 平行移動 (0, 0.2525, 0) | 黄の箱（半分 (0.13, 0.05, 0.13)）と、四面体を 0.14 倍して (0, 0.0875, 0) 動かした白 | 複数プリミティブ、3段の合成 |
| `lamp` | 一様拡大 0.28・平行移動 (0.75, 0.172, 0.35) の行列 | 四面体、青、**法線なし** | 行列指定、法線の導出 |
| `spare`（`axle_rear` の子） | 平行移動 (0.08, 0.163, 0)、回転なし | 車輪と同じアクセサを指す別のメッシュ（材質だけ緑） | 材質が違っても形状は共有される |
円柱は24分割で、側面も天面も底面も外から見て反時計回り。四面体の頂点順は `[0,2,1, 0,3,2, 0,1,3, 1,2,3]`。車輪は車軸と同じ向きに並び、台は車輪の上、腕は台の上に傾けて立ち、先端は腕の先、ランプは台の上の離れた位置、予備の車輪は回転せず台の上に隙間を空けて置く。台と車輪・予備車輪・ランプ、腕と予備車輪・ランプは、根の回転を除いた組立座標の境界箱で重ならない。根の Y15° のあと軸平行にした world_aabb は、台と車輪、腕と予備車輪で重なる。
- ノード数・メッシュ数・プリミティブ数・三角形数と、各ノードの期待するワールド位置は、生成器の定数として公開し、テストがそれを参照する。
- 性能の確認には、同じ生成器の `stress` を使う（例: 部品10万個・各200三角形）。出力は `target/` の下に置き、リポジトリには入れない。

## 検証の手順
作業パッケージごとに、実装者が次の4つを通す。
```
export PATH="$HOME/.cargo/bin:$PATH"
cargo fmt --check && cargo test --workspace && cargo clippy --all-targets --workspace && cargo build --release
```
実機（GPUと画面あり）では、進行役が追加で次を行う。
```
cargo test --workspace -- --include-ignored
cargo run --release -- --script crates/app/e2e/flow-1.json --out target/e2e     # 開く〜レビュー保存、画像と状態を出力
cargo run --release -- --script crates/app/e2e/flow-2.json --out target/e2e     # 再起動して復元、状態が一致すれば終了コード0
```
出力された画像を目で見て、形・前後関係・日本語の字形・輪郭線を確かめる。確かめていない項目は、報告で「未確認」と分けて書く。
