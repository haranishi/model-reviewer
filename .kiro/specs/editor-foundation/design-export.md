# GLBの書き出しとレビューJSON版2

## 方式：元のJSONを値のまま直し、BINは末尾に足す
読み込みは、表示に要る形状と色だけを取り出し、テクスチャ・アニメーション・スキン・拡張・追加情報を捨てている。文書から新しいGLBを組み立てると、それらが消える。そこで書き出しは**元のファイルのバイト列を土台にする**。

1. 元のファイルを読み直し、大きさとハッシュが開いたときの値と同じことを確かめる（違えば書き出さない）。
2. JSONチャンクを `serde_json::Value` として読む。型つきの `gltf::json::Root` は使わない。知らない拡張と `extras` を落とすためである（`gltf-json` の `extras` 機能は切ってあり、読み込みは未知の拡張を取り除いてから型に入れている）。
3. 値の上で、変えた所だけを書き換え、足す物は**配列の末尾に追記**する。既存の要素の番号は1つも変えない。
4. BINチャンクは元のバイト列をそのまま置き、足した図形の頂点とインデックスだけを末尾に足す。`buffers[0].byteLength` を伸ばす。
5. 一時ファイルへ書き、読み直して照合し、名前を付け替える。

容器（12バイトのヘッダと2つのチャンク、4バイト境界の詰め物）は自前で書く。`gltf::binary::Glb::to_writer` は実物にあるが、BIN全体を1つのバイト列として渡す必要があり、元のBINと追記分をつなげた写しが要る。自前なら、元のBINの範囲と追記分を順に書き出すだけで済む。

## 境界の型（`model_reviewer_gltf::export`）
```rust
pub struct ExportScene { pub nodes: Vec<ExportNode> /* 行きがけ順 */, pub added: Vec<Arc<Primitive>>, pub base_primitive_count: u32 }
pub struct ExportNode { pub parent: Option<u32> /* nodes の添字 */, pub name: String, pub local: Affine3A,
                        pub file_index: Option<u32>, pub template: Option<u32>, pub draws: Vec<Draw> }
pub struct Built { pub json: Vec<u8>, pub appended_bin: Vec<u8>, pub assigned: Vec<u32> /* nodes[i] のファイル内の番号 */, pub notes: Vec<ExportNote> }
pub enum ExportNote { DetachedNodes { count: u32 }, AnimatedNodesChanged { count: u32 }, SkinnedNodesChanged { count: u32 },
                      MatrixWritten { count: u32 }, SceneAdded }
pub fn build(base: &[u8], scene: &ExportScene) -> Result<Built, ExportError>;
pub fn write_container(out: &mut dyn io::Write, base: &[u8], built: &Built) -> Result<u64, ExportError>;
pub fn verify(written: &[u8], base: &[u8], scene: &ExportScene, built: &Built) -> Result<(), ExportError>;
```
`ExportScene` は `Document` と別の型にする。書き出しは別スレッドで動くので、どのみち文書の写し（部品の表だけ）が要る。型を分けておけば、書き出しの作業は文書の作業と並行して進められ、`gltf` クレートは `core::doc` を知らなくて済む。

## 部品ごとの扱い
| 文書の部品 | JSONでの扱い |
|---|---|
| ファイルにあり、変形も親子も変えていない | **触らない。** 判定は、ファイルの値を読み込みと同じ関数で行列にし、文書の `local` とビット単位で一致すること |
| ファイルにあり、変形を変えた | そのノードの変形だけを書き換える。位置・回転・大きさに分けられれば3項目で書き、`matrix` を消す。分けられなければ `matrix` で書く（一覧に出す） |
| ファイルにあったが、文書から削除した | 親の `children`（根ならシーンの `nodes`）から番号を外す。**ノード自体は配列に残す**（下の「削除の扱い」） |
| 複製（`template` あり） | 元のノードのJSONを写して末尾に足す。名前・`children`・変形だけを差し替える。`mesh`・`skin`・拡張・追加情報は写したままなので、テクスチャ付きの形状もそのまま使われる |
| 足した図形（`template` なし） | 形状ごとに `mesh`・`accessor`・`bufferView` を、色ごとに `material`（`baseColorFactor` と `metallicFactor: 0`）を末尾に足し、ノードを足す |
- 子の並びは文書の並びに合わせる。親の `children` を書き換えるのは、並びか顔ぶれが変わった親だけ。
- 根が変わったときは、読み込みが使ったシーンの `nodes` を書き換える。ほかのシーンは触らない。シーンが無いファイルで根を足したり外したりしたときは、根を並べたシーンを1つ足して既定にする（一覧に出す）。
- 足す形状は、位置と法線が32ビット浮動小数、インデックスが32ビット整数。`POSITION` には `min`・`max` を入れる。`bufferView` の位置は4バイト境界にそろえる。

### 削除の扱い：番号を詰めない
削除したノードを配列から取り除くと、後ろの番号がすべてずれる。番号は `children`・シーン・スキンの関節・アニメーションの対象に加えて、**本アプリが中身を知らない拡張**からも指されうる。知らない場所の番号は直せないので、詰めると気づかれないまま壊れる。そこで削除は「シーンから外す」にとどめ、ノードと形状のデータはファイルに残す。
- 代償は2つ。ファイルが小さくならないこと、削除した部品のデータが受け取った人の手元に残ること。**後者は利用者が知らないと困る**ので、書き出しの結果に「削除した部品 n 個はシーンから外しました。形状のデータはファイルに残っています」と必ず出す（要件11.7）。
- 不要なデータを取り除く書き出し（番号の詰め直し）は、知らない拡張があるファイルを断る条件つきで、後続の範囲とする。

## 保証と、その確かめ方
`verify` は、書いたバイト列を読み直して次を確かめる。1つでも外れたら失敗にし、一時ファイルを消す。保存先には何も残さない。
1. 元のBINの範囲が、書き出したファイルの同じ位置にバイト単位で一致する。
2. JSONの最上位の項目のうち、`nodes`・`scenes`・`scene`・`meshes`・`materials`・`accessors`・`bufferViews`・`buffers` 以外が、値として元と等しい。この8つも、元からあった要素は、書き換えると決めたノードと `buffers[0].byteLength` と該当のシーンを除いて等しい。
3. 本アプリの読み込み（`load_glb`）で開ける。部品の数、各部品の名前とワールド行列（許容差つき）、配置後の三角形数が、渡した `ExportScene` と一致する。
- JSONは値として保つ。項目の並び順と、数の書き方（`1.0e0` と `1.0` など）は変わりうる。意味は変わらない。並び順まで保つには `serde_json` の `preserve_order` 機能が要るが、ワークスペース全体の振る舞いが変わるので使わない。
- 数は64ビット浮動小数で読み書きするので、32ビットの値は元の値に戻る。

## ファイルの扱い（`app::exporter`、別スレッド）
- 工程は「読み取り中 → 組み立て中 → 書き込み中 → 確かめ中」。工程名を状態欄に出す。割合は出さない。書き出し中は編集を受け付けず、視点の操作は受け付ける（読み込み中と同じ仕組み）。
- **「開く」で開いたファイルへは書き出せない。** 正規化したパスが同じか、同じファイル（Unix では装置番号とiノード番号）なら断る。`Session` は、この作業で「開く」から開いたファイルを覚えておく。書き出して作業の対象が移った後も、元のファイルは書き出し先にできない。本アプリが同じ作業の中で書き出したファイルへ、もう一度書き出すことはできる。
- 書き込みは、保存先と同じフォルダの一時ファイルへ行い、照合の後で名前を付け替える（第1段階のレビュー保存と同じ）。
- メモリは、元のファイルと読み直した結果を同時に持つ間、ファイルの大きさの約2倍が上乗せされる見込みである（未計測。測って検証の記録に残す）。開いている間ずっとバイト列を持つ案は、常駐メモリが増えるので採らない。
- 全体が4GiBを超える（GLBの長さは32ビット）ときは、書き出す前に理由を出して止める。

## 書き出した後
- `built.assigned` を文書の「鍵→ノード番号」の表に入れ、複製の `template` を消す。`ModelRef` を新しいファイル（パスと、書いたバイト列のハッシュ）に替える。文書の版を「書き出し済み」として覚える。履歴は残す。
- 取り消しで「書き出した後に足した物」より前へ戻ると、ファイルにある部品が文書から消える。次の書き出しでは、それは「削除」として扱われる（シーンから外れる）。やり直せば元に戻る。書き出しは毎回「いまの土台のファイル」と文書を比べるだけで、履歴を見ない。

## レビューJSON版2
- 変わるのは1点だけ。視点の `camera.projection` に `"orthographic"` を許す。平行投影の見える高さは `2 × distance × tan(fov_y / 2)` で、項目は足さない。
- 版1のアプリは `"orthographic"` を「値が不正」として拒む（`review_file.rs` で確認）。理由が伝わらないので、**平行投影の視点を1つでも含むときだけ版2で書く**。含まなければ版1のまま書き、前の版のアプリでも読める。版2は古いアプリで「新しい版です」と表示される。
- 読むときは版1と版2の両方を受け付ける。項目の意味は同じなので、変換は要らない。
- モデルの識別（ファイル全体のハッシュ）は変えない。書き出したGLBは別のファイルなので、元のファイル用のレビューは当てはまらない。当てはめる選択肢は置かない（理由と、後続の案は [design-decisions.md](design-decisions.md)）。

## この段階の制限（利用者向けの文書にも書く）
- 削除した部品のデータはファイルに残る。色・材質・形状そのものは変えられない。
- アニメーションの対象になっている部品の変形を変えると、再生するソフトではアニメーションの値が優先される。スキンの付いた部品の変形は、仕様上、表示に使われない。どちらも書き出しの結果に件数を出す。
- 本アプリで開けないGLB（必須の圧縮拡張など）は、書き出しの対象にならない。
