# テストと性能

第1段階の方針（論理はGPUなしで試す、GPUの試験は `#[ignore]`、実機の確認はOSの入力を使わない自動操作）を保つ。検証コマンドも同じ4つである（`cargo fmt --all --check`、`cargo test --workspace`、`cargo clippy --all-targets --workspace -- -D warnings`、`cargo build --release`）。GPUのある環境では `cargo test --workspace -- --include-ignored` も通す。

## どこで何を確かめるか
| 対象 | 置き場所 | 確かめること |
|---|---|---|
| 文書 | `core/tests/doc.rs` | 開いた直後は `Model` と同じ内容。変形で子孫の `world` と境界が合う。触れていない部品の `world` がビット単位で変わらない。挿入と削除の後も、行きがけ順・`subtree_end`・深さ・鍵の表が正しい。`Remap` が全部の添字を正しく移す |
| 履歴 | `core/tests/history.rs` | 各操作を実行→取り消しで、文書と `ReviewState` が元とビット単位で等しい。やり直しで実行後と等しい。無作為な操作の列（決まった種の乱数）を全部取り消すと最初に戻る。上限を超えると古い順に捨て、残りの取り消しが正しい。版の番号と未保存の判定 |
| ハンドル | `core/tests/gizmo.rs` | 軸の移動が軸の方向だけに効く。回転の角度が画面上の動きと合う。視線と軸が平行なら `None`。分解と合成が往復で一致。傾いた拡大を見分ける。透視と平行の両方 |
| カメラ | `core/tests/camera.rs` | 仰角±90°で行列が有限で、回転を続けられる。平行で `project` と `screen_ray` が互いに逆。切り替えの前後で注視点の見かけの大きさが同じ。平行の深度が手前ほど大きい |
| 図形 | `core/src/shapes.rs` の中 | 頂点と三角形の数、法線が外向きで長さ1、すべての辺が2つの面に共有される（平面を除く）、境界が指定の大きさ |
| 書き出し | `gltf/tests/export.rs` | 下の「書き出しの試験」 |
| 描画 | `render/tests/gpu.rs`（`#[ignore]`） | 格子が出る・部品に隠れる。線の表示で画像が変わる。変形中の行列で部品の位置が変わり、送ったバイト数が部品の数で増えない。部分更新の後の画像が、全体を作り直した画像と一致する。足した図形が出る。何もしないフレームで描かない |
| 画面の部品 | `app/tests/{viewcube,inspector,toolrail,gizmo_view}.rs`（`egui_kittest`） | 入力用の構造体だけで動く。押すと期待した `Command` が積まれる。押せない状態で理由が出る。日本語の文言で落ちない（フォントを登録して実行する） |
| つながり | `app/tests/{edit,undo,export,view}.rs`、`gpu_flow.rs` | `Command` の列で、変形→取り消し→やり直し、追加→削除、書き出し→作業対象の切り替え→レビュー保存、未保存の確認。読み込み中と書き出し中に編集が断られる |

## 書き出しの試験
入力は、試験用の生成器で作るGLB（テクスチャ・アニメーション・スキン・知らない任意の拡張・`extras` を、中身が偽でも構造として含むもの。`crates/testdata` に足す）と、外部で作ったGLB（`MR_EXTERNAL_GLB_DIR`、`#[ignore]`）。
1. 何も変えずに書き出す → BINがバイト単位で同じ、JSONが値として同じ、読み直した `Model` が同じ。
2. 1個だけ動かす → そのノード以外のJSONが値として同じ。子の部品のワールド位置が、親に付いて動いている。
3. `matrix` で書かれたノードを動かす → 分けられれば3項目、分けられなければ `matrix`。動かしていない `matrix` のノードは触らない。
4. 複製 → 新しいノードが同じ `mesh` を指す。既存の番号が変わらない。
5. 図形を足す → 新しい `mesh`・`accessor`・`bufferView`・`material` が末尾に付き、`POSITION` の `min`・`max` が正しい。読み直すと同じ形状。
6. 削除 → 親の `children` から消え、ノードは配列に残る。読み直すと部品が減っている。アニメーションの対象の番号が変わらない。
7. 書き出したファイルを土台にもう一度書き出す（足した物を取り消してから）→ 外れた扱いになり、やり直してから書くと元に戻る。
8. 断る場合: 元のファイルが変わっている、保存先が開いたファイルと同じ（別名のリンク経由を含む）、4GiB超、照合の失敗（試験用に結果を壊す）。どの場合も保存先に何も残らない。

## 第1段階で踏んだ罠と、今回の試験の対応
| 罠 | この段階での備え |
|---|---|
| `Response::has_focus` は前面でないウィンドウで常に偽 | キーと確定の判定は egui のメモリで行う。実機の自動操作（ウィンドウは前面に出ない）で、数値の欄へ打って Enter で確定する手順を通す |
| 隠れたウィンドウは描画の要求が要り、入力が持ち越される | 足した手順（`drag_widget`・`export_glb`）は、既存の注入の順番待ちを通す。ハンドルのドラッグを、隠れた状態でも最後まで実行できることを確かめる |
| 出たばかりの小窓は1回目の位置が定まらず、入力位置も次の回から | 新しい操作は並べたボタンにして小窓を使わない。書き出しの結果と確認のダイアログを押す手順は、位置が2回そろうのを待つ。数値の欄は、入力位置が来たのを2回確かめてから打つ |
| 起動直後に大きいモデル（複数回に分ける転送）を開く経路 | `gpu_flow.rs` に「何も開いていない状態から32MiB超のモデルを開き、転送が終わった直後に、変形・図形の追加・取り消し・書き出しを行う」試験を足す。転送中の編集が断られることも確かめる |
| 画面に出ていない間の描き過ぎでメモリが増える | 実機の自動操作 `heavy-edit.json` で、重いモデルのハンドルを600フレーム動かし、300フレーム目と600フレーム目の常駐メモリを `report.json` に残す。増え続けていないことを確かめる |
| 日本語フォントは最優先で登録済み | 新しい画面の画像（`ui_shots.rs`）で、足した文言と「、。（）・」の字形を確かめる。記号は図形で描き、絵文字に頼らない |

## 実機の自動操作（進行役が実行する）
| 手順 | 内容 |
|---|---|
| `view-1.json` | 開く → 立方体で前・上・右 → 平行 → 表示を4つ → 格子を消す → 視点を保存 → レビュー保存（版2になる）→ 画像 |
| `edit-1.json` | 開く → 部品を選ぶ → 移動のハンドルをドラッグ → 数値の欄へ打って確定 → 回転 → 取り消し2回 → やり直し1回 → 注釈 → 書き出し → レビュー保存 → 状態を書き出す |
| `edit-2.json` | 起動し直して、書き出したGLBとレビューを開く → `edit-1` の最後の状態と一致。元のGLBのハッシュが変わっていない |
| `edit-3.json` | 図形を足す → 複製 → 削除 → 取り消し → 書き出し → 開き直して部品の数と位置が一致 |
| `measure-1.json` | 計測の2点 → 距離が期待値 → 部品を動かす → 距離が変わる → 単位を切り替えても数値が同じ |
| `heavy-edit.json` | 生成した重いモデル（部品10万個）で、下の性能の測定を行う |
既存の `smoke`・`flow-1`・`flow-2` は、変えずに通ること。

## 性能：測るものと目標
値はすべて、詳細パネルと `--log-metrics`、自動操作の `report.json` に出す。**下の目標は設計上の狙いであり、測った値ではない。** 測った結果は検証の記録（`verification.md`）に、モデル・機械・条件とともに書く。届かなかった項目は、値を書いたうえで直すか、目標を見直す理由を残す。
| 測るもの | 測り方 | 目標 |
|---|---|---|
| 変形中のフレームのCPU時間 | 部品10万個のモデルで、子孫5万個の部品のハンドルを120フレーム動かす。既存の「フレームのCPU時間」の平均と最大 | 同じモデルで視点を回したときの平均の1.5倍以内 |
| 変形中にGPUへ送ったバイト数 | `RenderStats::uploaded_bytes` の、ドラッグ開始から確定直前までの差 | 部品の数に依らず、1フレームあたり定数バッファ1つ分 |
| 変形の確定 | `CommitTransform` の `apply` にかかった時間（新しい性能値「編集の確定」） | 子孫5万個で1フレーム（16ms）以内 |
| 追加・複製・削除 | 同じく `apply` の時間。部品10万個で、1個の追加と、1万個の部品の削除 | 100ms以内 |
| 取り消し・やり直し | 上の各操作の取り消しの時間 | 元の操作と同じ桁 |
| 履歴のメモリ | `History::bytes()` と件数（新しい性能値）。変形100回と、1万個の削除1回の後の値 | 上限（64MiB）以内。変形1回は200バイト以内 |
| 書き出し | 工程ごとの時間（読み取り・組み立て・書き込み・確かめ）と、書き出し中の常駐メモリの最大 | 目標は置かない。測って記録する |
| 何もしない間 | 格子・ハンドルを出した状態で、入力なしのフレームの `draw_count` | 増えない |
- GPUの処理時間は、この段階でも測らない（「未計測」と出す）。
- 重いモデルは `cargo run --release -p model-reviewer-testdata -- stress 100000 200 target/stress.glb` で作る。リポジトリには置かない。
- 他のソフトとの比較は書かない。
