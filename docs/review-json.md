# レビューJSON（版1・版2）

「レビュー保存」が書き、「レビュー読込」が読む形式です。下の例は版1です。版2との違いは「版2」の節にあります。日時を記録しないので、同じ状態からは同じ内容になります。

保存先には、新しい名前か、このアプリで読める既存のレビューを選べます。拡張子が `.json` でも、別の内容や未対応の版なら理由を表示して保存を止めます。注釈や視点に保存できない数値がある場合も、理由を表示します。同じフォルダに一時ファイルを書き、保存先を確認してから置き換えるため、失敗しても前のファイルと未保存の編集は残ります。

この起動で開いた GLB・STL は、改名やドライブ間の移動の後も、バイト数と BLAKE3 が同じなら保護します。同じ内容のコピーも対象です。この起動で書き出した GLB には同じ場所へ再び書き出せます。

```json
{
  "format": "model-reviewer.review",
  "version": 1,
  "app_version": "0.1.0",
  "model": {
    "file_name": "review-sample.glb",
    "path": "（保存時の絶対パス）",
    "relative_path": "../models/review-sample.glb",
    "size_bytes": 11732,
    "hash": { "algorithm": "blake3", "hex": "（64桁の十六進）" },
    "node_count": 12
  },
  "hidden_nodes": [{ "gltf_index": 9, "name": "arm" }],
  "annotations": [{
    "id": 1,
    "node": { "gltf_index": 1, "name": "base" },
    "local_position": [0.5, 0.5, 0.0],
    "local_normal": [0.0, 1.0, 0.0],
    "text": "台の角を面取りしてください"
  }],
  "views": [{
    "id": 2,
    "name": "斜め上",
    "camera": {
      "projection": "perspective",
      "target": [0.0, 0.3, 0.0],
      "yaw_deg": 35.0,
      "pitch_deg": 20.0,
      "distance": 4.0,
      "fov_y_deg": 40.0
    }
  }]
}
```

数値は形の見本で、実ファイルの値ではありません。

## 項目

- `path` は絶対パスで、**ユーザー名が含まれることがあります。共有する前に中身を確かめてください。** `relative_path` は JSON のあるフォルダから見た相対パスです。
- 注釈の位置は、付いた部品の中の座標です。画面の座標は保存しません。
- `hidden_nodes` は、自分で非表示にした部品だけです。親に連れて隠れた子は書きません。
- `id` は注釈と視点で共通の番号です。
- STL のレビューには、`model` に単位の仮定 `stl_unit`（`"mm"`・`"cm"`・`"m"`）と、上の向きの仮定 `stl_up`（`"z"`・`"y"`）が入ります。版はこれまでどおりで、GLB のレビューでは両方を省略します。STL の部品の `gltf_index` は 0 です。

## 読み込みと復元

1. 形式名が違う、版が 2 より新しい、数値が非数や範囲外、id の重複や大きすぎる値がある場合は読みません。知らない項目は無視します。
2. 開いているモデルのバイト数と BLAKE3 が一致し、STL なら単位と上の向きも一致すれば、その場で復元します。書き出した GLB に未書き出しの形の編集があるときは、破棄を確認して開き直します。
3. 同じモデルを開き直すときは、現在のファイルを最初に調べます。そこに一致するファイルがないときや、別のモデルを復元するときは、レビューの `relative_path`、`path` の順に調べます。STL はレビューの単位と上の向きで開きます。
4. 内容の違うファイルしか無いときは、何も復元せず、保存時と今のバイト数とハッシュの先頭を示して「別のGLBを指定」か「やめる」を選びます。
5. ファイルが見つからないときは、探した場所を示して「モデルを指定…」を出します。
6. GLB の非表示や注釈は、`gltf_index` と部品名が両方一致したときだけ復元します。STL の部品名はファイル名から付くので、STL として読み込んだモデルは改名後も唯一の部品（番号 0）に復元します。単位の記録がないレビューも同じです。
7. STL は `stl_unit` がなければ mm、`stl_up` がなければ Y が上として開きます。指定できる文字列以外の値は読みません。`stl_up` を知らない旧版では、Z が上のレビューも Y が上で表示されます。旧版で保存し直すと、向きの記録が消えます。

形が変わったモデルでは、注釈の位置を指し直す必要があります。保存していない変更（入力途中の注釈を含む）があるときは、読み込みの前に確認します。

表示中のモデルを置き換える間は、復元のために開き直す場合も「レビュー保存」が無効になります。キーで保存を求めると、状態欄に「読み込みが終わってからレビューを保存してください」と出ます。表示・注釈・視点の変更もこの間は休止します。読み込みに失敗したときや復元をやめたときは、元のモデルで選択と注釈を続けられます。

## 版2

版2で変わるのは1点だけです。視点の `camera.projection` に `"orthographic"`（平行投影）を書けます。見える高さは `2 × distance × tan(fov_y_deg / 2)` で決まり、項目は足していません。

- 平行投影の視点を1つでも含むときだけ `"version": 2` で書きます。含まなければ版1で書くので、前の版のアプリでも読めます。
- 版1だけを読むアプリは、版2のファイルを「新しい版です」として読みません。
- 読むときは版1と版2の両方を受け付けます。項目の意味は同じです。

## 形を編集したときの保存

注釈と非表示は、ファイル内のノード番号（`gltf_index`）とハッシュで、どのGLBのどの部品かを指します。そのため次のように扱います。

- 書き出していない形の編集（変形、追加、複製、削除）があるときは、レビューを保存できません。保存しようとすると、先にGLBを書き出すよう案内します。足した部品は元のファイルに無く、指す番号が無いからです。
- 書き出すと、作業の対象が新しいGLBに移ります。その後に保存したレビューは、新しいGLBのバイト数とハッシュを持ちます。元のGLB用に保存したレビューは、新しいGLBには当てはまりません。
- 書き出し後にさらに形を編集し、その変更を破棄してレビューを復元するときは、書き出した GLB を開き直します。別の場所の候補から復元した場合は、そのモデルも上書きから保護します。
- 部品を削除すると、その部品と子に付いた注釈と非表示の設定も一緒に消えます。取り消すと戻ります。
- 計測は保存しません。
