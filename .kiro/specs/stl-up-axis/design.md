# 設計：STL の上の向き

要件は [requirements.md](requirements.md)。第3段階の [design-stl-units.md](../cad-inspect/design-stl-units.md) の続きで、足す分だけを書く。

## 決めたこと
**向きは、単位の倍率と同じ部品の `local` に回転として入れる。** Z が上のとき、`local` は「一様な拡大 × X 軸まわり -90° の回転」になる。倍率が一様なので、掛ける順で結果は変わらない。位置は 0 のまま。

| ファイルの軸 | 画面（ワールド）での向き |
|---|---|
| X | X |
| Y | -Z（奥） |
| Z | Y（上） |

行列式は正で、面の表裏は変わらない（要件1.4）。

```rust
// core::units（UnitLabel の隣。どちらも「ファイルに書かれていない前提」）
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum UpAxis { #[default] Z, Y }
impl UpAxis {
    pub fn suffix(self) -> &'static str;   // "Z"・"Y"（画面の文字）
    pub fn key(self) -> &'static str;      // "z"・"y"（レビューJSON と自動操作）
    pub fn other(self) -> UpAxis;          // 切り替えの行き先
    pub fn rotation(self) -> glam::Mat3;   // Z は下の行列、Y は単位行列
}
// stl::StlOptions に up: UpAxis ／ app::loader::LoadOptions に stl_up: Option<UpAxis>（None は Z）
// app::session::SourceKind::Stl { unit, up } ／ Command::SetStlUp(UpAxis) ／ ExportBase::Stl { unit, up, name }
// core の ModelRef と ReviewModelRecord に stl_up: Option<UpAxis>（GLB では None で、項目ごと書かない）
```

- **回転の行列は、角度から三角関数で作らず、0 と ±1 を直に並べる**（列は X →(1,0,0)、Y →(0,0,-1)、Z →(0,1,0)。これに倍率を掛ける）。`f32` で cos 90° を計算すると 0 にならず、外形の箱に 1e-7 程度の余りが乗る。開いた直後の外形を、値どおり（20・40・30 mm）にするためである。
- 書き出した GLB を開き直すと、回転は四元数（-0.7071…, 0, 0, 0.7071…）から行列に戻るので、1e-7 程度の差が出る。`synthesize_base` の約束（`local` は相対 1e-6 以内）の内に収まる見込みで、試験で固定する。

## 確かめたこと（コードを読んだ事実）
- 書き出しは、部品の `local` を位置・回転・大きさに分け、単位回転でなければ `rotation` を書く（`gltf::export::json::write_transform`）。分けられないときだけ `matrix` を書く。合成する土台も同じ関数を通るので、`synth.rs` に手を入れずに回転が入る見込みである。
- 「変形」の回転は、X・Y・Z の順の外部回転の角度（度）で出る（`core::gizmo::euler_deg`）。一意でなくなるのは Y が ±90° 付近だけで、X = -90 は一意に出る。
- 寸法（外形）・計測・断面・床の格子は、ワールドの座標で計算している。回転は部品の `world` に入るので、どれも画面の軸で出る。計算の側を変える必要は無い。
- 注釈の位置は部品の中の座標（＝ファイルの座標）で持つ。向きを替えても同じ面に付く（要件3.6）。保存した視点はワールドの値なので、向きが違うと合わない。だからレビューに向きを書く。
- 単位の切り替え（`set_stl_unit`）は、開き直しの指定に単位だけを渡している。レビューの照合（`persist` の `same_unit`）も単位だけを見ている。どちらも向きを足す。
- 依頼者が確かめたこと: 回転を入れて書き出した GLB は、ほかのソフトで元の向きになる。第3段階の記録にも、手で X = -90 を入れた場合の結果がある。

## 捨てた案
| 案 | 捨てた理由 |
|---|---|
| 頂点の座標を入れ替えて読む | 「座標の値は形状にそのまま入れる」約束が崩れる。書き出した GLB の位置が元の STL と違ってしまい、注釈の位置の意味が向きの仮定に左右される |
| 親の部品を1つ足して、そこに回転を入れる | 「部品1つ」の前提（合成する土台、レビューの部品0の扱い、部品の一覧）が崩れる |
| カメラや床の側で「上」を替える | 格子・視点の立方体・断面の軸・正面や上からの視点が、Y が上を前提にしている。変える所が多く、GLB との混在で食い違う |
| 形から向きを推し量る | 外れたときに理由を説明できない。仮定を1つ見せて、1回で替えられるほうが確かである |

## 流れ
- **開く**: `loader` が `options.stl_up`（無ければ Z）を `StlOptions` へ渡し、`SourceKind::Stl { unit, up }` と `ModelRef.stl_up` に入れる。
- **切り替え**: `SetStlUp(up)` と `SetStlUnit(unit)` は、同じ関数で「今の単位と向きのうち、片方だけを替えた指定」を作り、`open_guarded` へ渡す。条件（STL のときだけ、同じ値なら何もしない、読み込み中は断る）は今のまま。
- **書き出し**: 土台を作り直すとき（`exporter::synthesize_from_stl`）にも同じ `up` を渡す。ここで渡し忘れると、土台の部品に回転が無く、文書の部品0と土台がずれる。書き出しが終わると `source_kind` は `Glb` になり、向きの仮定は消える（回転は部品に残る）。
- **レビュー**: 保存で `stl_up` を書く。復元で `LoadOptions` へ渡す。開いている STL と単位か向きが違えば、レビューの値で開き直す。

## レビューJSON
- `model` に `"stl_up": "z"`（`"y"`）。STL のときだけ書く。版は上げない（理由は `stl_unit` と同じ）。
- **項目が無いときは Z**。`stl_unit` と同じく「無ければ既定」の1つの決まりにする。この項目ができる前に作った STL 用のレビューは Y が上で保存されているので、開くと注釈は正しい面に付くが、保存した視点は向きが合わない。STL を開く機能は公開前で、そうしたレビューは開発中の物だけなので受け入れる。
- 2つ以外の値、文字列でない値は `InvalidValue`。

## 自動操作と既存の手順
- `open_model` の `stl_up`（`"z"`・`"y"`）。それ以外は「stl_up は z、y のいずれかです」。`dump_state` の最上位に `"stl_up"`（STL 以外は `null`）。
- `stl-1.json` は `stl_up: "y"` を足し、画面の位置の数値を変えずに通す。保存されるレビューに `"stl_up": "y"` が入り、`stl-2` が既定でない向きの復元を確かめる手順になる。`heavy-inspect.json` の STL 2つも `"y"` にして、測る条件を前の記録とそろえる。
- 手順書の撮影は既定で行う。`guide-05-stl.json` は部品の一覧を押すだけなので、そのまま通る（絵は変わる）。`guide-03-measure.json` は、測る2点の位置を取り直す（取り直すまでは `stl_up: "y"` を仮に足して通す）。
