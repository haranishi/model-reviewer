# 判断・捨てた案・落とし穴・保留

## 決めたこと（理由つき）
| # | 決めたこと | 理由 |
|---|---|---|
| 1 | 新規作成は、空のモデルを「読み込んだモデル」と同じ受け渡しに流す | 文書・視点・履歴・GPUの入れ替えは、今 `commit_pending` の1か所にある。別の入口を作ると、消し忘れ（断面、計測、当たり判定の表）が起きる |
| 2 | 元の形式に「新規」を足し、書き出すと GLB へ移す | 第3段階の STL と同じ移り方で、利用者が覚える流れが1つで済む |
| 3 | 新規の文書の書き出しは、「空の土台」を元のファイルの代わりにする | 今の書き出し（土台に足す・照合する）をそのまま通せる。別の「一から書く」経路を作ると、照合と番号の決まりが二重になる |
| 4 | 部品の無い文書は書き出させない | メッシュの無い GLB は、このアプリが開かない。開けないファイルを作らない |
| 5 | 新規の文書は、書き出すまでレビューを保存できない | レビューJSONは、モデルのファイルの大きさとハッシュで相手を確かめる。識別の無いレビューを作ると、復元の確かめが働かない。形式と版を変えずに済む |
| 6 | 新規の単位は、シーンがメートル、表示は「ファイルと同じ」 | GLB を開いたときと同じ。右のパネルの「変形」は換算しない決まり（第3段階）なので、表示だけ mm にすると、寸法は mm・位置は m になって混ざる（分かれ道1） |
| 7 | 1つ目の図形は 1 m、原点。初期視点は格子 0.1 の距離 | 今の「全体の大きさから決める」式が、空のときに 1 を返す（確かめた）。式を変えずに済む |
| 8 | ［新規作成］は何も開いていない画面と Cmd+N。上部には置かない | 幅960で上部に余りが無い。作り始めるのは、何も開いていないときである |
| 9 | 色は `Draw.base_color` を書き換える。対象は、選んだ部品とその子孫 | 文書は、すでに部品ごとに描画の表を持っている。移動・複製・削除と同じ範囲で、選択の意味が1つになる |
| 10 | 扱うのは基本色の赤・緑・青だけ。金属らしさ・粗さ・透明度は扱わない | 画面に出ない値を変えさせない。`Draw` に項目が無く、足すと29か所の組み立てが変わる。テクスチャの段階で、描画と一緒に足す |
| 11 | 色の部品は、見本12色・16進・R・G・B。つまみは置かない | 確定だけの形なら、履歴の1回分がはっきりする。つまみは、試し塗りと確定の状態が要る |
| 12 | 色は sRGB の8ビットで見せ、ファイルにはリニアで書く。読み込んだ色は、変えるまで1ビットも変えない | glTF の基本色はリニア。画面で扱う色は sRGB。変えていない部品を「変えた」と見なさないために、表示のための丸めを文書へ戻さない |
| 13 | 書き出しは、元の材質とメッシュを写して足し、元を残す | 元の材質を書き換えると、同じ材質を使う別の部品まで色が変わる。番号を変えない決まりを保つ。形状のデータは増えない |
| 14 | 色が変わったかは、土台とビット単位で比べて決める。印を持たない | 変形と同じやり方。取り消しで戻せば、ファイルも元のままになる |
| 15 | テクスチャの注意は、モデル単位で出す | 部品ごとの判定には、`Draw` に材質の情報が要る。今は足さない |
| 16 | キーで動かす操作と、キーの働く場所の直しは、shortcuts-guide に入れた | キーの表と振り分けは、あちらの仕様が持つ。同じファイル（`app.rs`）を2つの仕様で変えない |

## 捨てた案と理由
| 案 | 捨てた理由 |
|---|---|
| 新規作成で、見えない小さな GLB を一時フォルダに書いて開く | 利用者の機械にファイルを作る。書き出し先を禁じる一覧やレビューのパスに、一時の場所が入る |
| 新規の文書を、はじめから「1つ目の図形つき」で作る | 何を置くかを決めつける。消せば同じ空になるので、空を扱う経路は結局要る |
| `Draw` に材質の番号を持たせ、材質の表を文書に持つ | 正しい形だが、この段階で要るのは色だけである。型の変更は、テクスチャの段階で1回にまとめる |
| 元の材質の `baseColorFactor` をその場で書き換える | 同じ材質を使うほかの部品の色が変わる。「触らない項目は値として同じ」の照合に反する |
| 色を変えた部品のメッシュを、形状ごと写す | BIN が増える。同じ脚4本の色を1本ずつ変えると、形状が4つになる |
| 色の変更を、拡張（見た目の切り替え）として書く | 読むソフトが限られる。このアプリの読み込みも扱っていない |
| 使われなくなった材質とメッシュを消す | 番号がずれる。アニメーションや拡張が番号で指している所を、すべて直す必要が出る |
| 色を「レビュー」（表示の設定）として持つ | 書き出しに出ない色になる。依頼は「作る」ための色である |
| 新規の文書のレビューを、識別なしで保存する | 復元で、別のモデルに注釈が付く事故を防げない |

## 落とし穴
1. **描画の番号とプリミティブの番号は一致しない。** 読み込みが、点・線・読めないプリミティブを飛ばす。書き出しで数え直さず、読み込みが作った対応を使う。
2. **照合が、色の写しを3か所で断る**（BIN なしの追加、`metallicFactor`、ノードの `mesh`）。ゆるめるときは、「何でも通す」にせず、写しであることを確かめる形にする（[design-export.md](design-export.md) の表）。
3. **書いた色が読み直した色と1ビットでも違うと、次の書き出しのたびに写しが増える。** 照合でビット単位の一致を確かめる。
4. **空のモデルは、今まで一度も流れたことが無い。** 形状0個の転送、当たり判定の表、範囲が空のときの視点・図形の大きさ・断面の既定。GPUの試験を足す。
5. **`model_ref` が無い状態が、文書があるのに起きる。** 今までは「文書がある ⇒ `model_ref` がある」だった。`unwrap` に近い読み方（「モデルの場所が分かりません」で失敗にしている所を含む）を洗い出す。
6. **選んでいる部品は、選択の強調で明るく見える。** 色を選んだ直後の見た目は、書き出される色より明るい。欄の見本が正しい色である。
7. **数える処理を毎フレーム回さない。** 選んだ範囲の色の数は、部品が10万個あると重い。選択と文書の版が変わったときだけ数える。
8. **16進の欄は入力欄である。** 打っている間は、キーの振り分けが「入力中」で止まる（G や Cmd+Z が働かないのは正しい）。Esc で欄を離れる今の決まりのまま。
9. **インスタンスの部分更新は、色を前の値のまま写している**（`render/src/lib.rs` の `update_instances`）。直さないと、色を変えても次にインスタンスを作り直すまで画面に出ない。試験は、GPUなしで `InstanceList` の中身を見る形にする。
10. **`Applied` に項目を足すと、手で組み立てている試験が通らなくなる。** `..Applied::default()` を使っている所は通る。使っていない所を、契約の作業で直す。
11. **第3段階の区切りBと第4段階が、同じファイル（右のパネル、状態欄、ヘルプ、自動操作、`app.rs`）を変える。** 取り込む前に始めると衝突する。順は [tasks.md](tasks.md)。

## 確かめた事実と、要確認
- 確かめた（リポジトリのコードを読んだ。行は区切りAの時点）: `Draw` の形と、組み立てている箇所の数（29か所・11ファイル）。文書が部品ごとに描画の表を持つこと。インスタンスが色を持ち、範囲だけ書き直す関数があること。シェーダーが色をリニアで扱い、透明度を使わないこと。部分更新が色を前の値のまま写していること、位置の表が部品の順・描画の順であること。書き出しが、ファイルにある部品の描画を読んでいないこと。`build::assemble` が描画0個で失敗すること。`array_mut` が無い配列を作ること。`size_for` と `OrbitCamera::fit` の、空のときの動き。`Session.model_ref` が `Option` であること。`image` クレートが PNG だけ有効なこと。
- 要確認: [design-new.md](design-new.md) の末尾の4件、[design-export.md](design-export.md) の末尾の4件、[design-testing.md](design-testing.md) の色の換算（OSごとの丸め）。Cmd+N が、macOS でOSやメニューに取られずに届くか。区切りBの後の「何も開いていない画面」の文言と、右のパネルの並び。

## 保留（範囲外。足したくなったもの）
テクスチャの表示と貼り付け（[design-texture-outlook.md](design-texture-outlook.md)）／金属らしさ・粗さ・透明度・発光／色のつまみと、動かす間の試し塗り／面ごとの色／最近使った色、色の吸い取り／材質の一覧と名前／色の欄へ移るキー、見本をキーで選ぶ操作／使われなくなった材質の掃除／上部の［新規作成］ボタン／ひな形（机・箱など）から作る／新規の文書の自動の控え。

## 依頼者に確かめたい分かれ道（どれも既定で進められる）
1. **新規の文書の表示の単位**: 既定は「ファイルと同じ（m）」。mm で始めたいなら、表示だけ mm にする（寸法と矢印の量は mm、右のパネルの「変形」は m のままになる）。
2. **色の対象**: 既定は「選んだ部品とその子孫」。選んだ部品だけにするなら、親を選んだときは何も変わらない。
3. **金属らしさ・粗さ**: 既定は「今回は扱わない（画面に出ないため）」。先に欲しいなら、「画面には出ません」と書いた数値の欄として足せる（`Draw` の型を変える作業が増える）。
4. **上部の［新規作成］ボタン**: 既定は「置かない（Cmd+N と、何も開いていない画面のボタン）」。置くなら、幅960で収まるように上部のボタンを1つ畳む必要がある。
5. **テクスチャ（次の段階）**: 既定は「この段階の確認が済んでから、仕様を書く」。メモリが増えるので、出す・出さないを切り替えられる形を先に決めたい。
