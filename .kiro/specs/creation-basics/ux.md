# UX設計（ユーザーストーリーとUX5階層）

実装の前に書いた。戦略から順に決め、下の階層の判断は上から導いている。第1〜第4段階の ux.md は有効で、ここには足す分だけを書く。キーで動かす操作の体験は [shortcuts-guide の ux.md](../shortcuts-guide/ux.md) に足した。

## 誰のためか
- **試しに何か作ってみたい人**: 起動して、まず箱を置いてみたい。開くファイルを持っていない。
- **受け取ったデータに手を入れる人**: 部品を見分けやすくするために色を付けたい。元のファイルと材質は壊したくない。
- **書き出したものをほかのソフトで使う人**: この画面で見た色と、ほかのソフトで見える色が違うと困る。違うなら、先に知りたい。

## ユーザーストーリー
| # | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| S1 | ファイルを用意せずに作り始めたい。今は土台の GLB を開く必要がある | 何も開いていない画面のボタンか Cmd+N で、空の文書が開く |
| S2 | 作りかけを、うっかり消したくない | 未保存があれば、新規作成の前に確認が出る |
| S3 | 作ったものをファイルにしたい | 新規の文書を、開いたファイル無しで GLB に書き出せる |
| S4 | 部品に色を付けたい。色つきの部品を先に用意して複製する回り道をやめたい | 選んで、見本を押すか16進を打つと色が変わる |
| S5 | 同じ形の脚が4本あるとき、1本だけ色を変えたい | 選んだ部品だけが変わる。ファイルの形状は増えない |
| S6 | 色を間違えたら戻したい | 取り消しで、元の色（部品ごとに違っていた色も）に戻る |
| S7 | 元のファイルの材質を壊したくない | 元の材質は残り、変えた部品だけが新しい材質を指す |
| S8 | この画面とほかのソフトで見え方が違うなら、先に知りたい | テクスチャのあるモデルでは、色の欄の下に注意が出る |

## 1. 戦略
- 目的は「思いついたら、すぐ置いて、色を付けて、ファイルにできる」こと。材質を細かく作り込む道具にはしない。
- 大事にする順番は、①利用者の作業と元のファイルを失わない・壊さない、②画面で見たとおりに書き出される（見えないものを変えさせない）、③軽さを保つ（色を変えても形状を送り直さない、メモリを増やさない）、④覚えることを増やさない（今ある確認・書き出し・取り消しの流れに乗せる）。
- 触らない人の画面を変えない。足すのは、何も開いていない画面のボタン1つと、右のパネルの「色」だけである。

## 2. 要件（戦略から導いたもの）
- ①から: 新規作成は、別のモデルを開くときと同じ未保存の確認を通す。色の変更は履歴に入り、未書き出しの印が付く。書き出しは元の材質とメッシュを残し、足すだけにする。
- ②から: 金属らしさ・粗さ・透明度の欄を置かない。テクスチャや頂点の色があるモデルでは、色がどう掛かるかを画面と結果の一覧に書く。色は sRGB の8ビットで見せ、選んだ値がそのまま表示に戻る。
- ③から: 色はインスタンスの値を書き直すだけにする。形状のデータ・アクセサ・BIN を足さない。新規作成は一時ファイルを作らない。
- ④から: 新規の文書の書き出しは、今の「書き出すと作業の対象が移る」流れのまま。レビューの保存は、書き出すまで断る（今の「先に GLB を書き出してください」と同じ考え方）。

## 3. 構造
- 文書の状態は3つになる: **何も開いていない** → **新規（未書き出し）** → **ファイルを土台にした文書**。新規の文書は、書き出すと3つ目へ移る。STL を開いた文書（第3段階）と同じ移り方である。
- 入口は2つ。何も開いていない画面の［新規作成］と、Cmd+N。上部のボタンは増やさない（幅960で余りが無い。モデルを開いている間の入口は Cmd+N とヘルプの表）。
- 「色」は右のパネルの、部品 → 変形 → 寸法 → **色** → 計測 の位置に置く。選んだ部品に対する操作を上にまとめる並びを保つ。
- 色の対象は「選んだ部品とその子孫」。移動・複製・削除と同じ範囲にして、選択の意味を1つに保つ。

## 4. 骨格
```
何も開いていない画面                         右のパネル「色」（部品を選んでいるとき）
┌───────────────────────────────┐          ┌ 色 ─────────────────────────────┐
│ GLB・STL をここへドロップ、     │          │ [■ 今の色]  # [ C8C8C8 ]         │
│ または［開く］                 │          │ R [200]  G [200]  B [200]        │
│                               │          │ ■ ■ ■ ■ ■ ■                      │
│ ［新規作成］ 空の状態から作る   │          │ ■ ■ ■ ■ ■ ■   ← 見本12色         │
│ （Cmd+N）                     │          │ このモデルにはテクスチャがあります。│
│ ── 操作の表 ──                 │          │ この画面には出ていません。…        │
└───────────────────────────────┘          └─────────────────────────────────┘
```
- 見本は6列×2段。白・薄い灰・濃い灰・黒・赤・橙・黄・緑・青緑・青・紫・茶。押すとすぐ変わる（確定のボタンは無い。戻すのは取り消し）。
- 16進は `#` を欄の外に置き、6桁だけを打つ。Enter か、欄を離れたときに確定する。R・G・B は整数の欄で、同じく確定で変わる（ドラッグの途中では変えない）。
- 色が1つでないときは、今の色の見本を斜めの2色にせず、文字で「複数の色（3色）」と出す（字形や絵に頼らない）。
- 新規の文書では、状態欄のファイル名の所に「新規（未書き出し）」。1つ目の図形は原点に、1 m の大きさで置かれる。

## 5. 表層
配色と文字は今のまま。見本は 18 ポイントの角丸の四角で、今の色と同じ見本には選ばれた道具と同じ琥珀の枠を付ける。見本には、ポインタを載せたときの説明で色の名前と16進を出す（色の見分けに頼らない）。注意の文は補助の文字色で、欄の下に字下げして出す。［新規作成］は、［開く］と同じ見た目のボタンにする。

## この検討で要件・設計が変わった点: 9件
依頼の項目（新規作成、色と質感）をそのまま実装した場合からの変更。
1. **金属らしさと粗さの欄を置かない**（戦略②）。この画面の描画は基本色と簡単な照明だけで、変えても見た目に出ない。見えない値を変えさせると、書き出して初めて結果が分かる。テクスチャの段階で、描画と一緒に入れる。
2. **色を連続して変える部品（つまみ）を置かず、見本・16進・数値にした**（戦略③④）。つまみは、動かす間の試し塗りと、離したときの確定の2つの状態を増やす。まず確定だけの形で入れる。
3. **色の対象を、選んだ部品とその子孫にした**（構造）。選んだ部品だけにすると、組み立てた部品（親）を選んだときに何も変わらない。移動や削除と同じ範囲にそろえた。
4. **色が混ざっているときは文字で出す**（表層）。「複数の色（N色）」。絵で表すと、色の見分けに頼ることになる。
5. **テクスチャのあるモデルでは、色の欄の下に注意を出す**（S8、戦略②）。この画面にはテクスチャが出ないので、白い部品を赤にしても、ほかのソフトでは「赤く染まった木目」になる。黙っていると嘘の表示になる。
6. **元の材質を書き換えず、写しを足す**（S7、戦略①）。同じ材質を使うほかの部品の色まで変わる事故を無くす。ファイルは材質とメッシュの JSON のぶんだけ増える（形状は増えない）。
7. **新規作成のボタンを上部に足さない**（戦略「触らない人の画面を変えない」）。幅960で余りが無く、作り始めるのは何も開いていないときである。
8. **新規の文書はレビューを保存できない、と先に言う**（戦略①④）。レビューはモデルのファイルの識別を持つ。識別の無いレビューを作ると、復元で別のモデルに当たる。書き出せば保存できる。
9. **空の文書の書き出しを断る**（戦略②）。部品の無い GLB は、このアプリでも開けない（メッシュの無いファイルは開かない決まり）。開けないファイルを作らせない。
