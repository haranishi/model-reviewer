# UX設計（ユーザーストーリーとUX5階層）

実装の前に書いた。戦略から順に決め、下の階層の判断は上から導いている。第1〜第5段階の ux.md は有効で、ここには足す分だけを書く。

## 誰のためか
- **受け取ったモデルを確かめる人**: 木目やラベルの付いたモデルが、灰色や単色でしか見えないと、何を見ているのか分からない。
- **置いた図形や STL に、見た目を付けたい人**: 床に板の絵、箱にラベルを貼って、雰囲気や向きを確かめたい。UV という言葉は知らなくてよい。
- **書き出したものをほかのソフトで使う人**: この画面で見た貼り方のまま渡したい。写真の撮影場所などが、知らないうちにファイルへ入るのは困る。
- **軽さを確かめたい人**: 画像をたくさん入れても重くならないかを、数字で見たい。

## ユーザーストーリー
| # | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|
| S1 | テクスチャ付きの GLB を、絵が付いた姿で見たい | 開くと形が先に出て、画像が順に付く。状態欄に進み具合が出る |
| S2 | 出ていないものがあるなら知りたい | 読まない画像・縮めた画像・壊れた画像の件数と理由が「簡略表示」に出る |
| S3 | 重いときは、絵を切って軽い表示に戻したい | 表示の並びの［画像］で切り替えられる。起動の引数で読まないこともできる |
| S4 | 選んだ部品に、手元の画像を貼りたい | ボタン・ショートカット・ドロップのどれでも貼れる |
| S5 | UV の無い図形や STL にも、そのまま貼りたい | 箱形の投影で貼られ、「1枚の大きさ」を長さで決められる |
| S6 | 貼り間違えたら戻したい・外したい | 取り消しで戻る。［画像を外す］で外せる |
| S7 | 貼った結果を、ほかのソフトでも同じに見たい | 画像が GLB に埋め込まれ、箱形の貼り方は UV として書かれる |
| S8 | 写真の付帯情報やファイルの場所を、渡すファイルに入れたくない | 撮影情報は取り除かれ、名前とフォルダは書かれない |
| S9 | 元のモデルと、貼った画像のファイルを壊したくない | どちらも読むだけ。保存先にも選べない |

## 1. 戦略
- 目的は「絵の付いたモデルをそのまま見られ、手元の画像を1回の操作で貼って、同じ見た目で渡せる」こと。材質を作り込む道具にはしない。
- 大事にする順番は、①利用者の作業・元のファイル・持ち物（画像の付帯情報）を失わない・漏らさない、②画面で見たとおりに書き出される（出せないものは変えさせず、出していないものは知らせる）、③軽さを保つ（形を先に出す、上限を決めて縮める、使わない人の負担を増やさない）、④覚えることを増やさない（UV や材質の言葉を画面に出さず、今ある選択・取り消し・書き出しの流れに乗せる）。

## 2. 要件（戦略から導いたもの）
- ①から: 貼った画像のファイルを保護の対象に入れる。撮影情報を取り除いて持つ。名前と場所をどこにも書かない。貼る・外すは履歴に入り、未書き出しの印が付く。書き出しは足すだけにする。
- ②から: 金属らしさ・粗さ・法線の欄を置かない（画面に出せない）。読まない画像・縮めた画像を件数つきで知らせる。箱形の貼り方は、書き出すときに UV へ焼いて、ほかのソフトで同じに見せる。「線」「透かし」で画像が出ないことを、切り替えの説明に書く。
- ③から: 形状を先に表示し、画像は後から送る。合計の上限と、大きい順に縮める決まり。テクスチャの無いモデルでは、頂点もインスタンスも増やさない。箱形の投影は画面では計算で貼り、形状を増やさない。
- ④から: 貼り先は「選んだ部品とその子孫」（色・移動・削除と同じ）。貼り方は自動で決める（UV があれば UV、無ければ箱形）。利用者が決めるのは「1枚の大きさ」だけ。

## 3. 構造
- 画像の状態は、部品ごとに「無い」「ファイルの画像」「貼った画像」の3つ。貼る・外す・取り消すで行き来する。
- 入口は3つ: 右のパネル「画像」の［画像を貼る…］、ショートカット（既定 Cmd+T。変えられる）、画像ファイルのドロップ。ドロップは、先頭のバイトが画像なら「貼る」、GLB・STL なら今までどおり「開く」。
- 「画像」は右のパネルの、部品 → 変形 → 寸法 → 色 → **画像** → 計測 の位置に置く。色と画像は掛け合わされるので隣に置く。
- 表示の切り替えは、表示の並び（面・面と線・線・透かしの隣）に置く。上部のボタンは増やさない。
- 読み込みの知らせは状態欄（進み具合）と「簡略表示」の一覧（読まない・縮めた・壊れた）。小窓は出さない。

## 4. 骨格
```
右のパネル「画像」（部品を選んでいるとき）              状態欄（読み込み中）
┌ 画像 ───────────────────────────────┐            … テクスチャ 3/24 … 簡略表示 2 件 … [詳細]
│ 2048 × 2048（箱形の投影）              │
│ ［画像を貼る…］ ［画像を外す］           │           表示の並び
│ 1枚の大きさ [ 1.00 ] m                 │            [面][面と線][線][透かし]  [画像]
│ 色は画像に掛け合わされて見えます。        │
└──────────────────────────────────────┘
```
- 1行目は状態: 「画像はありません」／「2048 × 2048（箱形の投影）」／「1024 × 1024（モデルの UV）」／「複数の画像（3枚）」／「読み込み中…」／「1024 × 1024（縮小して表示）」。
- ［画像を外す］は、選んだ範囲に画像があるときだけ押せる。「1枚の大きさ」は、箱形の投影の描画があるときだけ出す。Enter か欄を離れたときに確定する。
- 選択が無いときにドロップやショートカットで貼ろうとしたら、状態欄に「貼る部品を選んでから、画像を貼ってください」と出す。モデルを開く動作には回さない。
- 幅960で、状態欄の進み具合と「画像」の2つのボタンが重ならないことを試験で確かめる。進み具合は、幅が足りないとき格子の表示より先に隠さない（読み込み中だけ出る項目のため）。

## 5. 表層（画面の言葉）
| 場所 | 文 |
|---|---|
| ボタン | 「画像を貼る…」「画像を外す」 |
| 押せない理由 | 「部品を選ぶと貼れます」「この部品には、貼る面がありません」「読み込み中・書き出し中は貼れません」 |
| 貼った後（状態欄） | 「画像を貼りました」／「画像を外しました」／「画像の大きさを変えました」 |
| 断るとき | 「PNG か JPEG の画像を選んでください」「画像が大きすぎます（64 MiB まで）」「画像を読めません: {理由}」「画像のメモリの上限（512 MiB）に空きがありません」 |
| 簡略表示 | 「基本色以外の画像 N 件（法線・粗さなど）は表示しません」「画像 N 枚を縮小して表示しています（上限 512 MiB）」「画像 N 枚は読めないため、色だけで表示します（{理由}）」 |
| 表示の切り替えの説明 | 「画像（テクスチャ）を表示します。「線」「透かし」では出ません」 |
| 書き出しの結果 | 「画像を変えた部品 3 個: 画像 1 枚（245 KB）を足しました」「箱形の投影の部品 2 個は、UV 付きの形状を作って足しました（頂点の色・スキン・モーフは写していません）」 |
配色と文字は今のまま。ボタンは［開く］と同じ見た目。押せない部品には、ポインタを載せたときの説明で理由を出す（色の違いだけに頼らない）。

## この検討で要件・設計が変わった点: 11件
依頼の項目（画像を貼る、UV の無い部品の貼り方、書き出し）をそのまま実装した場合からの変更。
1. **貼るときに基本色を白にする**（S4、戦略②）。足した図形は灰色なので、そのまま貼ると絵が暗く見え、貼った画像と違う色で書き出される。同じ履歴の1回分に入れる。
2. **撮影情報を取り除いて持つ**（S8、戦略①）。写真をそのまま埋め込むと、撮影場所や機種が、渡した GLB から読める。画素のデータは変えず、付帯情報の区画だけを落とす。
3. **貼った画像のファイルを保存先にできなくする**（S9、戦略①）。当初の案は、開いたモデルだけを守っていた。
4. **「1枚の大きさ」を長さで決める**（S5、戦略④）。繰り返しの回数にすると、部品の大きさを変えるたびに絵が伸び縮みする。長さなら、板の幅 10 cm のような実物の感覚で決められる。
5. **箱形の投影を、画面では計算で貼り、書き出すときだけ UV にする**（戦略③）。貼るたびに UV 付きの形状を作ると、500万三角形の STL に貼れない。
6. **選択なしのドロップを「開く」に回さない**（構造）。画像を落としたのにモデルを開こうとして失敗の小窓が出ると、何が起きたか分からない。
7. **縮めたこと・読まなかったことを件数で知らせる**（S2、戦略②）。黙って画質を落とすと、元のデータが悪いように見える。
8. **表示の切り替えと、読まない起動の引数を置く**（S3、戦略③）。重いときに戻れる道を残す。
9. **「線」「透かし」では画像を出さない、と説明に書く**（戦略②）。出ないことを黙っていると、壊れたように見える。
10. **色の欄の注意を、部品単位にして文を替える**（戦略②）。今の「この画面には出ていません」は、画像が出るようになると誤りになる。
11. **金属らしさ・粗さ・法線の欄を置かない**（戦略②）。依頼の「マテリアル」のうち、この画面の簡単な照明で出せるのは基本色と画像だけである。
