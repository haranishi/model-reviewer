# UX設計（ユーザーストーリーとUX5階層）

実装の前に書いた。戦略から順に決め、下の階層の判断は上の階層から導いている。

## 誰のためか
- **本命ユーザー（使う人）**: 3Dモデルを受け取って確かめ、指摘を返す人。設計の確認をする技術者、発注側の担当者、制作チームの監督役。モデルを作る道具は持っていないか、確認のためだけに起動するのを重いと感じている。
- **アプリが救う相手**: 指摘を受け取って直す制作者。いまは「この辺の角」と書かれた画面写真が届き、場所を聞き返している。位置と部品に結び付いた指摘が届けば、往復が減る。

## ユーザーストーリー
| # | 誰が | 欲しいことと理由 | 受け入れ条件 |
|---|---|---|---|
| S1 | レビューする人 | 届いたGLBをすぐ開いて全体を見たい。確認のために制作ソフトを立ち上げたくない | ドロップか「開く」で開ける。開いた直後に全体が収まっている。待つ間、いま何をしているかが出ている |
| S2 | レビューする人 | トラックパッドだけで回し、寄り、ずらしたい。出先ではマウスが無い | 1本指ドラッグで回転、2本指スクロールとピンチでズーム、Shift＋ドラッグで移動。ヘルプに同じ表がある |
| S3 | レビューする人 | 外側の部品を隠して中を見たい。隠した物を見失いたくない | ツリーの目の印で隠せる。親を隠すと子も消え、戻すと元どおり。「すべて表示」で1回で戻る |
| S4 | レビューする人 | 画面で気になった部品が、一覧のどれかを知りたい | 3Dでクリックすると一覧の行が見える位置に来て強調される。逆も同じ。隠れていても輪郭で場所が分かる |
| S5 | レビューする人 | 気になった場所に指摘を残したい。後で読んだ人が場所を取り違えないように | 表面をクリックして本文を書く。印と一覧に同じ番号が出る。視点を変えても印は同じ場所にある |
| S6 | レビューする人 | 見せたい角度を名前で残したい | 名前を付けて保存し、選ぶと同じ見え方に戻る |
| S7 | レビューする人 | 作業を中断して、後で続きから始めたい。指摘を失いたくない | レビューを保存でき、開き直すと元の状態になる。未保存のまま閉じようとすると確認される |
| S8 | 指摘を受け取る制作者 | 届いたレビューが、自分のどの版のモデルに対するものかを知りたい | モデルが保存時と違えば復元せず、違うと伝える。合うGLBを指定すれば復元される |
| S9 | 開発に加わる人 | 速さの話を、測った値でしたい | 詳細を開くと、何を測ったかの説明つきで値が出る。測っていないものは「未計測」 |

## 1. 戦略（何のために、誰の何を解くか）
- 目的は「確認と指摘の往復を短くする」。作る道具ではなく、**見て、指して、残す**道具である。
- 大事にする順番は、①指摘を失わない・取り違えない、②待たせない・待つ理由を見せる、③初めてでも迷わない。見た目の豪華さは順位に入れない。
- 「軽い」は主張ではなく体験で示す。数値は見たい人だけが開ける場所に置き、宣伝の言葉は画面にも README にも書かない。

## 2. 要件（何を備えるか）
戦略①から: 注釈は部品と位置に結び付ける。未保存を示し、失う前に確認する。違うモデルには復元しない。読み込みに失敗しても、開いていたものは残す。
戦略②から: 読み込み中も画面は動く。工程名を出し、分からない割合は出さない。何もしていない間は描き直さない。
戦略③から: 操作は少数に絞る。使えない操作は押せない見た目にする。操作の表を画面内に置く。初版に入れないもの（形状編集・検索・取り消し）は、ボタンも置かない。

## 3. 構造（画面と状態のつながり）
- 画面は1枚。状態は「何も開いていない／読み込み中／開いている」の3つで、開いている間だけ「通常」と「注釈追加」のモードがある。
- **注釈追加モードでも、ドラッグは回転のまま**にする。クリックだけが「注釈を置く」に変わる。視点を変えるたびにモードを抜ける必要が無い。モードは続けて置けるよう保ち、Esc か同じボタンで抜ける。
- 選択は1つ（部品1つ、またはまとめ役のノード1つとその子孫）。一覧・3D・注釈一覧が同じ選択を見る。
- 判断が要る知らせ（失敗・不一致・未保存の確認）は中央のダイアログ、要らない知らせは下の状態欄に出す。

## 4. 骨格（配置）
```
┌───────────────────────────────────────────────────────────────────────────────────────┐
│ [開く] [レビュー保存] [レビュー読込] │ [全体表示] [選択を表示] [初期視点] │ [注釈を追加] │ [?] │ 上部 36
├───────────────┬───────────────────────────────────────────────────┬───────────────────┤
│ 部品        ◀ │                                                   │ ▶ 注釈（3）       │
│ [すべて表示]  │                                                   │ ① arm_tip         │
│ ◉ ▾ assembly │                3Dビュー（主役）                   │   ここの角を…     │
│ ◉   ▸ axle_… │        ①  ②   ← 番号つきの印                      │ ② wheel_FL 非表示 │
│ ⊘   base     │                                                   │ ───────────────── │
│ ◉   ▾ arm    │   何も開いていないとき:                           │ 視点              │
│ ◉     arm_tip│   「GLBをここへドロップ、または［開く］」と操作表 │ [名前][保存]      │
│ 左 260（180〜420）                                                │ 正面 / 斜め上     │ 右 300
├───────────────┴───────────────────────────────────────────────────┴───────────────────┤
│ review-sample.glb ●未保存 │ 読み込み完了 │ 簡略表示 2件 │ 部品 14・三角形 1,204 │ [詳細▴] │ 下部 28
└───────────────────────────────────────────────────────────────────────────────────────┘
```
- 左右のパネルは境目をドラッグして幅を変えられ、◀▶ で折りたためる。最小のウィンドウは 960×600、既定は 1280×800。パネルを両方開いても、3Dビューが幅の半分以上を占める。
- ツリーの行は「目の印・開閉の三角・名前」の順で、目の印は行の左端に固定する。字下げで位置が変わらず、続けて押しやすい。親に連れて隠れている行は、目の印を薄い丸に薄い斜線にして名前を灰色にし、自分で隠した行（濃い斜線の ⊘）と見分ける。薄くするだけでは開いた丸（表示中）と見分けにくかった。
- ツリーは**見えている行だけを描く**。10万行のモデルでも、描くのは画面に入る数十行である。
- 注釈の下書きは、置いた印のそばに小さな入力欄（幅280前後、折り返して2〜4行、超える分は欄の中でスクロール）を出す。長い本文も先頭から読める。本文が空の間は「登録」を押せない。Enter で登録、Shift＋Enter で改行、Esc で取り消す。入力欄は3Dビューからはみ出さない。
- 他の部品に隠れた注釈の印は、中を塗らない破線の輪と薄い番号で描き、見えている印と形で見分ける（[design-review.md](design-review.md)）。
- 詳細（性能値と統計）は、下部の「詳細」を押したときだけ、状態欄の上に開く。高さは `min(280, 画面の35%)` で固定し、大きさは変えられない。中は縦にスクロールする。中身に合わせて伸ばすと最後の行が状態欄に重なった。各値は「名前: 値」の行の下に、説明を小さく薄く出す。
- 操作表は列幅に合わせて折り返し、句の切れ目（／、、、→、「て」、「または」の前後）でだけ改行する。何も開いていない画面とヘルプで同じ表を使う。ヘルプは幅に余裕があれば最大900まで広げる。

## 操作表（ヘルプにも同じ表を出す）
| したいこと | マウス | トラックパッド | キー |
|---|---|---|---|
| 回転 | 左ドラッグ | 1本指で押してドラッグ | |
| 平行移動 | 右ドラッグ、または Shift＋左ドラッグ | Shift＋ドラッグ、または2本指で押してドラッグ | |
| ズーム | ホイール | 2本指スクロール、ピンチ | |
| 選択 | 左クリック | クリック（タップ） | Esc で解除 |
| 全体表示／選択を表示／初期視点 | 上部のボタン | 同じ | A ／ F ／ Home |
| 選択を非表示／すべて表示 | 目の印、ボタン | 同じ | H ／ Shift＋H |
| 注釈を追加 | 「注釈を追加」→ 表面をクリック | 同じ | N で切り替え、Esc で終了 |
中ボタンは使わない。1文字のキーは、入力欄に文字を打っている間は働かない。

## 5. 表層（色と文字）
暗めの1配色に絞る（明るい配色は後続）。文字は本文14、補助12（単位はポイント）。
| 用途 | 色 | 備考 |
|---|---|---|
| 3Dビューの背景 | #22252B | モデルの色を邪魔しない無彩色 |
| パネルの背景／区切り | #2A2D34 ／ #3A3E47 | |
| 文字／補助の文字 | #E6E8EB ／ #A9AFB8 | パネル背景との明度比は約11対1 ／ 約6対1 |
| 選択（一覧の行の左の帯） | #F2A33A（琥珀） | 一覧では帯と太字。色だけにしない |
| 選択（3Dの輪郭線） | 外縁 #14161C ／ 内側 #F4F7FB | 暗い線と明るい線の二重。橙の部品の上でも見える |
| 注釈の印 | #4FB3FF の円に白い番号 | 選択中は琥珀の輪を足す |
| 警告／エラー | #F2C14E ／ #FF6B6B | 必ず「⚠ 注意」「✕ 失敗」の記号と文を添える |
赤と緑の対で意味を分ける箇所は作らない。表示と非表示は色ではなく印の形（◉ と ⊘）で分ける。印はフォントの絵文字に頼らず、図形として描く。

## この5階層を通したことで変わった実装: 8個
依頼をそのまま実装した場合からの変更点。
1. **注釈追加モードでもドラッグは回転**、モードは続けて使える（構造）。モードを「クリックの意味だけ」に絞った。
2. **輪郭線は隠れていても見える**（S4）。深度を使わないマスクから作る方式を選んだ。
3. **未保存の印と、失う前の確認**（戦略①）。依頼には無い。`Session` に未保存の印と保留中の操作を持たせた。
4. **読み込みに失敗しても、前のモデルとレビューを残す**（戦略①）。置き換えは新しいモデルの転送が終わってからにした。
5. **非表示の部品の注釈を、一覧に残して「非表示の部品」と出す**（S5）。消えたように見せない。
6. **ツリーは見える行だけを描き、目の印を左端に固定**（S3）。ノードの並びを行きがけ順の連続範囲にした理由の1つ。
7. **カーソルへ向かうズーム**（S2）。大きなモデルで、寄るたびに移動し直す手間を無くす。
8. **親に連れて隠れた行と、自分で隠した行を見分ける**（S3）。表示状態を「自分の設定」と「実際の結果」の2つで持つことにした。
