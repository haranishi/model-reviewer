# 判断・捨てた案・確かめたAPI

## 決めたこと（理由つき）
| # | 決めたこと | 理由 |
|---|---|---|
| 1 | 形状は不変の `Arc` のまま共有し、部品の表だけを持つ `Document` を上に載せる。部品は行きがけ順の配列のまま | 読み込みと転送の経路（第1段階で不具合を直した所）を変えずに済む。並びに頼る表示・注釈・当たり判定・輪郭線が、そのまま動く |
| 2 | 構造の変更は部品の表を1回作り直す。変形は書き換えるだけ | 追加・複製・削除は1回ずつの操作で、表は10万個で約20MB。毎フレーム起きる変形だけを安くすればよい |
| 3 | 変形中は、差分の行列を1つシェーダーへ渡す | 子孫の数に依らず、送るのは定数1つ。確定まで文書を書き換えないので、Esc の取り消しが「何もしない」で済む |
| 4 | 取り消しは逆の操作で持ち、対象は未保存の印が付く操作すべて。視点と選択は入れない | 文書の写しは1回20MBで続かない。対象の規則が1つなら、利用者が覚えることが無い |
| 5 | 書き出しは、元のJSONを値として直し、既存の番号を変えず、BINは末尾に足す | 表示に使わなかったテクスチャ・アニメーション・拡張を失わない。知らない拡張が指す番号も壊さない |
| 6 | 削除はシーンから外すだけで、データは残す。結果の一覧で必ず伝える | 番号を詰めると、中身を知らない拡張の参照を直せない |
| 7 | 書き出すと、作業の対象が新しいファイルへ移る。「開く」で開いたファイルは書き出し先にできない | レビューは `gltf_index` とハッシュでファイルに結び付く。編集後のファイルに付いていかないと、注釈を保存できない |
| 8 | 書き出していない編集がある間は、レビューを保存させない | ファイルに無い部品を指す注釈は書けない。黙って落とすより、先に書き出させる |
| 9 | レビューJSONは、平行投影の視点があるときだけ版2 | 古いアプリが読める範囲を狭めない。版1のアプリは未知の投影を理由なく拒むので、版を上げて「新しい版」と伝えさせる |
| 10 | ハンドル・立方体・計測は egui に描く | 当たり判定がCPUで済み、画面なしで試験できる。触れたときの強調で3Dを描き直さない |
| 11 | 移動と回転はワールドの軸、拡大は部品の軸。中心は見えている範囲の中心 | 床の軸と同じ向きで迷わない。拡大だけは、傾いた拡大を作らないために部品の軸にする |
| 12 | 線の表示は `PolygonMode::Line`。使えないGPUでは無効にして理由を出す | 追加のデータが要らない。辺の抽出や頂点の複製をしない |
| 13 | 単位は換算せず、前提として表示する | 画面の数値がファイルの値と食い違わない。規定（m）に従わないモデルにも、利用者が前提を合わせられる |
| 14 | 新しい依存は足さない | 要るものは `serde_json`・`glam`・`wgpu`・`egui` にすでにある |

## 捨てた案と理由
| 案 | 捨てた理由 |
|---|---|
| `Model` を「形状」と「構造」の2つの型に割り、読み込みから作り直す | 筋は良いが、転送と表示の照合（`Arc` の同一性に頼る箇所）を全部書き換える。直したばかりの経路を壊す危険に見合わない。`SceneRead` があれば、後で割る作業は機械的にできる |
| 部品を鍵つきの木（親が子の一覧を持つ）で持ち、行きがけ順の配列を毎回作る | 親子の付け替えには向くが、今回は範囲外。配列を作る手間は同じで、鍵だけあれば足りる |
| 構造を共有する不変のデータ構造にして、取り消しを「前の版を持つ」で済ませる | 依存が増え、全部の読み手が新しい型に合わせる必要がある。逆の操作のほうが小さい |
| 変形中もインスタンスを毎フレーム書き直す | 子孫5万個で1フレーム約7MBの転送になる |
| 変形のたびにインスタンス全体を作り直す | 確定のたびに部品数に比例した転送が起きる。範囲だけの書き直しで足りる |
| 文書から新しいGLBを組み立てる書き出し | 読み込みで捨てたものがすべて消える（依頼の「元の中身を保つ」に反する） |
| 型つきの `gltf::json::Root` で読んで書き戻す | `extras` と知らない拡張が落ちる。`extras` 機能を有効にしても、知らない拡張は残らない |
| JSONの文字列を、変えるノードの所だけ差し替える | 字句の位置を自分で追う必要があり、壊れやすい。値として直すほうが確かめやすい |
| 削除でノードの番号を詰める | 上の6。条件つきの後続の機能にする |
| 開いている間、元のファイルのバイト列を持ち続ける | 常駐メモリがファイルの大きさだけ増える。書き出すときに読み直し、ハッシュで同じ物と確かめれば足りる |
| 書き出したGLBに「どのファイルから作ったか」を記録し、元のファイル用のレビューを引っ越せるようにする | 使う機能が無いデータを、利用者のファイルへ足すことになる。他のソフトで編集されると記録が嘘になる。作業の中での引き継ぎ（上の7）で、指摘は失われない。必要になったら、部品の表の要約を添えて確かめる方式で足す |
| 書き出しても作業の対象を元のファイルのままにする | 足した部品に付けた注釈を保存できない |
| レビューを常に版2で書く | 平行投影を使わないレビューまで、前の版のアプリで読めなくなる |
| ハンドルと立方体を3Dの描画に入れる | 当たり判定に画面の読み戻しかCPUの二重計算が要る。触れたときの強調で3Dを描き直す |
| 格子を線の頂点で描く | 太さが物理1画素に固定され、間隔が変わるたびに作り直す |
| 線の表示のために、辺のインデックスを形状ごとに作る | メモリが増え、読み込みの経路に手が入る。稜線だけを描く表示が要るときに検討する |
| 道具ごとにドラッグの意味を変える（移動の道具ではドラッグで動く） | トラックパッドでは、視点を回すたびに道具を抜けることになる |
| 表示・投影・図形を開くメニューにする | 状態が見えない。出たばかりの小窓は位置が定まらず、自動操作と実機で不安定になる |
| 単位を選ぶと数値を換算する | 規定に従わないモデルで、画面の数値とファイルの値が食い違う |
| 吸着（一定の刻み）、角度の計測、複数選択、親子の付け替え、色の編集 | 土台の範囲を超える。数値入力で精度は足りる。ロードマップに載せる |
| 空の状態から図形を足して新規に作る | 土台のファイルが無い書き出しと、識別の無いモデルの扱いが要り、読み込み・転送・レビューの各所に「モデルが無いのに文書がある」状態が増える。後続の1つの作業として切り出す（下の「確かめたい分岐」） |

## 実物で確かめたAPI（括弧内は確かめたファイル。依存の実物は cargo のレジストリの下）
1. `Features::POLYGON_MODE_LINE` はネイティブだけの機能で、要求しないと `PolygonMode::Line` は使えない（`wgpu-types-30.0.2/src/features.rs`、`render.rs`）。Metal は `MTLTriangleFillMode::Lines` に対応し、機能を申告している（`wgpu-hal-30.0.2/src/metal/{adapter,device}.rs`）。Vulkan・DX12・GL も申告がある。
2. `DepthBiasState` は `constant: i32`・`slope_scale: f32`・`clamp: f32`（`wgpu-types/src/render.rs`）。
3. WGSL の `frag_depth` は naga にある（`naga-30.0.2/src/front/wgsl/parse/conv.rs`）。
4. glam 0.34 の平行投影は `glam::camera::rh::proj::directx::orthographic(left, right, bottom, top, near, far)`。`Affine3A::to_scale_rotation_translation`・`from_scale_rotation_translation` がある（`glam-0.34.3/src/camera/rh/proj.rs`、`src/f32/affine3a.rs`）。
5. `gltf::binary::Glb` に `to_writer`・`to_vec` がある。`json` と `bin` は `Cow<[u8]>`（`gltf-1.4.1/src/binary.rs`）。`gltf::json::Value` は `serde_json::Value` の再公開で、`gltf::json::serialize::to_vec` は `serde_json` のもの（`gltf-json-1.4.1/src/lib.rs`）。gltf クレートに、文書を組み立てて書き出す高水準の仕組みは無い。
6. `gltf-json` の `Extras` は、`extras` 機能が無いと中身を捨てる型になる（`gltf-json-1.4.1/src/extras.rs`）。本アプリは機能を有効にしていない。
7. `serde_json` は `preserve_order` を有効にしていない（`Cargo.lock` と各 `Cargo.toml`）。オブジェクトの項目は読み書きで並び替わる。
8. egui 0.37: `Response::has_focus` は `input.focused` も条件にする。`lost_focus` はメモリだけで決まる（`egui/src/response.rs`）。`DragValue` の確定はメモリの `lost_focus` と Esc の有無で決まる（`widgets/drag_value.rs`）。`Context::text_edit_focused`、`InputState::zoom_delta`・`multi_touch`・`consume_shortcut` がある。`Key` に `Num1`〜、`G`・`R`・`S`・`V`・`M`・`Z`・`Delete`・`Backspace` がある（`data/key.rs`）。
9. Cmd+C・X・V は `egui-winit` が `Event::Copy`・`Cut`・`Paste` に変える（`egui-winit-0.37.0/src/lib.rs` の `is_copy_command` ほか）。取り消し用の同じ変換は見当たらない。
10. レビューJSON版1の読み込みは、`projection` が `"perspective"` 以外なら `InvalidValue` を返す（本リポジトリの `crates/core/src/review_file.rs`）。

## 未確認だった項目の結果（2026-11-27、[verification.md](verification.md)）
- 確かめた: `frag_depth` と多重サンプルの描画先（Metal）で、格子が部品に隠れる（GPU試験と実機の画像）。平行投影の反転Z（カメラの試験と、平行投影の画像の前後関係）。線の表示の深度の偏りは `constant 8・slope_scale 1.0` で、面と線の画像に線のちらつきが無い。前面でないウィンドウで、数値の欄へ打って Enter で確定する（`edit-1`）。書き出し中のメモリと、重いモデルでの各操作の時間（verification.md の表）。
- 未確認のまま: 日本語配列の数字キーと、実キーの Cmd+Z・Cmd+D が egui のキーとして届くか（自動操作は egui の入力を直接入れるので、OSのキー配列を通らない）。第1段階の未確認（実キーとトラックパッド、日本語入力、ネイティブのダイアログ、Windows と Linux）。保存先のダイアログで既存のファイルを選んだときの上書きの確認。

## 確かめたい分岐（決めないと進めないものは無い。既定で進める）
1. **空の状態からの新規作成**は入れていない（既定）。入れるなら、接合の最後に1つ作業を足す。
2. **削除した部品のデータがファイルに残る**ことを、結果の一覧で伝える方式にした（既定）。「残さない書き出し」を先に求めるなら、知らない拡張があるファイルを断る条件つきで足す。
3. **部品の一覧の位置**: 依頼で選んだ案のとおり右に置き、注釈と視点を左へ移す（2026-11-26 に決定。配置の入れ替えは接合1で行う）。
