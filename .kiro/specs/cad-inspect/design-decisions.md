# 判断・捨てた案・落とし穴・保留

## 決めたこと（理由つき）
| # | 決めたこと | 理由 |
|---|---|---|
| 1 | 吸着の候補は、当たった三角形の近く（索引への問い合わせ1回）からだけ探す。頂点や辺の表を作らない | 数千万三角形で常駐メモリを増やさない。読み込みの時間も増えない |
| 2 | 辺は「隣の面との角度が10°以上」か「縁」だけ。位置で隣を探す | 平らな面の対角線に吸い付くと、意味の無い点を測らせる。位置で比べれば、頂点を共有しない STL でも働く |
| 3 | 吸着の探索は、計測の道具でポインタが動いたフレームとクリックだけ。8ミリ秒を超えたら自分で休む | 部品の数に比例する走査（既存の `pick`）を、毎フレームにしない |
| 4 | 断面は軸に垂直な1枚。描画の定数の空き2つに入れ、画素を捨てる | 定数の大きさ（304バイト）と既存の試験を変えない。GPUの追加の機能が要らない |
| 5 | 切り口は、裏を向いた面を1色で塗るだけ。ふたと輪郭線は作らない | ふたにはステンシルか形状の再構成が要る。閉じていない形状で誤ったふたを描くより、制限を書くほうが正直である |
| 6 | 断面・吸着・表示の単位は、履歴にも未保存の印にも保存にも入れない | 見え方の設定である。第2段階の「表示」「格子」と同じ扱い |
| 7 | 単位を「ファイルの単位（前提）」と「表示の単位」に分け、表示の既定を「ファイルと同じ」にする | 既定の状態で、第2段階と同じ数値と文字になる。換算は、利用者が表示を選んだときだけ起きる |
| 8 | STL は mm と仮定し、倍率を部品の `scale` に入れて、シーンをメートルにする | 書き出した GLB が規格どおりに読める。書き出しの前後でシーンの数値が変わらない |
| 9 | STL の単位の変更は開き直し | 編集として履歴に入れると、取り消しで倍率だけ戻り、状態欄の単位とずれる |
| 10 | STL の頂点は位置でまとめ、法線は面ごとに導く | メモリが3分の1以下になる。面ごとの法線は既にある経路で、STL の見た目として正しい |
| 11 | STL の書き出しは、STL から最小の GLB を合成して、第2段階の書き出しに渡す | 書き出しの方式（土台を保ち、変えた所だけ直し、照合する）を1つに保つ |
| 12 | レビューJSONの版は上げず、`model.stl_unit` を足す | 座標の意味が変わらない。前の版のアプリは知らない項目を無視し、STL は開けずに止まる（誤った復元をしない） |
| 13 | 寸法は部品の大きさ（`scale`）として持ち、確定は既存の `CommitLocal` | 形状を作り直さず、取り消し・書き出し・変形中の描画を足さずに済む |
| 14 | 「変形」の位置は換算せず、単位も付けない | 親の中の座標である。親に拡大がある GLB（cm で作られ、根に 0.01 が入ったものなど）で、誤った単位つきの数値を出さない |
| 15 | 外部の依存は足さない。足すのはワークスペース内の `model-reviewer-stl` だけ | STL の読み取りは数百行で書ける。`Cargo.lock` に入るのは自分のクレートの1項目で、外部のライセンスは増えない（`deny.toml` は変えない） |

## 既存の振る舞いを変える所（要件にも書いた）
1. 表示の単位を選ぶと、長さの数値が換算される（要件7.3）。選ばなければ変わらない。
2. 計測のクリックが、既定で頂点と辺に吸着する（要件1）。同じ場所を押しても、第2段階と違う点が置かれることがある。X か [吸着] で切れる。
3. 「開く」が STL を受け付け、どちらでもないファイルの知らせが「GLBではありません」から「GLB でも STL でもありません」に変わる（要件5.2）。ファイルを選ぶ画面の絞り込みに STL が入る。
4. `Hit`・`TriHit`・`ModelRef`・`Measurement` に項目が増える（公開の型。構造体を直接組み立てている試験は、契約の作業で直す）。

## 捨てた案と理由
| 案 | 捨てた理由 |
|---|---|
| 形状ごとに、頂点の空間索引や辺の表を読み込み時に作る | 数千万三角形で数百MB増える。使うのは計測のときだけ |
| GPUで番号を描いて読み戻し、吸着の候補を決める | 読み戻しの待ちが入り、画面なしで試験できない |
| 画面上の距離だけで候補を選ぶ（3Dの近さを見ない） | 薄い板の裏の頂点など、奥行きの違う点に付く。誤った寸法を黙って出す |
| 辺の中点・円の中心・別の部品の頂点への吸着 | 印と優先の規則が増える。まず頂点と辺で使ってから決める（保留） |
| 定数を広げて、任意の向きの平面を入れる | 斜めの断面は範囲外。大きさを変えると既存の試験と記録（304バイト）が変わる。要るときに広げる |
| クリップ距離の機能（`CLIP_DISTANCES`）で切る | 対応しない環境の分岐が要る。画素を捨てる方法は、どの環境でも同じに動く |
| ステンシルで切り口にふたをする | 深度の形式とパイプラインが増え、閉じていない形状で誤ったふたが出る |
| 切り口の輪郭線を、三角形と平面の交差で作る | 三角形の数に比例する計算が、位置を動かすたびに要る。選んだ部品だけに絞る案は後続にする |
| シーンの数値は STL の値のまま（mm）にして、単位は添える文字だけで扱う | 書き出す GLB をメートルにする時点でシーンの数値が1000倍変わり、視点・断面・保存した視点を全部直すことになる |
| STL の数値をそのまま GLB に書く（倍率を入れない） | 規格ではメートルなので、ほかのソフトで1000倍の大きさになる |
| 形状の頂点に 0.001 を掛けてから持つ | `f32` の丸めで、STL の値と1ビット違う座標になる。倍率を部品に置けば、値は元のまま残る |
| 表示の単位の既定を mm にする | GLB を開いたときの数値が、第2段階と変わる。既定は変えず、1回押せば mm になるようにした（下の分かれ道1） |
| STL のクレートを外から足す | 壊れた入力での確保の上限と、判定の順を自分で決めたい。依存とライセンスの確認も要らなくなる |
| 寸法のたびに形状を作り直す | 形状の転送・当たり判定の索引・書き出しの形状が、確定のたびに増える |
| 寸法を、書き出す GLB の `extras` に書いて、開き直しても直せるようにする | 利用者のファイルへ自分のデータを足すことになる（第2段階で同じ理由の案を捨てた）。ほかのソフトで編集されると嘘になる |
| 置く前に寸法を聞く小窓 | 出たばかりの小窓は位置が定まらない（第1段階の罠）。押すとすぐ置かれる流れも崩れる |

## 落とし穴
1. **`pick` は部品の数に比例する。** 吸着を毎フレーム呼ぶと、部品10万個で画面が重くなる。呼ぶ条件（design-snap.md）を守る。
2. **`Hit`・`TriHit` に項目を足すと、構造体を直接組み立てている箇所がすべて通らなくなる。** 契約の作業でまとめて直す。
3. **`front_facing` は、行列式が負の部品で逆になる。** 印を立てないと、鏡写しの部品が丸ごと切り口の色になる（design-section.md）。部分更新（`update_instances`）の経路にも同じ印が要る。
4. **`discard` は微分の後に置く。** `scene.wgsl` は微分で面の法線を求めている。
5. **定数の `params.z`・`params.w` を、断面なしで必ず 0 にする。** 0 以外が残ると、何も切っていないのに画素が消える。既定の `FrameParams` で第2段階と同じ絵になることを、GPUの試験で確かめる。
6. **`solid` で始まるバイナリの STL がある。** 先頭の語だけで ASCII と決めない。
7. **`"nan".parse::<f32>()` と `"1e999".parse::<f32>()` は成功する**（`NaN` と無限大。小さなプログラムで確かめた）。読めた後に有限かを見る。
8. **三角形の数 × 50 は `u32` であふれる。** 大きさの計算は `u64` で行う。申告の数で `Vec::with_capacity` を呼ばない。
9. **換算した値を `assert_eq!` で比べない。** 0.001 を掛けて 1000 を掛けた値は、元と1ビット違うことがある。OS によっても違う（design-testing.md）。
10. **STL の部品の「大きさ」は 0.001 と表示される。** 誤りではない。右のパネルの外形と寸法は、ワールド（メートル）から換算するので正しい値になる。
11. **`has_focus` は前面でないウィンドウで常に偽**（第1段階の罠）。断面の位置と寸法の欄の確定は、第2段階の数値の欄と同じ方法で判定する。
12. **ポインタを動かす自動操作は、隠れたウィンドウで描画の要求が要る**（第1段階の罠）。`hover_view` は既存の注入の順番待ちを通す。
13. **計測のクリックは、候補の控え（`snap_preview`）を使わない。** 自動操作と速いクリックでは、ポインタの移動の出来事より先にクリックが届く。
14. **合成した土台と、開いている文書の番号が合うこと。** 部品0・形状0・描画0。`synthesize_base` の約束の試験が、これを守る。

## 確かめた事実と、未確認
- 確かめた（リポジトリのコードと依存の実物）: 面の向きによる間引きは無い（`render/src/pipelines.rs` の `cull_mode: None`）。`scene.wgsl` はワールドの座標をフラグメントへ渡し、法線の無い形状は微分で面の法線を作る。定数は304バイトで、`params` は x と y だけを使う（`shaders/frame.wgsl`）。`ray_triangle` は両面に当たる（`core/src/bvh.rs`）。足した図形は根の直下で、`local` は平行移動だけ（`session/edit.rs`、`doc.rs` の `shape_piece`）。書き出しは土台のファイルを読み直して照合する（`app/src/exporter.rs`）。`front_facing` は naga にある（`naga-30.0.2/src/front/wgsl/parse/conv.rs`）。`camera.half_height_at` は透視と平行の両方で使える。
- 未確認: naga が `discard` の後の微分を受け付けるか（順番で避ける）。`pick` 1回の時間（部品10万個）。STL の読み込みの時間とメモリ。`gltf/src/export/append.rs` の内部の関数を、土台の合成に使い回せるか（使えなければ `synth.rs` の中に書く）。実キーの X・C、Windows と Linux の画面。

## 保留（範囲外。足したくなったもの）
辺の中点・円の中心・別の部品への吸着／角度・半径・面積の計測／斜めの断面、複数の断面、切り口のふたと輪郭線、断面を保存した視点に入れる／インチ（STL の仮定と表示の両方で要る。一緒に決める）／ワールドの座標での数値入力／寸法を開き直しても直せるようにする／ASCII の `solid` ごとに部品を分ける／部品側の階層的な索引（吸着の探索が遅いと測れたら、先に入れる）／STL の書き出し。

## 依頼者に確かめたい分かれ道（どれも既定で進められる）
1. **GLB を開いたときの表示の単位**: 既定は「ファイルと同じ（m）」。mm を既定にするなら、第2段階の数値の出方が変わる。
2. **STL の単位の仮定**: 既定は mm。インチは保留にした。
3. **切り口**: 既定は「裏の面を1色で塗るだけ」。ふたや輪郭線が要るなら、別の作業として足す。
